Edición de datos — Guías metodológicas

1. Presentación general#

Data Edition modifica directamente los componentes internos de un dataset phyloseq: metadata, abundancias OTU, taxonomía, secuencias de referencia y árbol filogenético. También permite importar, exportar o eliminar componentes, renombrar ASV y conservar un historial descriptivo.

2. Principio fundamental: los cambios son inmediatos#

No existe un borrador independiente. La mayoría de las acciones sustituyen inmediatamente el objeto seleccionado en datasets(): edición de celdas, operaciones de columnas, fusiones, renombrado, reemplazos taxonómicos, importaciones completas y eliminación de componentes.

3. El botón Guardar no aplica cambios pendientes#

Los cambios ya se han aplicado. Guardar solo vuelve a registrar el estado editado con el mismo nombre, uno nuevo o sobre otra entrada. No guarda el proyecto en disco.

4. Consecuencia importante para la versión original#

Editar COI_raw y después guardar como COI_edited no conserva un COI_raw intacto: la entrada de origen ya fue modificada. Duplique el dataset bruto en Datasets antes de editar.

5. Efecto sobre los archivos fuente#

No se reescriben los archivos RDS, RData, CSV, FASTA, Newick ni los resultados remotos. Se modifica el objeto en memoria. Para conservarlo, guarde el proyecto o exporte el dataset.

6. Organización del módulo#

Incluye selección del dataset, edición de metadata, edición OTU, edición taxonómica, importación/exportación/eliminación de componentes, logs y registro del dataset.

7. Dataset que se va a editar#

El selector muestra los datasets del registro y está sincronizado con active_ds(). Cambiarlo modifica el dataset activo global.

8. Cambio de dataset durante la edición#

Al cambiar de dataset se recargan los estados locales de los tres editores y se reinician los estados inicial/anterior y las previsualizaciones. El estado inicial local no siempre es el archivo original.

9. Restablecer después de cambiar de dataset y volver#

Si se modifica COI, se abre otro dataset y se vuelve a COI, Restablecer apunta al estado ya modificado que se cargó al volver.

10. Edición y persistencia del proyecto#

Cada acción actualiza datasets() y puede marcar el proyecto como no guardado. Use Datasets → Guardar proyecto para conservar los cambios tras cerrar la aplicación.

11. Diferencia entre los dos mecanismos de importación#

Fusionar añade únicamente columnas ausentes usando identificadores comunes. La importación completa reemplaza todo el componente seleccionado al elegir el archivo.

12. Operaciones para las que no está diseñado Data Edition#

No es el método preferido para filtración biológica, normalización, transformación de abundancias o eliminación por umbrales. Use Filtration o un flujo externo controlado.

13. Historial de modificaciones#

Las acciones pueden añadir una entrada a attr(ps, "edit_log") con fecha, dataset, tabla, acción, descripción, dimensiones antes/después y advertencias.

14. El historial no es una copia de seguridad#

No almacena las tablas antiguas completas. Es una traza de auditoría, no un sistema de versionado o restauración integral.

15. Idioma del historial#

Las acciones y advertencias internas de edit_log permanecen en francés aunque la interfaz use otro idioma.

16. Las tres vistas de logs#

Última acción global cubre la sesión actual del módulo, Historial completo muestra el log almacenado y Resumen agrega acciones, tablas, advertencias y fechas.

17. Acciones contabilizadas#

El total puede incluir ediciones, cambios estructurales, importaciones, exportaciones, deshacer, restablecer, guardados en el registro, renombrados y sincronizaciones automáticas.

18. Deshacer: un solo paso#

Cada editor conserva un único estado anterior. Deshacer no recorre todo el historial y varios clics pueden alternar entre dos estados recientes.

19. Restablecer#

Restaura el estado local capturado cuando el submódulo cargó el dataset. Es inmediato, se registra y puede deshacerse, pero no garantiza volver al archivo original.

20. Edición de metadata — presentación#

Actúa sobre sample_data(ps) y permite editar valores, añadir, eliminar o renombrar variables, fusionar un archivo, deshacer y restablecer.

21. Creación automática de metadata ausente#

Si no existe metadata utilizable, el editor crea una sample_data mínima con una columna SampleID y una fila por muestra. Puede modificar el dataset sin una entrada de log específica.

22. Identificadores de muestras#

Los identificadores reales son los rownames alineados con sample_names(ps). Una columna SampleID es una variable ordinaria; editarla no renombra las muestras OTU.

23. Tabla de metadata editable#

Las celdas se modifican directamente y se aplican al validar la edición. No existe un botón Aplicar global.

24. Tratamiento de factores#

Los factores se convierten localmente en texto. Sus niveles y orden pueden perderse tras la primera reescritura.

25. Tratamiento de columnas de listas#

Las listas se convierten en texto separado por comas, lo que puede ser irreversible.

26. Edición de una columna numérica#

Un número válido sigue siendo numérico, una celda vacía pasa a NA_real_ y un texto no numérico puede convertir toda la columna en carácter con advertencia.

27. Consecuencia de convertir numérico a texto#

Una covariable continua convertida a character puede dejar de funcionar como variable cuantitativa. Revise los tipos después de editar.

28. Columnas lógicas, fechas y clases especiales#

La conservación explícita se centra en columnas numéricas. logical, Date, POSIXct, factores ordenados y clases personalizadas pueden perderse.

29. Añadir una columna de metadata#

La nueva columna se rellena con NA. El nombre debe empezar por una letra ASCII, contener solo letras, números o _, no incluir punto y ser único.

30. Sugerencias de nombres compatibles#

Puede mostrarse una sugerencia normalizada, pero no se aplica automáticamente.

31. Renombrar una columna de metadata#

Conserva los valores y exige un nombre válido y único. No renombra rownames ni identificadores de muestras.

32. Consecuencia del renombrado para los análisis#

Las fórmulas y parámetros guardados con el nombre anterior no se actualizan y deben configurarse de nuevo.

33. Eliminar una columna de metadata#

Requiere el nombre exacto y distingue mayúsculas y minúsculas. Pueden mostrarse sugerencias aproximadas.

34. Eliminar la última columna#

No existe una protección general que garantice una columna restante. Para retirar toda la metadata, use la eliminación completa del componente.

35. Coherencia de las filas de metadata#

Las muestras ausentes se añaden con NA, las filas se ordenan según sample_names(ps) y las filas adicionales se descartan.

36. Fusionar un archivo en la metadata#

Se aceptan CSV, TSV y TXT con separador coma, punto y coma o tabulación.

37. Detección automática del separador de metadata#

Se inspeccionan hasta treinta líneas no vacías para comparar número de campos y regularidad. Un resultado incierto puede corregirse manualmente.

38. Primera columna como identificadores#

Al activarlo, la primera columna se usa como rownames. Sin esta opción, los rownames numéricos suelen impedir la correspondencia.

39. Fusión de metadata: comportamiento real#

Solo se añaden columnas nuevas para rownames comunes. Las muestras coincidentes reciben valores y las demás reciben NA.

40. Columnas ya existentes#

Fusionar no actualiza columnas existentes. Si no hay columnas nuevas, no se modifica nada.

41. Muestras adicionales en el archivo de fusión#

Los identificadores ausentes del phyloseq se ignoran y no crean nuevas muestras.

42. Muestras actuales ausentes del archivo#

Permanecen en el dataset y reciben NA en las columnas nuevas.

43. Edición de la tabla OTU — presentación#

Permite editar celdas, añadir o eliminar columnas, fusionar, ordenar la visualización, renombrar ASV, declarar orientación, deshacer y restablecer.

44. Orientación de la tabla OTU#

Se conserva taxa_are_rows(). Con taxones en filas, las columnas son muestras; en el caso contrario, las columnas son taxones.

45. «ASV en columnas» no transpone la tabla#

El selector informa principalmente al renombrado automático. Cambiarlo solo no transpone ni modifica inmediatamente taxa_are_rows.

46. Riesgo de elegir el eje incorrecto#

Puede renombrar muestras como ASV, alterar la orientación declarada y desincronizar taxonomía, secuencias y árbol.

47. Tabla OTU editable#

Cada celda puede modificarse y el módulo reconstruye después una matriz numérica.

48. Conversión numérica de la tabla OTU#

Toda la tabla se convierte a numérico después de una acción. Los valores no convertibles pasan a NA con advertencia.

49. Valores vacíos en OTU#

Las celdas vacías, espacios y NA se señalan, pero no se sustituyen automáticamente por cero.

50. Valores no numéricos#

Textos como absent, low o ? suelen convertirse en NA.

51. Valores negativos y decimales#

No se bloquean. La tabla puede contener cuentas, proporciones, transformaciones o CLR, aunque algunos análisis las rechacen.

52. Añadir una columna a OTU#

Con taxones en filas añade una muestra; con taxones en columnas añade un taxón. La columna se inicializa con NA.

53. Riesgos al añadir una muestra#

No se crea automáticamente la fila correspondiente en sample_data, por lo que el objeto puede quedar incoherente.

54. Riesgos al añadir un taxón#

No se crean taxonomía, secuencia ni hoja del árbol. RefSeq o el árbol pueden eliminarse si quedan incompletos.

55. Recomendación para adiciones estructurales#

Para nuevos taxones o muestras, reconstruya y valide un phyloseq completo en R.

56. Eliminar una columna de OTU#

Según la orientación, elimina una muestra o un taxón. La metadata o taxonomía no se sincronizan siempre.

57. Usar Filtration para eliminaciones biológicas#

Filtration está diseñado para retirar taxones o muestras con criterios documentados y producir un dataset hijo coherente.

58. Orden natural de ASV#

Muestra ASV1, ASV2, ASV10 en orden numérico sin modificar el orden interno.

59. Edición con el orden activado#

La fila visible se asocia de nuevo con su identificador original para modificar el elemento correcto.

60. Fusionar un archivo en OTU#

Detecta el separador, usa rownames, encuentra filas comunes y añade solo columnas nuevas.

61. Significado de las columnas importadas#

Depende de la orientación actual; el módulo no deduce si son muestras o taxones.

62. Filas adicionales en el archivo OTU#

Se ignoran y no crean nuevos identificadores.

63. Filas actuales ausentes del archivo#

Las nuevas columnas permanecen NA para esas filas.

64. Renombrado automático de ASV#

Combina un prefijo, el eje declarado y los identificadores actuales.

65. Conservación de números finales#

Si todos los identificadores terminan en números únicos, se conservan: ASV128 puede convertirse en Feature128.

66. Renombrado secuencial#

Si algún identificador no posee un número final utilizable, todos se renombran secuencialmente según el orden interno.

67. Colisiones de nombres nuevos#

Si los nombres generados no son únicos, se utiliza un renombrado secuencial de respaldo.

68. Validación del prefijo#

Solo se eliminan espacios externos. Use prefijos simples como ASV, OTU, ZOTU o Feature.

69. Propagación del renombrado de ASV#

Con identificadores antiguos únicos, los nombres se propagan a tax_table, refseq y hojas del árbol.

70. Identificadores duplicados antes del renombrado#

La propagación se desactiva y el objeto puede seguir incoherente. Corrija duplicados antes.

71. Realineación de secuencias tras modificar OTU#

Las secuencias sin nombre se nombran por orden si el número coincide; las completas se reordenan. Si falta una secuencia para algún taxón, se elimina toda refseq.

72. Realineación del árbol tras modificar OTU#

Se podan hojas adicionales. Si falta un taxón OTU, se elimina todo el árbol.

73. Paquete ape ausente#

Si ape no está disponible durante una modificación OTU, el árbol se elimina con advertencia.

74. Taxonomía tras cambios estructurales OTU#

La propagación es explícita al renombrar ASV, pero no está garantizada para todos los cambios. Verifique los identificadores.

75. Edición de taxonomía — presentación#

Actúa sobre tax_table(ps): celdas, rangos, fusión, reemplazo automático, deshacer y restablecer.

76. Taxonomía ausente#

Use la importación completa para añadir una tabla taxonómica.

77. Confirmación antes de la primera edición taxonómica#

El primer intento solo abre una ventana informativa y no ejecuta la acción. Ciérrela y repita la acción.

78. Nueva confirmación tras cambiar de dataset#

El estado se reinicia al cambiar el dataset seleccionado.

79. Edición de una celda taxonómica#

El valor se guarda como texto. No se valida nomenclatura ni coherencia taxonómica.

80. Sin verificación de jerarquía#

No se comprueba la coherencia especie–género–familia ni la validez de los nombres.

81. Añadir un rango taxonómico#

Se añade al final una columna de NA con un nombre estricto, válido y único.

82. Orden de los rangos#

No se impone orden. Mantenga manualmente una secuencia coherente.

83. Renombrar un rango taxonómico#

No hay botón directo. Cree un rango nuevo, transfiera valores y elimine el antiguo, o realice la operación en R.

84. Eliminar un rango#

La eliminación es inmediata con el nombre exacto; pueden aparecer sugerencias.

85. Eliminar todos los rangos#

No existe una protección general. Para eliminar toda la taxonomía, use la eliminación completa del componente.

86. Orden taxonómico por ASV#

El orden natural solo afecta la visualización y usa la primera secuencia numérica del identificador.

87. Sincronización tras renombrar ASV#

Si cambian los rownames manteniendo el mismo número de filas, se actualizan los estados locales y se añade una entrada de sincronización.

88. Límite de la sincronización taxonómica#

Una sustitución completa con los mismos identificadores puede no actualizar los valores locales. Cambie de dataset y vuelva.

89. Fusionar un archivo en taxonomía#

Añade únicamente rangos ausentes para taxones comunes; los demás reciben NA.

90. Sin detección automática del separador taxonómico#

Debe seleccionarse manualmente.

91. Columnas taxonómicas existentes#

Fusionar no sustituye rangos existentes como Genus. Use importación completa.

92. Reemplazo automático de valores#

Patrones como NA, unidentified, unclassified, unknown o missing pueden sustituirse por un texto común.

93. Coincidencia exacta sin distinguir mayúsculas#

Los patrones se recortan, se convierten a minúsculas y se comparan exactamente.

94. Patrón NA#

Coincide con valores realmente ausentes y con variantes textuales de NA.

95. Patrón vacío#

Apunta a cadenas vacías o compuestas solo por espacios.

96. Alcance del reemplazo#

Se aplica a todos los rangos; no existe selección de una sola columna.

97. Previsualización obligatoria#

Se muestran totales por patrón y columna antes de confirmar.

98. Patrones solapados#

Una celda puede coincidir con varios patrones; los recuentos por patrón pueden solaparse.

99. Valor de reemplazo no vacío#

No se permite una cadena de reemplazo vacía.

100. Consecuencias científicas del reemplazo#

Convertir NA en Unassigned crea una categoría real y modifica completitud, aglomeración y gráficos.

101. Agrupación de taxones no asignados#

Los taxones con el mismo texto pueden agruparse mediante tax_glom(), a diferencia de los valores ausentes reales.

102. Estado taxonómico inicial y restablecimiento#

El estado inicial se vuelve a capturar al cargar localmente el dataset; cambiar de dataset puede alterar la referencia de Restablecer.

103. Importación, exportación y eliminación — presentación#

Gestiona componentes completos: metadata, OTU, taxonomía, RefSeq y árbol.

104. Importación automática#

Comienza al seleccionar el archivo, sin confirmación adicional ni previsualización general.

105. Límite de tamaño#

Se aplica el límite global de carga de BarCodeR, aproximadamente 500 MB.

106. Detección de separador en importaciones completas#

Se inspecciona principalmente la primera línea: punto y coma, después tabulación, y si no, coma. Es menos robusto que Fusionar.

107. Importación completa de metadata#

La primera columna contiene identificadores. Las muestras desconocidas provocan rechazo; las ausentes se añaden con NA. La metadata anterior se reemplaza por completo.

108. Importación completa de OTU#

Se interpreta como taxones en filas y muestras en columnas, imponiendo taxa_are_rows = TRUE.

109. Identificadores aceptados para OTU#

Taxones y muestras deben ser subconjuntos de los identificadores existentes. No se añaden nuevos elementos.

110. Identificadores ausentes en OTU#

Los taxones o muestras actuales ausentes se rellenan con cero y se reordenan según el objeto.

111. Conversión numérica en OTU#

Toda la tabla se convierte a numérico; los valores inválidos pasan a NA y la importación puede continuar con advertencia.

112. Importación completa de taxonomía#

La primera columna contiene taxones. Los desconocidos se rechazan; los ausentes se añaden con NA. Se sustituye la tabla anterior.

113. Importación de RefSeq#

Los identificadores FASTA deben corresponder y cubrir todos los taxones. Se rechazan archivos parciales o identificadores desconocidos.

114. Importación del árbol#

Las hojas Newick deben corresponder y cubrir todos los taxones. Las hojas desconocidas o taxones ausentes provocan rechazo.

115. Sustitución completa de componentes#

El componente antiguo no se conserva como snapshot. Solo se registran dimensiones, archivo y advertencias.

116. Actualización de editores tras importación completa#

Los editores locales pueden conservar una copia antigua si no cambia el nombre del dataset. Cambie de dataset y vuelva antes de editar.

117. Exportación de componentes#

Metadata, OTU y taxonomía se exportan como CSV; RefSeq como FASTA; el árbol como Newick.

118. Separador de exportaciones CSV#

Se utiliza punto y coma ; aunque la extensión sea .csv.

119. Exportación de metadata#

Se crea una columna SampleID desde los rownames y los valores ausentes se exportan como celdas vacías.

120. Exportación de OTU#

Se conserva la orientación almacenada y el archivo no registra explícitamente taxa_are_rows.

121. Exportación de taxonomía#

Los identificadores aparecen en la primera columna y las anotaciones ausentes como celdas vacías.

122. Exportación de RefSeq#

Se escribe FASTA con los nombres actuales; requiere Biostrings.

123. Exportación del árbol#

Se escribe Newick; requiere ape.

124. Exportación e historial#

Cada exportación añade una entrada a edit_log y puede marcar el proyecto como no guardado.

125. Eliminación de componentes#

La ventana muestra los componentes presentes y permite seleccionar varios antes de confirmar.

126. Eliminar metadata#

Se retira sam_data; los análisis con grupos o covariables dejan de estar disponibles.

127. Eliminar taxonomía#

Se retira tax_table; los análisis taxonómicos dejan de estar disponibles.

128. Eliminar RefSeq#

Se pierden las secuencias para análisis de longitud, GC o secuencia.

129. Eliminar el árbol#

UniFrac, Faith PD y visualizaciones filogenéticas dejan de estar disponibles.

130. Eliminar la tabla OTU#

La interfaz lo permite, pero elimina el componente central y hace inutilizable el dataset en la mayoría de módulos.

131. Eliminar varios componentes#

Pueden retirarse varios slots aunque el objeto restante quede incoherente.

132. Deshacer la eliminación de un componente#

No hay Undo. Reimporte, restaure el proyecto o cargue una exportación anterior.

133. Eliminación y archivos en disco#

La eliminación afecta a la memoria hasta guardar el proyecto. Los archivos fuente y copias anteriores no se eliminan.

134. Guardar el dataset en el registro#

El campo de nombre permite registrar con el mismo nombre, crear una entrada nueva o sustituir una existente.

135. Nombre vacío#

Se vuelve a registrar con el nombre actual, permanece activo y se añade una entrada al log. El proyecto no se guarda en disco.

136. Nuevo nombre disponible#

Se crea una entrada con el estado editado y pasa a ser activa. La fuente permanece, pero ya estaba editada.

137. Nombre usado por otro dataset#

Tras confirmar, el objetivo se sobrescribe por completo con el estado editado; la fuente también permanece.

138. Limpieza del nombre#

El helper común limpia el nombre antes de comprobar colisiones.

139. Sobrescribir otro dataset#

Se sustituyen tablas, secuencias, árbol, atributos, logs y procedencia. No es una fusión.

140. Guardar el proyecto completo#

Use Datasets → Guardar proyecto para persistir el registro en disco.

141. Resolución de problemas#

Las subsecciones siguientes describen errores frecuentes y sus causas reales.

141.1. Se modificó el dataset equivocado#

El selector sigue el dataset activo global. Compruebe el nombre antes de cada acción.

141.2. El original cambió aunque se quería un nombre nuevo#

La edición ocurre antes de copiar. Restaure una copia, exportación o archivo original.

141.3. Guardar no guardó el proyecto#

Solo modifica el registro en memoria. Guarde desde Datasets.

141.4. La metadata apareció automáticamente#

El dataset no contenía sample_data; se creó una tabla mínima.

141.5. Editar SampleID no renombró muestras#

Los identificadores reales son los rownames.

141.6. Una variable numérica se convirtió en texto#

Se introdujo un valor no numérico. Repare toda la columna o reimporte metadata tipada.

141.7. Un factor se convirtió en character#

El editor aplana los factores. Restaure niveles en R si es necesario.

141.8. Una columna nueva tiene el tipo incorrecto#

Comienza con NA y se infiere a partir de los valores. Revísela y conviértala.

141.9. Fusionar metadata no actualizó una columna#

Solo añade columnas ausentes. Use importación completa o edite celdas.

141.10. No se encontró un identificador común#

Revise primera columna, opción rownames, mayúsculas, espacios y ortografía.

141.11. El separador detectado es incorrecto#

Selecciónelo manualmente en archivos irregulares.

141.12. Valores OTU se convirtieron en NA#

Falló la conversión por texto, símbolos, espacios o coma decimal.

141.13. Los decimales con coma se vuelven NA#

El separador decimal esperado es el punto.

141.14. Una columna OTU nueva desincronizó metadata#

La muestra se añadió solo a OTU. Añada metadata o reconstruya el objeto.

141.15. RefSeq desapareció tras modificar OTU#

Ya no cubría todos los taxones.

141.16. El árbol desapareció tras modificar OTU#

Faltaba un taxón, el renombrado no se propagó o ape no estaba disponible.

141.17. Desaparecieron hojas del árbol#

Las hojas adicionales se podan automáticamente.

141.18. Las muestras se renombraron como ASV#

Se declaró el eje incorrecto. Restaure una copia.

141.19. El prefijo ASV produjo nombres extraños#

No se valida estrictamente. Use un prefijo simple.

141.20. La taxonomía ya no coincide con OTU#

Revise rownames, duplicados y recargue los editores; compare conjuntos de identificadores en R.

141.21. La primera modificación taxonómica no se ejecutó#

El primer intento solo abre la advertencia. Repita la acción.

141.22. Un reemplazo taxonómico cambió varios rangos#

Se aplica a todas las columnas. Revise la previsualización por rango.

141.23. NA ahora se considera una categoría real#

Se sustituyó por texto y puede agregarse como taxonomía asignada.

141.24. La fusión taxonómica no sustituyó Genus#

El rango ya existe; Fusionar solo añade rangos ausentes.

141.25. No se detectó el separador taxonómico#

Debe seleccionarse manualmente.

141.26. La importación completa borró columnas#

Sustituye todo el componente. Restaure una copia o use Fusionar.

141.27. La importación OTU cambió la orientación#

Siempre impone taxones en filas.

141.28. La importación rechaza nuevas muestras#

Los identificadores deben existir. Construya un phyloseq completo nuevo.

141.29. La importación rechaza nuevos taxones#

Los rownames deben pertenecer a taxa_names(ps).

141.30. Se rechaza el FASTA#

Revise formato, identificadores, cobertura completa y disponibilidad de Biostrings.

141.31. Se rechaza el árbol#

142. Checklist antes de editar#

  • Confirme proyecto y dataset.
  • Duplique el dataset bruto.
  • Guarde el proyecto y exporte datos importantes.
  • Revise componentes y orientación OTU.
  • Cierre otras sesiones que puedan escribir en el mismo proyecto.

143. Checklist antes de editar metadata#

  • Revise rownames y no los confunda con SampleID.
  • Documente tipos, factores, fechas y valores ausentes.
  • Use nombres válidos.
  • Verifique los tipos después.

144. Checklist antes de editar OTU#

  • Revise taxa_are_rows y el eje ASV.
  • Confirme la naturaleza de las abundancias y ausencia de texto.
  • Revise metadata, taxonomía, RefSeq y árbol antes de cambios estructurales.
  • Exporte antes de renombrar masivamente.

145. Checklist antes de reemplazar taxonomía#

  • Revise patrones, mayúsculas y espacios.
  • Examine recuentos por rango.
  • Comprenda NA frente a categorías textuales.
  • Anticipe efectos de aglomeración.
  • Conserve la taxonomía original.

146. Checklist antes de una importación completa#

  • Verifique dataset, separador, primera columna, identificadores y cobertura.
  • Guarde el componente anterior.
  • Comprenda que será reemplazado.
  • Recargue editores y valide en Description.

147. Checklist antes de eliminar un componente#

  • Exporte el componente y guarde el proyecto.
  • Revise módulos dependientes.
  • Evite eliminar OTU salvo casos excepcionales.
  • Recuerde que no existe Undo.

148. Checklist después de Data Edition#

  • Abra Description y revise dimensiones, sumas, tipos, ausencias, taxonomía, RefSeq y árbol.
  • Verifique identificadores y lea el historial.
  • Guarde el proyecto en Datasets.

150. Limitaciones actuales#

  • Los cambios son inmediatos y el original no se preserva automáticamente.
  • Guardar no persiste el proyecto.
  • Undo conserva un estado y Reset depende de la carga local.
  • Puede crearse metadata automáticamente.
  • Factores y clases especiales pueden perderse.
  • El switch ASV no transpone.
  • Las ediciones OTU pueden desincronizar componentes.
  • Los reemplazos taxonómicos afectan todos los rangos.
  • Las importaciones completas empiezan sin previsualización y no extienden identificadores.
  • Los editores locales pueden mostrar copias obsoletas.
  • Exportar modifica el log.
  • Se permite eliminar OTU.
  • No se ejecuta un guard completo tras cada acción.

151. Flujo recomendado#

  1. Guarde el proyecto y duplique el dataset bruto.
  2. Edite la copia.
  3. Verifique orientación OTU.
  4. Edite metadata y controle los tipos.
  5. Edite OTU solo cuando sea necesario.
  6. Revise taxonomía, RefSeq y árbol tras cambios estructurales.
  7. Use las previsualizaciones taxonómicas.
  8. Recargue tras importar o eliminar componentes.
  9. Valide en Description.
  10. Guarde el proyecto y exporte el dataset final.
