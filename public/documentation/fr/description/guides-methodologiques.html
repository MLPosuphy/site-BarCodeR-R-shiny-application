Description — Guides méthodologiques

1. Présentation générale#

L’onglet Description sert à examiner la structure et le contenu des objets phyloseq présents dans BarCodeR avant de poursuivre vers l’édition, la filtration ou les analyses statistiques.

Il est organisé en deux vues complémentaires.

Vue Dataset#

Elle inspecte un objet phyloseq à la fois et permet de :

  • vérifier ses dimensions ;
  • vérifier les composants disponibles ;
  • consulter ses métriques descriptives ;
  • visualiser les abondances et la richesse ;
  • inspecter les séquences de référence ;
  • calculer des courbes de raréfaction ;
  • repérer des échantillons atypiques ;
  • consulter et exporter les tables ;
  • consulter les logs de filtration ;
  • relire la provenance OpenMetaBar.

Vue Projet#

Elle compare plusieurs datasets présents en mémoire et permet de :

  • obtenir une synthèse de tous les objets chargés ;
  • sélectionner les datasets à comparer ;
  • comparer leurs dimensions ;
  • comparer leurs profondeurs et leur richesse ;
  • comparer leur sparsité ;
  • examiner les différences par rapport à un dataset de référence ;
  • comparer les suppressions documentées dans leurs logs de filtration.

2. Rôle de l’onglet#

Description est principalement destiné à comprendre les données, contrôler un import, repérer les anomalies évidentes, préparer les choix méthodologiques ultérieurs et comparer la structure générale de plusieurs datasets.

Besoin Onglet approprié
Modifier les tables Data Edition
Retirer des échantillons ou des taxons Filtration
Renommer ou supprimer un dataset Datasets
Réaliser une analyse statistique Analyse
Produire un pipeline depuis des FASTQ OpenMetaBar

3. Effet de l’onglet sur les données#

Description ne modifie pas l’OTU table, la taxonomie, les métadonnées, les séquences, l’arbre, les abondances, les identifiants ni les logs. Les graphiques et tableaux sont construits à partir de l’objet présent en mémoire.

3.1. Exception : dataset actif#

Le sélecteur principal de la vue Dataset est synchronisé avec le dataset actif global. Changer le dataset dans Description :

  • modifie active_ds() ;
  • change le dataset actif dans le reste de BarCodeR ;
  • peut marquer le projet comme comportant une modification non sauvegardée.

Le contenu du phyloseq n’est pas modifié, mais le contexte de travail global change.

4. Conditions nécessaires#

Pour utiliser la majorité des fonctions de Description, le dataset doit contenir au minimum une otu_table.

Les composants suivants sont facultatifs :

  • sample_data ;
  • tax_table ;
  • refseq ;
  • arbre phylogénétique ;
  • attributs de provenance ;
  • logs de filtration.

L’absence d’un composant réduit les informations disponibles, mais n’empêche pas nécessairement l’ouverture de l’onglet.

5. Hypothèse importante sur les abondances#

Le module présente les valeurs de l’OTU table sous le terme reads, mais ne vérifie pas qu’elles sont des comptes bruts, entiers, non transformés et non négatifs.

Si le phyloseq contient des abondances relatives, une transformation CLR ou logarithmique, une normalisation, des valeurs décimales ou des valeurs négatives, les métriques affichées comme « reads » ne correspondent plus à une profondeur de séquençage brute.

Cette distinction est essentielle pour interpréter les sommes, la richesse, la dominance, les courbes de raréfaction et les comparaisons entre datasets.

7. Sélectionner le dataset#

Le champ Sélectionner un dataset contient tous les datasets présents dans la session.

7.1. Synchronisation globale#

La sélection suit le dataset actif global. Si le dataset actif est changé dans Datasets, dans la barre latérale ou dans un autre sélecteur global, Description se synchronise avec cette nouvelle valeur. Inversement, changer la sélection dans Description change le dataset actif de l’application.

7.2. Valeur de repli#

Si aucun dataset actif valide n’est défini, Description utilise :

  1. le dataset sélectionné précédemment s’il existe toujours ;
  2. sinon le premier dataset de la liste.

7.3. Changement de dataset#

Lors d’un changement, les métriques, graphiques, tables, paramètres de groupement, provenance et outliers sont recalculés.

Attention — raréfaction : le calcul de raréfaction n’est pas automatiquement relancé lors du changement de dataset. Il faut cliquer de nouveau sur Calculer les courbes.

8. Variable de groupement#

Le champ Variable de groupement — échantillons permet de colorer ou séparer les échantillons selon une colonne de sample_data.

8.1. Variables proposées#

Une colonne est proposée lorsqu’elle contient au moins deux et au maximum quinze valeurs distinctes non manquantes. Les colonnes Date, POSIXct et POSIXt sont exclues.

8.2. Colonnes numériques#

Une colonne numérique peut être proposée si elle contient entre deux et quinze valeurs distinctes. Elle est alors interprétée comme une variable catégorielle.

Exemple :

Temperature = 10, 15, 20

sera traitée comme trois groupes et non comme une variable quantitative continue.

8.3. Valeurs manquantes#

Les valeurs manquantes sont regroupées sous l’étiquette NA. Une chaîne de caractères littérale "NA" et une vraie valeur manquante peuvent donc devenir visuellement difficiles à distinguer.

8.4. Aucun groupement#

Lorsque Aucun groupement est sélectionné, tous les échantillons sont placés dans un groupe unique nommé Tous.

8.5. Effets du groupement#

Le groupement agit sur :

  • la couleur du nuage reads/richesse ;
  • les violons par groupe ;
  • les courbes cumulées par groupe ;
  • les couleurs de raréfaction ;
  • la raréfaction agrégée ;
  • la contextualisation des outliers ;
  • la concentration des outliers par groupe.

Il ne modifie pas les données.

9. Le groupement ne change pas la détection des outliers#

Les outliers sont calculés sur l’ensemble des échantillons du dataset. Ils ne sont pas recalculés séparément à l’intérieur de chaque groupe.

La variable de groupement sert uniquement à contextualiser les outliers, voir dans quels groupes ils se concentrent et colorer les représentations.

Un échantillon peut donc être normal au sein de son propre groupe, mais être détecté comme outlier par rapport à l’ensemble du dataset.

10. Bouton « Voir les logs »#

Le bouton Voir les logs sélectionne le sous-onglet Logs de filtrage dans la section Tables et logs.

Dans le fonctionnement actuel, il ne fait pas défiler automatiquement la page et n’ouvre pas forcément la box si elle est repliée. Après le clic, il peut être nécessaire de descendre jusqu’à Tables et logs, déplier la box puis consulter le sous-onglet déjà sélectionné.

11. En-tête du dataset#

L’en-tête affiche :

  • le nom du dataset ;
  • le nombre d’échantillons ;
  • le nombre de taxons ;
  • le total des abondances ;
  • les composants disponibles.

Exemple :

130 échantillons • 2 450 ASVs/OTUs • 7 779 736 reads

12. Badges de composants#

Les badges indiquent la présence de l’OTU table, de la taxonomie, des métadonnées, des séquences de référence et des logs de filtration.

12.1. OTU#

Indique qu’une otu_table a été détectée.

12.2. Taxonomie#

Indique qu’une tax_table a été détectée. Cela ne garantit ni que toutes les ASV sont annotées, ni que tous les rangs sont complets, ni que la taxonomie est biologiquement correcte.

12.3. Métadonnées#

Indique qu’une sample_data a été détectée. Cela ne garantit pas que toutes les variables sont exploitables, que les types sont corrects ou qu’il n’y a pas de valeurs manquantes.

12.4. RefSeq#

Indique que les séquences de référence sont disponibles et que le package Biostrings permet de les lire. Si Biostrings n’est pas disponible, les séquences peuvent être considérées comme absentes par Description même si l’objet contient une refseq.

12.5. Logs#

Indique la présence de l’attribut filtration_log. Cela ne garantit pas que le log contient effectivement des lignes d’ASV ou d’échantillons supprimés.

12.6. Arbre phylogénétique#

Le module actuel n’affiche pas de badge dédié à l’arbre phylogénétique. L’absence de badge ne permet donc pas de savoir si un phy_tree est présent.

13. Orientation de l’OTU table#

Description réoriente temporairement la matrice pour ses calculs afin d’obtenir les taxons en lignes et les échantillons en colonnes.

Si l’objet possède les taxons en colonnes, la matrice est transposée en mémoire pour les calculs descriptifs. L’objet phyloseq original n’est pas transposé ni modifié.

14. Métrique : nombre de taxons#

Le nombre affiché correspond au nombre de lignes de la matrice réorientée, équivalent à phyloseq::ntaxa(ps).

Le terme ASV est utilisé dans l’interface, mais les unités peuvent être des ASV, OTU, ZOTU, espèces regroupées ou autres unités. Description ne vérifie pas la méthode utilisée pour construire les taxons.

15. Métrique : nombre d’échantillons#

Le nombre correspond au nombre de colonnes de la matrice réorientée, équivalent à phyloseq::nsamples(ps).

16. Métrique : total des reads#

Le total est la somme de toutes les cellules de l’OTU table, avec exclusion des valeurs manquantes.

Cette somme n’est interprétable comme un total de reads que si la matrice contient des comptes bruts.

17. Métrique : reads par échantillon#

Pour chaque échantillon :

Reads = somme des abondances de tous les taxons

Le module calcule ensuite minimum, maximum, moyenne, médiane et écart-type. La médiane est affichée dans les cartes principales.

18. Métrique : richesse observée#

Pour chaque échantillon :

Richesse = nombre de taxons dont l’abondance est strictement supérieure à zéro

Il s’agit d’une richesse observée brute. Elle ne correspond pas à Chao1, ACE, Shannon, Simpson ou à une richesse corrigée pour la profondeur.

Deux échantillons ayant des profondeurs différentes peuvent donc avoir des richesses non directement comparables.

19. Métrique : dominance du taxon majoritaire#

Pour chaque échantillon :

Dominance (%) =
abondance maximale d’un taxon
÷ abondance totale de l’échantillon
× 100

Une dominance élevée peut refléter une communauté réellement dominée, une amplification préférentielle, un contaminant, un problème de composition, une faible profondeur ou un échantillon particulier. Elle ne permet pas seule de conclure à une mauvaise qualité.

20. Métrique : part de zéros par échantillon#

Pour chaque échantillon :

Zéros (%) =
nombre de taxons avec une abondance égale à zéro
÷ nombre total de taxons
× 100

Cette valeur décrit la proportion de taxons absents de l’échantillon. Elle n’est pas utilisée dans la détection actuelle des outliers.

21. Métrique : sparsité globale#

La sparsité correspond à :

nombre de cellules égales à zéro
÷ nombre total de cellules de l’OTU table
× 100

21.1. Interprétation#

Une sparsité élevée signifie qu’une grande partie des couples taxon-échantillon possède une abondance nulle. C’est fréquent en métabarcoding en raison de la diversité, de la spécialisation des taxons, de la variabilité spatiale, des limites de détection, de la profondeur et des traitements bioinformatiques.

21.2. Seuils d’affichage utilisés#

Sparsité Message
≥ 97 % Sparsité très élevée
90 à < 97 % Sparsité élevée
< 90 % Sparsité maîtrisée

Ces seuils sont des règles d’affichage internes et non des normes scientifiques universelles.

21.3. Présence de NA#

Le dénominateur utilise la taille totale de la matrice. Les valeurs NA ne sont pas comptées comme des zéros, mais restent comprises dans le nombre total de cellules. Une matrice contenant des NA peut donc produire une estimation de sparsité légèrement sous-évaluée.

22. Variabilité de la profondeur#

Description calcule un coefficient de variation :

CV (%) =
écart-type des reads par échantillon
÷ moyenne des reads par échantillon
× 100

Un message de profondeur très hétérogène est affiché lorsque CV ≥ 100 %.

Ce seuil est une règle descriptive interne et non une limite universelle. Un CV inférieur à 100 % ne garantit pas que les profondeurs sont suffisamment homogènes pour toutes les analyses.

23. Complétude taxonomique#

Pour chaque rang taxonomique :

Complétude (%) =
nombre de valeurs non manquantes et non vides
÷ nombre total d’ASV
× 100

La complétude moyenne affichée est la moyenne non pondérée des pourcentages de complétude de tous les rangs.

23.1. Conséquence#

Un dataset comportant plusieurs rangs très incomplets et quelques rangs très complets peut avoir une moyenne intermédiaire qui masque les différences. Il faut consulter le tableau détaillé.

23.2. Chaînes contenant des espaces#

Une chaîne contenant uniquement des espaces peut être considérée comme renseignée si elle n’a pas été nettoyée avant l’import.

24. Valeurs manquantes des métadonnées#

Pour chaque variable :

% manquant =
nombre de NA ou de chaînes vides
÷ nombre d’échantillons
× 100

La moyenne affichée correspond à la moyenne non pondérée des taux de valeurs manquantes de toutes les variables.

24.1. Valeur "NA"#

La chaîne de caractères "NA" n’est pas une vraie valeur manquante et peut être comptée comme une modalité.

24.2. Espaces#

Une chaîne contenant uniquement des espaces peut être considérée comme renseignée.

24.3. Type affiché#

Le tableau de complétude affiche la première classe R de la colonne : character, numeric, factor, Date, etc. Cela permet notamment de repérer les colonnes devenues character après un import.

25. Longueur des séquences#

Lorsque refseq et Biostrings sont disponibles, Description calcule longueur minimale, maximale, moyenne, médiane et écart-type, en paires de bases.

25.1. Interprétation#

Une distribution multimodale ou très étendue peut indiquer plusieurs régions amplifiées, plusieurs marqueurs, des séquences tronquées, des indels, des produits non spécifiques, des séquences mal filtrées ou une variabilité biologique réelle.

La longueur attendue doit être interprétée selon le marqueur, les amorces, la présence ou non des amorces et le pipeline utilisé.

26. Pourcentage de GC#

Le pourcentage de GC est calculé à partir des bases A, C, G et T :

GC (%) =
nombre de G + nombre de C
÷ nombre total de A, C, G et T
× 100

Les bases ambiguës ne sont pas incluses dans le dénominateur ACGT. Une séquence contenant beaucoup de caractères ambigus peut donc produire une valeur de GC basée uniquement sur sa portion non ambiguë.

27. Noms des séquences#

Description utilise les noms contenus dans refseq. Si les séquences n’ont pas de noms valides, des identifiants génériques sont produits pour l’affichage :

ASV_1
ASV_2
ASV_3

Le module ne vérifie pas explicitement que chaque nom de séquence correspond à un taxon de l’OTU table.

28. Message d’interprétation automatique#

La carte de synthèse construit un texte à partir de quelques métriques : reads médians, richesse médiane, sparsité et présence des composants.

Ce texte est une aide descriptive. Il ne constitue pas une validation scientifique, un contrôle qualité définitif, une décision de filtration ou une recommandation statistique automatique.

29. Lecture rapide du dataset#

La section présente quatre domaines.

29.1. Structure#

Résumé des reads médians, de la richesse médiane et de la sparsité.

29.2. Contenu disponible#

Présence ou absence de l’OTU table, de la taxonomie, des métadonnées et des séquences.

29.3. Séquences#

Lorsque disponibles : longueur médiane et GC médian.

29.4. Filtration#

Lorsque l’attribut filtration_log existe : nombre d’ASV supprimées et nombre d’échantillons supprimés.

30. Diagnostics automatiques#

La grille diagnostique peut signaler :

  • sparsité élevée ;
  • profondeur hétérogène ;
  • absence de métadonnées ;
  • absence de taxonomie ;
  • absence de séquences ;
  • présence d’un historique de filtration.

Ces alertes ne modifient rien et ne doivent pas être utilisées seules pour exclure des données.

31. Provenance OpenMetaBar#

La box Provenance OpenMetaBar lit l’attribut attr(ps, "openmetabar_run"). Elle ne contacte pas le cluster. Il s’agit d’un instantané enregistré dans l’objet phyloseq au moment de l’import.

31.1. Résumé du run#

Peut contenir l’identifiant du run, le libellé, la date de lancement, la technologie, le marqueur, le moteur, le type et le chemin de la base, le design file, le nombre d’échantillons et le nombre de FASTQ.

31.2. Démultiplexage#

Peut contenir les paramètres MiniBar : activation, méthode, tolérances et autres options enregistrées.

31.3. Filtres#

Peut contenir orientation, qualité, longueur, filtre codant et table génétique.

31.4. LotuS3#

Peut contenir plateforme, type d’amplicon, clustering, assignation et autres paramètres enregistrés.

31.5. LCA#

Peut contenir couverture, seuils d’identité, fraction d’accord et mode d’assignation.

31.6. IDMABIO#

Présent uniquement si la route correspondante a été utilisée.

31.7. NextITS#

Présent uniquement si la route correspondante a été utilisée.

31.8. Environnement cluster#

Peut contenir partition, mémoire, processeurs, modules et chemins distants.

31.9. Fichiers FASTQ#

La liste des fichiers peut être affichée. Les chemins représentent la provenance enregistrée, pas nécessairement des fichiers encore accessibles.

31.10. Renommage des échantillons#

La provenance peut conserver le nom d’origine, le nom corrigé, la date et la raison.

31.11. Absence de provenance#

Une absence de provenance ne signifie pas nécessairement que le dataset n’a jamais été produit par OpenMetaBar. L’attribut peut avoir été supprimé, perdu lors d’une conversion, remplacé, absent dans une ancienne version ou non conservé lors d’un export externe.

32. Visualisations interactives — Vue d’ensemble#

La vue d’ensemble comporte :

  1. Reads versus richesse.
  2. Fiche d’échantillon.
  3. Top 15 des échantillons.
  4. Top 15 des taxons.
  5. Contribution cumulée des échantillons.
  6. Contribution cumulée des taxons.

33. Reads versus richesse#

Chaque point représente un échantillon.

X = abondance totale
Y = richesse observée

La couleur représente le groupe sélectionné et le symbole représente le statut : cercle pour standard, losange pour outlier.

33.1. Interprétation#

Le graphique permet de repérer une relation entre profondeur et richesse, des échantillons peu profonds, des échantillons riches mais peu profonds, des points éloignés du nuage et des différences entre groupes.

33.2. Limite#

Une relation positive entre reads et richesse ne prouve pas que la profondeur est la seule cause des différences biologiques.

33.3. Interaction#

Cliquer sur un point met à jour la fiche d’échantillon.

34. Fiche d’échantillon#

La fiche affiche SampleID, reads, richesse, dominance, part de zéros, statut et jusqu’à six valeurs de métadonnées disponibles.

34.1. Échantillon initial#

Avant tout clic, la fiche affiche le premier outlier détecté s’il en existe un, sinon le premier échantillon du dataset.

34.2. Métadonnées affichées#

Les colonnes entièrement manquantes pour l’échantillon sont exclues. Seules les six premières colonnes exploitables sont affichées : la fiche n’est donc pas exhaustive.

35. Top 15 des échantillons#

Le graphique classe les échantillons par abondance totale décroissante et en affiche au maximum quinze. Cliquer sur une barre met à jour la fiche d’échantillon.

35.1. Limite#

Les échantillons les plus profonds ne sont pas nécessairement les meilleurs, les plus riches, les plus représentatifs ou les plus fiables.

36. Top 15 des taxons#

Le graphique classe les taxons selon la somme de leurs abondances sur tous les échantillons. L’infobulle affiche aussi le nombre et le pourcentage d’échantillons dans lesquels le taxon est présent.

36.1. Prévalence#

Prévalence = nombre d’échantillons où l’abondance est > 0

Prévalence (%) =
prévalence
÷ nombre total d’échantillons
× 100

36.2. Limite#

Le graphique utilise l’identifiant du taxon et non son annotation taxonomique. Un ASV très abondant dans un seul échantillon peut apparaître en tête malgré une faible prévalence.

37. Contribution cumulée des échantillons#

Les échantillons sont classés par abondance décroissante. La courbe montre la proportion cumulée des abondances expliquée par les premiers échantillons.

Une forte montée initiale indique que la profondeur est concentrée dans un petit nombre d’échantillons.

38. Contribution cumulée des taxons#

Les taxons sont classés par abondance totale décroissante. La courbe montre la proportion cumulée des abondances expliquée par les taxons dominants.

Elle ne tient pas compte de la taxonomie, de la prévalence, des groupes ou de la rareté biologique.

39. Onglet Abondance#

Il comprend :

  • histogramme des reads ;
  • violon des reads par groupe ;
  • contribution cumulée des reads par groupe.

40. Histogramme des reads#

L’histogramme décrit la distribution des abondances totales par échantillon. Il permet de repérer asymétrie, échantillons peu ou très profonds et plusieurs populations de profondeur.

Le nombre de classes est déterminé automatiquement par Plotly.

41. Reads par groupe#

Le graphique en violon est disponible lorsqu’une variable de groupement contient plusieurs groupes. Il affiche distribution, boîte à moustaches, moyenne et points individuels.

41.1. Absence de groupement#

Si aucun groupement n’est sélectionné, un message indique qu’aucune variable qualitative n’est disponible.

41.2. Interprétation#

Le graphique est descriptif. Il ne réalise aucun test statistique, aucune normalisation, aucune correction pour les tailles de groupe ni pour les covariables.

42. Contribution cumulée des reads par groupe#

Pour chaque groupe, les échantillons sont triés par abondance décroissante puis le cumul est calculé à l’intérieur du groupe. Chaque courbe atteint donc 100 % pour son propre groupe.

42.1. Conséquence#

Les courbes montrent la concentration interne de la profondeur dans chaque groupe. Elles ne montrent pas la proportion de reads du projet attribuable à chaque groupe.

Un groupe très petit et un groupe très grand atteignent tous deux 100 %.

43. Onglet Richesse#

Il comprend :

  • histogramme de richesse ;
  • richesse par groupe ;
  • richesse versus dominance.

44. Histogramme de richesse#

Il affiche la distribution du nombre de taxons présents par échantillon.

Cette richesse n’est pas corrigée pour la profondeur. Un échantillon plus profond peut mécaniquement contenir davantage de taxons observés.

45. Richesse par groupe#

Le graphique en violon compare la richesse observée entre les groupes. Comme pour les reads, il est descriptif et ne réalise aucun test statistique.

46. Richesse versus dominance#

X = richesse observée
Y = dominance du taxon majoritaire

Ce graphique peut distinguer des communautés riches et équilibrées, riches mais dominées, pauvres et dominées ou des profils atypiques.

46.1. Ce graphique n’est pas un indice d’équitabilité#

La dominance du taxon majoritaire peut servir de proxy simple, mais elle ne correspond pas à Pielou, Shannon, Simpson ou à une mesure complète d’équitabilité.

Deux communautés ayant la même dominance maximale peuvent avoir des distributions très différentes pour les taxons restants.

47. Onglet Séquences#

Il comprend :

  • histogramme des longueurs ;
  • histogramme du GC ;
  • relation longueur versus GC.

Ces graphiques exigent une refseq et le package Biostrings.

48. Relation longueur versus GC#

Chaque point correspond à une séquence. Le graphique peut révéler des groupes de tailles ou de composition distincts, des séquences très courtes ou longues, des valeurs GC atypiques ou une combinaison de plusieurs marqueurs.

Il ne permet pas à lui seul de déterminer si une séquence est contaminante ou incorrecte.

49. Courbes de raréfaction#

Le sous-onglet Raréfaction lance un calcul séparé. Le calcul n’est pas effectué automatiquement à l’ouverture.

Il faut cliquer sur Calculer les courbes.

50. Méthode de raréfaction utilisée#

Le module utilise :

vegan::rarefy()

Cette fonction calcule l’espérance analytique du nombre de taxons observés à une profondeur donnée.

Il ne s’agit pas d’une raréfaction aléatoire répétée, d’une création d’un nouveau phyloseq, d’un appel à rarefy_even_depth(), d’un remplacement des abondances ou d’une normalisation enregistrée.

Les données originales restent inchangées.

51. Conditions du calcul de raréfaction#

Le calcul exige :

  • le package vegan ;
  • une OTU table ;
  • au moins deux échantillons avec une abondance positive ;
  • au moins deux échantillons comportant au minimum 50 reads.

Les échantillons contenant moins de 50 reads sont exclus du calcul.

51.1. Seuil de 50 reads#

Le seuil est fixé dans le code et ne peut pas actuellement être modifié dans l’interface.

Il s’agit d’une règle pratique interne, pas d’une norme universelle.

52. Nature attendue des données pour la raréfaction#

vegan::rarefy() est conçu pour des comptes.

La raréfaction n’est pas appropriée pour :

  • des abondances relatives ;
  • des données CLR ;
  • des données négatives ;
  • des transformations continues ;
  • des valeurs non entières.

Le module ne bloque pas explicitement toutes ces situations. Il faut vérifier la nature de l’OTU table avant de lancer le calcul.

53. Profondeurs calculées#

Le module génère jusqu’à environ 80 profondeurs réparties entre 1 et la profondeur maximale observée.

Pour chaque échantillon, seules les profondeurs inférieures ou égales à son total sont conservées. Les profondeurs sont arrondies et dédupliquées.

54. Courbes individuelles#

Le mode Courbes individuelles colorées par groupe affiche une ligne par échantillon. La couleur correspond au groupe.

L’infobulle contient notamment :

  • SampleID ;
  • groupe ;
  • reads totaux ;
  • profondeur raréfiée ;
  • richesse attendue ;
  • richesse observée ;
  • statut outlier.

55. Sous-sélection des courbes individuelles#

Les options sont :

  • Tous les échantillons ;
  • Top reads ;
  • Bottom reads ;
  • Outliers.

55.1. Tous les échantillons#

Toutes les courbes admissibles sont affichées.

Le champ Nombre max de courbes n’est pas appliqué dans ce mode dans l’implémentation actuelle. Un dataset comportant beaucoup d’échantillons peut donc produire un graphique lourd.

55.2. Top reads#

Conserve les échantillons les plus profonds, dans la limite choisie.

55.3. Bottom reads#

Conserve les échantillons les moins profonds parmi ceux ayant au moins 50 reads.

55.4. Outliers#

Conserve les échantillons marqués comme outliers par la règle IQR.

Si aucun outlier n’est disponible, le graphique peut rester vide après le calcul.

56. Nombre maximal de courbes#

Le nombre est limité entre 2 et 200.

Il agit sur Top reads, Bottom reads et Outliers, mais pas actuellement sur Tous les échantillons.

57. Courbes agrégées par groupe#

Le mode Courbes agrégées par groupe additionne les abondances de tous les échantillons d’un groupe. Une courbe est ensuite calculée sur cette communauté poolée.

57.1. Ce que représente la courbe#

Elle représente la richesse attendue dans le pool de reads du groupe.

Elle ne représente pas :

  • la moyenne des courbes individuelles ;
  • la richesse moyenne par échantillon ;
  • une moyenne accompagnée d’un intervalle de confiance ;
  • une comparaison corrigée pour le nombre d’échantillons.

57.2. Effet de la taille des groupes#

Un groupe contenant davantage d’échantillons ou davantage de reads possède un pool plus grand et peut atteindre une richesse plus élevée.

Les courbes agrégées doivent être interprétées en tenant compte du nombre d’échantillons et du nombre total de reads du groupe. Ces informations sont affichées dans les infobulles.

57.3. Sans groupement#

Si aucun groupement n’est sélectionné, tous les échantillons sont poolés dans une seule courbe nommée Tous.

58. Afficher la légende#

La légende est désactivée par défaut. Sur un grand nombre de groupes, l’activer peut réduire la lisibilité du graphique.

Pour les courbes individuelles, une seule entrée de légende est affichée par groupe, même si plusieurs échantillons partagent cette couleur.

59. Recalcul nécessaire#

Le résultat de raréfaction est lié au dataset utilisé au moment du clic.

Changer ensuite le dataset ne relance pas automatiquement le calcul. Il faut cliquer de nouveau sur Calculer les courbes.

59.1. Changement de groupement#

Changer la variable de groupement après le calcul peut mettre à jour les couleurs ou les agrégations à partir du résultat déjà calculé.

59.2. Risque de résultat ancien#

Après un changement de dataset sans nouveau clic, le résultat mémorisé peut encore correspondre au dataset précédent.

Toujours relancer la raréfaction après un changement de dataset.

60. Interprétation des courbes de raréfaction#

Une courbe qui s’aplatit suggère que l’ajout de reads apporte progressivement moins de nouveaux taxons.

Une courbe encore fortement croissante suggère que davantage de profondeur pourrait révéler davantage de taxons.

L’absence de plateau ne prouve cependant pas nécessairement une mauvaise qualité, un séquençage insuffisant ou un échec expérimental. Elle peut aussi refléter une communauté extrêmement diverse, de nombreux taxons rares, du bruit résiduel, des erreurs de séquençage ou une grande hétérogénéité biologique.

61. Limites de la raréfaction affichée#

Le graphique ne fournit pas :

  • d’intervalle de confiance ;
  • de moyenne de répétitions aléatoires ;
  • d’extrapolation ;
  • de couverture de Good ;
  • de Chao1 ;
  • de comparaison statistique entre courbes ;
  • de seuil automatique de saturation.

Il s’agit d’un outil descriptif.

62. Détection des outliers#

La détection repose sur trois métriques :

  1. profondeur ;
  2. richesse ;
  3. dominance.

La part de zéros n’est pas utilisée pour le marquage.

63. Règle IQR#

Pour chaque métrique, Description calcule :

Q1 = premier quartile
Q3 = troisième quartile
IQR = Q3 - Q1

Limites :

Limite basse = Q1 - 1,5 × IQR
Limite haute = Q3 + 1,5 × IQR

Une valeur située en dehors de ces limites est marquée comme outlier. Cette règle correspond à la convention des moustaches d’un boxplot de Tukey.

64. Outliers hauts et bas#

La règle s’applique aux deux extrémités.

Un échantillon peut être marqué pour une profondeur très faible ou très élevée, une richesse très faible ou très élevée, ou une dominance très faible ou très élevée.

Même si certains textes de l’interface insistent sur une dominance excessive, le calcul réel détecte aussi une dominance exceptionnellement basse.

65. Conditions minimales de la règle IQR#

Aucun outlier n’est détecté pour une métrique lorsque :

  • il y a moins de quatre valeurs ;
  • toutes les valeurs sont manquantes ;
  • l’IQR est nul.

Une absence d’outlier peut donc signifier une réelle homogénéité, un effectif trop faible, une absence de variabilité ou un signal non exploitable.

66. Statut d’un échantillon#

Un échantillon est marqué Outlier s’il est atypique sur au moins une des trois métriques. Sinon, il est marqué Standard.

Le statut est descriptif. Aucun échantillon n’est automatiquement supprimé.

67. Nombre de signaux#

Le nombre de signaux correspond au nombre de métriques atypiques parmi profondeur, richesse et dominance.

Valeurs possibles :

0, 1, 2 ou 3

Un échantillon marqué sur trois signaux est priorisé avant un échantillon marqué sur un seul signal.

68. Score d’outlier#

Pour chaque métrique, le dépassement au-delà de la limite est exprimé en unité d’IQR.

Exemple conceptuel :

Score profondeur =
distance au-delà de la limite
÷ IQR

Le score global est la somme des scores profondeur, richesse et dominance. Les échantillons standards reçoivent un score nul.

68.1. Interprétation#

Un score plus élevé indique un dépassement plus éloigné des limites IQR.

Il ne représente pas une probabilité, une p-value, une mesure de qualité universelle ou un seuil de suppression.

69. Ordre de priorité des outliers#

Les outliers sont triés selon :

  1. nombre de signaux ;
  2. score global ;
  3. nombre de reads.

Le premier devient l’échantillon « spotlight ».

70. Résumé des outliers#

La section affiche :

  • nombre total d’outliers ;
  • pourcentage d’échantillons concernés ;
  • nombre d’outliers de profondeur ;
  • nombre d’outliers de richesse ;
  • nombre d’outliers de dominance ;
  • signal le plus fréquent ;
  • groupe le plus exposé, si un groupement est actif.

71. Concentration des outliers par groupe#

Pour chaque groupe :

Pourcentage d’outliers =
nombre d’outliers du groupe
÷ nombre total d’échantillons du groupe
× 100

Les quatre groupes les plus concernés sont affichés.

71.1. Seuils de couleur#

Pourcentage Niveau visuel
≥ 30 % Danger
15 à < 30 % Avertissement
< 15 % Faible

Ces seuils sont uniquement des conventions visuelles et non des seuils statistiques validés.

72. Détection globale et lecture par groupe#

La concentration par groupe doit être interprétée avec prudence : les seuils d’outlier ont été calculés globalement, puis le pourcentage est calculé dans chaque groupe.

Un groupe naturellement différent du reste du dataset peut donc concentrer de nombreux outliers sans contenir d’échantillons techniquement défectueux.

73. Tableau des échantillons à surveiller#

Le tableau contient : SampleID, groupe, signaux, nombre de signaux, score, reads, richesse et dominance.

Il ne contient que les échantillons détectés par au moins une règle IQR. Il dispose d’une recherche, de filtres de colonnes, d’un défilement et d’un export DataTables.

74. Tableau complet des échantillons#

Le tableau complet affiche SampleID, groupe, signaux, nombre de signaux, reads, richesse, dominance, part de zéros et statut.

Les outliers apparaissent en premier.

75. Ce qu’un outlier ne signifie pas#

Un outlier n’est pas automatiquement une erreur, un contaminant, un échantillon à supprimer, un échec de séquençage ou un mauvais contrôle.

Il peut correspondre à une réalité biologique, une matrice très hétérogène, un groupe expérimental différent, une forte dominance réelle, une faible biomasse ou un événement rare.

Toute décision doit être contextualisée avec les métadonnées, le protocole, les contrôles, les résultats de filtration et les visualisations.

77. Résumé des tables#

Les dimensions excluent la colonne d’identifiant ajoutée pour l’affichage.

78. OTU table affichée#

Description convertit la table dans une orientation standard : taxons en lignes et échantillons en colonnes.

Une colonne explicite ASV est ajoutée. Même si les unités sont des OTU ou ZOTU, la colonne reste nommée ASV.

78.1. Orientation originale#

L’export de Description ne conserve pas nécessairement l’orientation originale du phyloseq. Il exporte la version réorientée utilisée pour l’affichage.

78.2. Contenu#

Les valeurs ne sont pas modifiées. Elles peuvent rester entières, décimales, négatives, transformées ou manquantes.

79. Taxonomie affichée#

La taxonomie contient une colonne ASV et les rangs taxonomiques.

79.1. Noms de rangs#

Les noms de colonnes vides ou dupliqués sont remplacés pour l’affichage par des noms uniques.

Exemples :

Rang_sans_nom_1
Genus
Genus_1

Cette correction concerne la table affichée et exportée depuis Description. Elle ne renomme pas la tax_table dans le phyloseq.

80. Métadonnées affichées#

Les rownames de sample_data deviennent une colonne SampleID.

Si une colonne SampleID existe déjà dans la metadata, elle est renommée pour éviter la collision :

SampleID_meta
SampleID_meta_2

Le phyloseq original n’est pas modifié.

81. Fonctions des tableaux interactifs#

Les tables offrent :

  • filtres en haut des colonnes ;

82.1. Format#

82.3. Composant absent#

Si un composant est absent, le bouton peut produire un fichier CSV vide.

83. Complétude taxonomique#

Le tableau affiche pour chaque rang le pourcentage renseigné et le pourcentage manquant.

Il permet de distinguer les rangs presque complets, partiellement renseignés ou largement vides. Le rang le plus rempli est également affiché dans le résumé.

Cela permet de repérer les colonnes totalement vides, les variables presque constantes, les variables de groupe potentielles, les colonnes numériques devenues texte et les identifiants presque uniques.

85. Variables groupables#

Le nombre de variables groupables correspond aux colonnes qui répondent aux critères :

  • 2 à 15 modalités ;
  • non temporelles.

Cela ne garantit pas leur pertinence biologique. Une variable telle que Replicate_number = 1, 2, 3 peut être proposée alors qu’elle n’est pas forcément un groupe expérimental approprié.

86. Logs de filtration#

Description lit l’attribut :

attr(ps, "filtration_log")

Il recherche notamment removed_taxa et removed_samples.

86.1. ASV supprimées#

Le tableau peut contenir identifiant, abondance, prévalence, raison, paramètres et autres colonnes enregistrées par Filtration. Le contenu dépend de la version et de l’étape ayant créé le log.

86.2. Échantillons supprimés#

Le tableau peut contenir SampleID, profondeur, raison et autres informations enregistrées.

86.3. Absence d’identifiant explicite#

Si le tableau utilise ses rownames comme identifiants, Description ajoute une colonne ASV ou SampleID.

87. Export des logs#

Les logs des taxons et des échantillons sont combinés dans un même CSV.

Une colonne log_type est ajoutée, avec les valeurs removed_taxa ou removed_samples.

Les colonnes présentes dans un seul type de log sont ajoutées à l’autre avec des valeurs manquantes.

88. Portée des logs de filtration#

Le log représente l’information attachée à l’objet actuel.

Il ne garantit pas un historique exhaustif de toutes les anciennes versions, que le parent existe encore, que toutes les étapes externes sont documentées, que les modifications manuelles ont été enregistrées ou que les logs n’ont pas été écrasés.

89. Vue Projet#

La vue Projet travaille sur tous les datasets présents dans datasets().

Elle ne lit pas directement tous les projets enregistrés sur le disque. Elle compare uniquement les objets actuellement chargés en mémoire dans le projet ouvert.

90. Résumé global du projet#

Le résumé contient :

  • nombre de datasets chargés ;
  • nombre de datasets sélectionnés pour la comparaison ;
  • somme des échantillons ;
  • somme des abondances ;
  • sparsité moyenne.

91. Échantillons cumulés#

La valeur correspond à la somme du nombre d’échantillons de chaque dataset.

Elle ne correspond pas au nombre d’échantillons uniques. Si les mêmes échantillons existent dans plusieurs datasets, ils sont comptés plusieurs fois.

Exemple :

COI : 100 échantillons
16S : 100 mêmes échantillons
Total affiché : 200

92. Reads cumulés#

La valeur correspond à la somme des abondances de tous les datasets.

Elle n’est pertinente que si les datasets contiennent des valeurs comparables. Additionner des comptes bruts, des proportions et des données CLR n’a pas de sens commun.

93. Sparsité moyenne du projet#

La sparsité moyenne est la moyenne simple des sparsités des datasets.

Chaque dataset possède le même poids, quelle que soit sa taille. Un petit dataset de 10 × 10 et un grand dataset de 50 000 × 500 ont le même poids dans cette moyenne.

95. Datasets à comparer#

Le sélecteur multiple définit les datasets inclus dans les graphiques comparatifs.

Par défaut, tous les datasets sont sélectionnés, sauf si une sélection précédente a été restaurée depuis l’état d’interface du projet.

La sélection ne modifie pas le registre, ne change pas le dataset actif et ne filtre pas les objets. Elle agit uniquement sur les graphiques de comparaison.

96. Dataset de référence#

Le dataset de référence est utilisé uniquement dans le graphique Écart vs référence.

Il n’est pas utilisé dans la heatmap, le dotplot, les barplots absolus ou la comparaison de filtration.

96.1. Référence hors sélection#

Le sélecteur peut proposer un dataset qui n’est pas inclus dans les datasets comparés.

Dans ce cas, le graphique utilise silencieusement le premier dataset de la sélection comme référence de repli.

Pour éviter toute ambiguïté, inclure toujours le dataset de référence dans la sélection.

97. Métrique clé#

Les métriques disponibles sont :

  • ASV ;
  • échantillons ;
  • reads ;
  • richesse moyenne ;
  • sparsité.

Elle influence le texte de lecture synthétique et le graphique Écart vs référence.

98. Lecture synthétique du projet#

Le texte identifie le dataset possédant la valeur la plus élevée pour la métrique choisie.

Une valeur plus élevée ne signifie pas nécessairement une meilleure qualité.

  • Plus de reads peut refléter une meilleure profondeur ou un déséquilibre de séquençage.
  • Plus d’ASV peut refléter une diversité supérieure, du bruit ou une méthode différente.
  • Plus de sparsité signifie davantage de zéros, ce qui n’est pas nécessairement souhaitable.

99. Heatmap synthétique#

La heatmap compare :

  • ASV ;
  • échantillons ;
  • reads ;
  • richesse moyenne ;
  • sparsité.

99.1. Normalisation#

Chaque métrique est mise séparément à l’échelle entre 0 et 1 :

Valeur normalisée =
valeur - minimum
÷ maximum - minimum

99.2. Valeurs identiques#

Si tous les datasets ont la même valeur pour une métrique, la valeur normalisée est fixée à 0,5.

99.3. Interprétation#

La couleur indique la position relative d’un dataset pour une métrique.

Elle ne permet pas de comparer directement une valeur de reads, une valeur de sparsité et un nombre d’échantillons. Les unités sont différentes et ont été normalisées indépendamment.

Les valeurs brutes restent disponibles dans l’infobulle.

100. Dotplot comparatif#

Le dotplot utilise la même normalisation 0–1.

Chaque point représente un dataset, une métrique et sa position relative.

Il est utile pour voir rapidement le profil général de chaque objet. Il ne constitue pas un score global, une analyse multivariée ou un classement de qualité.

101. Écart versus référence#

Pour la métrique sélectionnée :

Écart (%) =
valeur du dataset - valeur de référence
÷ valeur de référence
× 100

Le dataset de référence n’est pas affiché comme barre, puisqu’il possède par définition un écart nul.

101.1. Référence nulle#

Le graphique n’est pas produit si la valeur de référence est nulle ou manquante.

101.2. Un seul dataset#

Il faut au moins un dataset supplémentaire en plus de la référence.

101.3. Interprétation selon la métrique#

Un écart positif signifie plus d’ASV, d’échantillons, de reads, de richesse ou de sparsité selon la métrique choisie.

Il ne signifie pas toujours une amélioration.

102. Comparaison de filtration#

Le graphique affiche le nombre d’ASV supprimées et le nombre d’échantillons supprimés, à partir de filtration_log.

102.1. Limite importante#

Les nombres sont absolus. Ils ne sont pas divisés par le nombre initial d’ASV, le nombre initial d’échantillons, le volume de reads ou la taille du dataset.

Supprimer 1 000 ASV dans un dataset de 100 000 ASV n’est pas équivalent à supprimer 1 000 ASV dans un dataset de 2 000 ASV.

102.2. Absence de log#

Un dataset sans log apparaît comme valeur manquante. L’absence de log ne signifie pas qu’aucune filtration n’a été réalisée.

103. Barplots comparatifs#

La vue Projet contient des barplots absolus pour :

  • nombre d’échantillons ;
  • nombre d’ASV ;
  • reads totaux ;
  • richesse moyenne ;
  • sparsité.

Ces graphiques ne réalisent aucune normalisation ni aucun test.

104. Comparabilité des datasets#

Deux datasets ne sont pas nécessairement comparables simplement parce qu’ils sont chargés dans le même projet.

Avant d’interpréter les graphiques, vérifier :

  • même technologie ;
  • même marqueur ;
  • même région ;
  • même pipeline ;
  • mêmes filtres ;
  • même base taxonomique ;
  • mêmes échantillons ;
  • même nature des abondances ;
  • même niveau de transformation ;
  • même définition des unités taxonomiques.

105. Comparaison de marqueurs différents#

Comparer COI, 16S et ITS peut être utile pour décrire leurs tailles respectives.

En revanche, il ne faut pas interpréter directement le nombre d’ASV, la richesse, le nombre de reads ou la sparsité comme des mesures biologiques équivalentes entre marqueurs.

Chaque marqueur possède une résolution, des amorces, des bases, des biais et des groupes biologiques différents.

106. Comparaison avant et après filtration#

La vue Projet est utile pour comparer un dataset brut à un dataset filtré.

Il faut néanmoins vérifier que le dataset filtré provient réellement du brut, que les mêmes échantillons sont comparés, que les abondances n’ont pas été transformées, que le log est présent et que le parent n’a pas été renommé ou supprimé.

107. Performance#

Description réalise plusieurs calculs en mémoire.

Les opérations potentiellement coûteuses sont :

  • somme de grandes matrices ;
  • calcul des métriques pour tous les datasets ;
  • conversion complète des tables ;
  • affichage d’une OTU table très large ;
  • calcul des séquences ;
  • raréfaction ;
  • création des graphiques Plotly ;
  • comparaison d’un grand nombre de datasets.

107.1. Initialisation paresseuse#

Le module est initialisé lorsque l’onglet Description est ouvert. Le premier affichage peut donc être plus lent.

107.2. Tables volumineuses#

Le défilement différé améliore l’affichage, mais la table complète est préparée en mémoire côté R.

107.3. Raréfaction#

Afficher toutes les courbes de centaines d’échantillons peut rendre le navigateur lent. Utiliser Top reads, Bottom reads ou Outliers pour limiter l’affichage.

108. Résolution des problèmes#

108.1. Aucun dataset n’apparaît#

Causes possibles : aucun dataset chargé, mauvais projet ouvert, import échoué ou session restaurée sans registre.

Correction : utiliser Input data, OpenMetaBar ou Datasets.

108.2. Le dataset affiché change dans les autres onglets#

Cause : le sélecteur Description est synchronisé avec le dataset actif global.

Correction : ce comportement est normal. Utiliser une sélection locale dans les modules qui le permettent.

108.3. Le projet est indiqué comme non sauvegardé après une simple consultation#

Cause possible : le dataset actif a été changé dans Description.

Correction : sauvegarder le projet si ce choix doit être conservé.

108.4. Les valeurs affichées comme reads sont décimales#

Cause : l’OTU table contient probablement des valeurs transformées ou normalisées.

Conséquence : les métriques de profondeur et la raréfaction ne doivent pas être interprétées comme des comptes bruts.

108.5. La richesse semble incohérente#

Causes possibles : abondances transformées, valeurs négatives, taxons non supprimés, différence de profondeur, zéros structuraux ou mauvaise orientation de l’objet.

La richesse compte uniquement les valeurs strictement supérieures à zéro.

108.6. La sparsité semble trop faible#

Cause possible : la matrice contient des NA, qui ne sont pas comptés comme zéros mais restent dans le dénominateur.

108.7. Aucune variable de groupement n’est proposée#

Causes possibles : absence de metadata, une seule modalité, plus de quinze modalités, variable de date ou valeurs uniquement manquantes.

Correction : vérifier la metadata dans Data Edition.

108.8. Une variable numérique apparaît comme groupe#

Cause : elle contient entre deux et quinze valeurs distinctes.

Correction : ne pas la sélectionner si une interprétation catégorielle n’est pas pertinente.

108.9. Les valeurs manquantes apparaissent comme un groupe NA#

Cause : Description convertit les valeurs manquantes en étiquette de groupe.

Correction : nettoyer ou compléter la metadata si nécessaire.

108.10. Le bouton Voir les logs ne semble rien faire#

Cause : il sélectionne le sous-onglet Logs mais ne déplie pas automatiquement la box.

Correction : descendre vers Tables et logs et ouvrir la section.

108.11. Les séquences sont indiquées absentes#

Causes possibles : aucune refseq, package Biostrings indisponible ou objet de séquences invalide.

108.12. Le GC semble étrange#

Causes possibles : bases ambiguës, séquences très courtes, plusieurs marqueurs, séquences non nucléotidiques ou nombreuses bases non ACGT.

108.13. Les noms de rang taxonomique ont changé#

Cause : Description rend les noms vides ou dupliqués uniques pour l’affichage. L’objet original n’est pas modifié.

108.14. Une colonne SampleID_meta apparaît#

Cause : la metadata contenait déjà une colonne nommée SampleID. Description réserve SampleID aux rownames.

108.15. Les courbes de raréfaction ne se calculent pas#

Causes possibles : vegan absent, OTU table absente, moins de deux échantillons positifs, moins de deux échantillons avec 50 reads, données non adaptées ou erreur dans les comptes.

108.16. Les courbes de raréfaction correspondent à l’ancien dataset#

Cause : le calcul n’a pas été relancé après un changement de dataset.

Correction : cliquer de nouveau sur Calculer les courbes.

108.17. Le nombre maximal de courbes n’est pas respecté#

Cause : le mode Tous les échantillons ignore actuellement cette limite.

Correction : choisir Top reads, Bottom reads ou Outliers.

108.18. La raréfaction agrégée d’un grand groupe est beaucoup plus haute#

Cause : les reads sont additionnés entre tous les échantillons du groupe.

Conséquence : ce n’est pas une moyenne par échantillon.

108.19. Aucun outlier n’est détecté#

Causes possibles : homogénéité réelle, moins de quatre échantillons, IQR nul, valeurs manquantes ou seuil global peu adapté aux groupes.

108.20. Un échantillon biologiquement normal est signalé#

Cause possible : la règle est appliquée globalement et non au sein de son groupe.

Correction : interpréter avec la metadata et le contexte expérimental.

108.21. Un échantillon très atypique n’est pas signalé#

Causes possibles : la métrique concernée n’est pas utilisée, IQR nul, peu d’échantillons, outlier sur la part de zéros uniquement ou transformation des données.

108.22. Le groupe a 30 % d’outliers et apparaît en rouge#

Cause : la couleur utilise un seuil visuel interne de 30 %.

Conséquence : ce n’est pas une p-value ni une preuve d’effet de groupe.

108.23. L’export OTU n’a pas l’orientation d’origine#

Cause : Description exporte toujours les taxons en lignes.

108.24. L’export CSV ne correspond pas au filtre visuel du tableau#

Cause : le bouton dédié exporte la table complète.

Alternative : utiliser le bouton CSV intégré au tableau pour un export lié à l’état de DataTables.

108.25. Le fichier CSV est vide#

Cause probable : le composant correspondant est absent.

108.26. Les logs sont absents#

Causes possibles : dataset jamais filtré dans BarCodeR, attribut supprimé, objet produit par un autre outil, ancienne version ou log non conservé.

108.27. La vue Projet compte deux fois les mêmes échantillons#

Cause : les nombres sont additionnés entre datasets, sans déduplication.

108.28. La heatmap donne des valeurs similaires malgré des ordres de grandeur différents#

Cause : chaque métrique est normalisée séparément entre 0 et 1.

108.29. Toute une colonne de heatmap vaut 0,5#

Cause : tous les datasets possèdent la même valeur pour cette métrique.

108.30. Le dataset de référence choisi n’est pas utilisé#

Cause possible : il n’est pas inclus dans la sélection des datasets à comparer.

Correction : ajouter le dataset de référence à la sélection.

108.31. Le graphique d’écart ne fonctionne pas#

Causes possibles : référence nulle, référence manquante, un seul dataset sélectionné ou métrique absente.

108.32. La comparaison de filtration semble injuste#

Cause : elle compare des nombres absolus et non des pourcentages.

Correction : rapporter les suppressions aux dimensions initiales avant de conclure.

108.33. La vue Projet est lente#

Causes possibles : nombreux datasets, matrices volumineuses, nombreuses séquences ou tables très larges.

Correction : retirer temporairement certains datasets, limiter la sélection comparative, éviter d’ouvrir les grandes tables inutilement ou utiliser des datasets filtrés.

109. Checklist à l’ouverture d’un dataset#

  • Vérifier le nom du dataset sélectionné.
  • Vérifier le nombre d’échantillons.
  • Vérifier le nombre de taxons.
  • Vérifier le total des abondances.
  • Vérifier la nature brute ou transformée de l’OTU table.
  • Vérifier la présence de la taxonomie.
  • Vérifier la présence des métadonnées.
  • Vérifier la présence des séquences.
  • Vérifier la présence des logs.
  • Lire les alertes de sparsité et de profondeur.

110. Checklist avant une analyse par groupe#

  • Choisir une variable de groupement biologiquement pertinente.
  • Vérifier ses modalités.
  • Vérifier les valeurs manquantes.
  • Vérifier les tailles des groupes.
  • Vérifier que la variable n’est pas quantitative par erreur.
  • Examiner les profondeurs par groupe.
  • Examiner les richesses par groupe.
  • Examiner les outliers.
  • Ne pas confondre description et test statistique.

111. Checklist avant une raréfaction#

  • Vérifier que les abondances sont des comptes bruts.
  • Vérifier qu’elles sont entières et non négatives.
  • Vérifier qu’au moins deux échantillons ont 50 reads.
  • Choisir le bon dataset.
  • Choisir le bon groupement.
  • Cliquer sur Calculer.
  • Recalculer après tout changement de dataset.
  • Distinguer courbes individuelles et pools de groupes.
  • Ne pas interpréter un plateau comme une validation définitive.

112. Checklist avant d’exclure un outlier#

  • Vérifier les trois métriques responsables.
  • Vérifier la metadata.
  • Vérifier le groupe expérimental.
  • Vérifier les contrôles positifs et négatifs.
  • Vérifier les logs.
  • Vérifier la profondeur.
  • Vérifier la dominance taxonomique.
  • Vérifier si l’écart est biologiquement attendu.
  • Ne pas supprimer depuis Description.
  • Utiliser Filtration uniquement après justification.

113. Checklist avant une comparaison de datasets#

  • Même type d’abondances.
  • Même marqueur ou objectif de comparaison explicite.
  • Même technologie ou biais connus.
  • Même définition des unités.
  • Même niveau de filtration.
  • Même ensemble d’échantillons ou différences documentées.
  • Dataset de référence inclus dans la sélection.
  • Comprendre que les sommes ne sont pas dédupliquées.
  • Comprendre la normalisation 0–1.
  • Ne pas interpréter « plus élevé » comme « meilleur ».

114. Limites actuelles à connaître#

114.1. Les abondances ne sont pas validées comme comptes bruts#

Toutes les métriques peuvent être trompeuses avec des données transformées.

114.2. Le nombre d’ASV est un terme générique#

Le module ne connaît pas la méthode de génération des unités.

114.3. L’arbre n’est pas résumé#

La présence et la cohérence du phy_tree ne sont pas affichées.

114.4. Les séquences ne sont pas alignées explicitement aux taxons#

Le module décrit les séquences présentes sans contrôle exhaustif de correspondance.

114.5. La sparsité et la complétude utilisent des résumés simples#

Elles peuvent masquer des hétérogénéités importantes.

114.6. Les diagnostics utilisent des seuils internes#

Les seuils ne sont pas des standards universels.

114.7. Les outliers sont détectés globalement#

Ils ne sont pas calculés à l’intérieur des groupes.

114.8. La part de zéros n’est pas un signal d’outlier#

Elle est affichée, mais n’entre pas dans le statut.

114.9. La raréfaction doit être relancée manuellement#

Un changement de dataset ne réinitialise pas automatiquement le résultat.

114.10. La limite de courbes n’agit pas sur le mode Tous#

Un grand dataset peut produire un graphique très lourd.

114.11. Les courbes agrégées utilisent des pools#

Elles ne représentent pas des moyennes d’échantillons.

114.12. Les tables sont préparées intégralement en mémoire#

L’affichage de très grands objets peut être coûteux.

114.13. Les exports Description réorientent certaines tables#

L’OTU table est exportée avec les taxons en lignes.

114.14. Les noms de colonnes peuvent être ajustés pour l’affichage#

Le phyloseq original reste inchangé.

114.15. La vue Projet additionne les dimensions#

Elle ne déduplique ni les échantillons ni les taxons.

114.16. La heatmap compare des positions relatives#

Elle ne compare pas des unités communes.

114.17. La comparaison de filtration utilise des nombres absolus#

Elle ne corrige pas pour la taille initiale.

114.18. Aucun test statistique n’est réalisé#

Les différences visualisées restent descriptives.

115. Parcours recommandé#

  1. Ouvrir Description après l’import.
  2. Vérifier le dataset actif.
  3. Examiner les dimensions et les composants.
  4. Lire les alertes de structure.
  5. Vérifier la nature des abondances.
  6. Examiner reads versus richesse.
  7. Examiner les distributions d’abondance.
  8. Examiner la richesse.
  9. Examiner les séquences si disponibles.
  10. Choisir une variable de groupement pertinente.
  11. Inspecter les outliers.
  12. Lancer la raréfaction si les données sont des comptes.
  13. Examiner les tables.
  14. Examiner la complétude.
  15. Examiner les logs.
  16. Comparer les datasets dans la vue Projet.
  17. Passer ensuite vers Data Edition ou Filtration si une action est nécessaire.
