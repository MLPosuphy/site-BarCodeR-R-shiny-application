Description — Methodological guides

1. General overview#

The Description tab is used to inspect the structure and content of the phyloseq objects available in BarCodeR before moving to editing, filtering, or statistical analysis.

It is organized into two complementary views.

Dataset view#

This view inspects one phyloseq object at a time and lets you:

  • check its dimensions;
  • check which components are available;
  • review descriptive metrics;
  • visualize abundance and observed richness;
  • inspect reference sequences;
  • calculate rarefaction curves;
  • identify atypical samples;
  • view and export tables;
  • inspect filtration logs;
  • review OpenMetaBar provenance.

Project view#

This view compares several datasets currently held in memory and lets you:

  • obtain a summary of all loaded objects;
  • select the datasets to compare;
  • compare their dimensions;
  • compare sequencing depth and richness;
  • compare sparsity;
  • examine differences relative to a reference dataset;
  • compare removals documented in filtration logs.

2. Purpose of the tab#

Description is primarily intended to help you understand the data, verify an import, identify obvious anomalies, prepare later methodological choices, and compare the general structure of several datasets.

Need Appropriate tab
Modify tables Data Edition
Remove samples or taxa Filtration
Rename or delete a dataset Datasets
Run a statistical analysis Analysis
Start a pipeline from FASTQ files OpenMetaBar

3. Effect of the tab on the data#

Description does not modify the OTU table, taxonomy, metadata, sequences, tree, abundances, identifiers, or logs. Plots and tables are built from the object currently held in memory.

3.1. Exception: the active dataset#

The main Dataset-view selector is synchronized with the global active dataset. Changing the dataset in Description:

  • updates active_ds();
  • changes the active dataset in the rest of BarCodeR;
  • may mark the project as having unsaved changes.

The phyloseq content is not changed, but the global working context is.

4. Required components#

Most Description functions require at least an otu_table.

The following components are optional:

  • sample_data;
  • tax_table;
  • refseq;
  • phylogenetic tree;
  • provenance attributes;
  • filtration logs.

A missing component reduces the available information but does not necessarily prevent the tab from opening.

5. Important assumption about abundance values#

The module labels OTU-table values as reads, but it does not verify that they are raw, integer, untransformed, non-negative counts.

If the phyloseq object contains relative abundances, CLR- or log-transformed values, normalized values, decimals, or negative values, the metrics displayed as “reads” no longer represent raw sequencing depth.

This distinction is essential when interpreting totals, richness, dominance, rarefaction curves, and comparisons between datasets.

6. Interface organization#

The tab has two main controls:

Dataset
Project

Dataset view#

It contains:

  1. Dataset controls.
  2. OpenMetaBar provenance.
  3. Quick dataset reading.
  4. Interactive visualizations.
  5. Tables and logs.

Project view#

It contains:

  1. Global project overview.
  2. Interactive comparisons.

7. Selecting the dataset#

The Select a dataset field contains all datasets currently available in the session.

7.1. Global synchronization#

The selection follows the global active dataset. If the active dataset is changed in Datasets, in the sidebar, or in another global selector, Description follows that value. Conversely, changing the selection in Description changes the application's active dataset.

7.2. Fallback value#

If no valid active dataset is defined, Description uses:

  1. the previously selected dataset if it still exists;
  2. otherwise the first dataset in the list.

7.3. Changing datasets#

When the dataset changes, metrics, plots, tables, grouping options, provenance, and outliers are recomputed.

Rarefaction warning: rarefaction is not automatically recomputed when the dataset changes. Click Calculate curves again.

8. Grouping variable#

The Grouping variable — samples field colors or separates samples using a column from sample_data.

8.1. Variables offered#

A column is offered when it contains at least two and at most fifteen distinct non-missing values. Date, POSIXct, and POSIXt columns are excluded.

8.2. Numeric columns#

A numeric column may be offered if it contains between two and fifteen distinct values. It is then treated as categorical.

For example:

Temperature = 10, 15, 20

is treated as three groups rather than as a continuous quantitative variable.

8.3. Missing values#

Missing values are grouped under the label NA. A literal string "NA" and a true missing value may therefore be difficult to distinguish visually.

8.4. No grouping#

When No grouping is selected, all samples are assigned to a single group named All.

8.5. Effects of grouping#

Grouping affects:

  • color in the reads-versus-richness plot;
  • group violin plots;
  • cumulative curves by group;
  • rarefaction colors;
  • pooled-group rarefaction;
  • outlier context;
  • outlier concentration by group.

It does not modify the data.

9. Grouping does not change outlier detection#

Outliers are computed across all samples in the dataset. They are not recalculated separately within each group.

The grouping variable only contextualizes outliers, shows where they are concentrated, and colors the visualizations.

A sample can therefore be typical within its own group but flagged as an outlier relative to the full dataset.

10. “View logs” button#

The View logs button selects the Filtration logs sub-tab in the Tables and logs section.

In the current implementation, it does not automatically scroll the page and may not expand the box if it is collapsed. After clicking, you may need to scroll to Tables and logs, expand the box, and open the already-selected sub-tab.

11. Dataset header#

The header displays:

  • dataset name;
  • number of samples;
  • number of taxa;
  • total abundance;
  • available components.

Example:

130 samples • 2,450 ASVs/OTUs • 7,779,736 reads

12. Component badges#

Badges indicate the presence of an OTU table, taxonomy, metadata, reference sequences, and filtration logs.

12.1. OTU#

Indicates that an otu_table was detected.

12.2. Taxonomy#

Indicates that a tax_table was detected. It does not guarantee that all ASVs are annotated, all ranks are complete, or the taxonomy is biologically correct.

12.3. Metadata#

Indicates that sample_data was detected. It does not guarantee that every variable is usable, that types are correct, or that there are no missing values.

12.4. RefSeq#

Indicates that reference sequences are available and that the Biostrings package can read them. If Biostrings is unavailable, Description may report sequences as absent even when the object contains refseq.

12.5. Logs#

Indicates the presence of the filtration_log attribute. It does not guarantee that the log actually contains removed ASV or sample rows.

12.6. Phylogenetic tree#

The current module has no dedicated tree badge. The absence of a badge therefore says nothing about whether phy_tree is present.

13. OTU-table orientation#

Description temporarily orients the matrix for calculations with taxa in rows and samples in columns.

If the original object stores taxa in columns, the matrix is transposed in memory for descriptive calculations. The original phyloseq object is not transposed or modified.

14. Metric: number of taxa#

The displayed number is the number of rows in the reoriented matrix, equivalent to phyloseq::ntaxa(ps).

The interface uses the term ASV, but the units may be ASVs, OTUs, ZOTUs, grouped species, or other units. Description does not verify how the taxa were generated.

15. Metric: number of samples#

The value is the number of columns in the reoriented matrix, equivalent to phyloseq::nsamples(ps).

16. Metric: total reads#

The total is the sum of all OTU-table cells, ignoring missing values.

It can only be interpreted as total reads if the matrix contains raw counts.

17. Metric: reads per sample#

For each sample:

Reads = sum of all taxon abundances

The module then calculates minimum, maximum, mean, median, and standard deviation. The median is shown in the main cards.

18. Metric: observed richness#

For each sample:

Richness = number of taxa with abundance strictly greater than zero

This is raw observed richness. It is not Chao1, ACE, Shannon, Simpson, or richness corrected for depth.

Samples with different depths may therefore have richness values that are not directly comparable.

19. Metric: dominance of the most abundant taxon#

For each sample:

Dominance (%) =
maximum taxon abundance
÷ total sample abundance
× 100

High dominance may reflect genuine community dominance, preferential amplification, a contaminant, compositional imbalance, low depth, or a particular sample. It cannot by itself establish poor quality.

20. Metric: zero proportion per sample#

For each sample:

Zeros (%) =
number of taxa with abundance equal to zero
÷ total number of taxa
× 100

This describes the proportion of taxa absent from the sample. It is not used in the current outlier detection.

21. Metric: global sparsity#

Sparsity is:

number of zero cells
÷ total number of OTU-table cells
× 100

21.1. Interpretation#

High sparsity means that many taxon–sample combinations have zero abundance. This is common in metabarcoding because of diversity, specialization, spatial variation, detection limits, sequencing depth, and bioinformatic processing.

21.2. Display thresholds#

Sparsity Message
≥ 97% Very high sparsity
90 to <97% High sparsity
<90% Controlled sparsity

These are internal display rules, not universal scientific standards.

21.3. Presence of NA#

The denominator uses the full matrix size. NA values are not counted as zeros but remain in the total number of cells, so sparsity may be slightly underestimated when missing values are present.

22. Depth variability#

Description calculates a coefficient of variation:

CV (%) =
standard deviation of reads per sample
÷ mean reads per sample
× 100

A “very heterogeneous depth” message is displayed when CV ≥ 100%.

This is an internal descriptive threshold, not a universal limit. A CV below 100% does not guarantee sufficiently homogeneous depth for every analysis.

23. Taxonomic completeness#

For each taxonomic rank:

Completeness (%) =
number of non-missing, non-empty values
÷ total number of ASVs
× 100

The displayed mean completeness is the unweighted mean of completeness percentages across all ranks.

23.1. Consequence#

A dataset with several highly incomplete ranks and a few complete ranks may have an intermediate average that hides those differences. Review the detailed table.

23.2. Space-only strings#

A string containing only spaces may be considered filled if it was not cleaned before import.

24. Missing metadata values#

For each variable:

Missing (%) =
number of NA or empty strings
÷ number of samples
× 100

The displayed mean is the unweighted mean of missing-value rates across all variables.

24.1. The value "NA"#

The character string "NA" is not a true missing value and may be counted as a level.

24.2. Spaces#

A string containing only spaces may be considered non-missing.

24.3. Displayed type#

The completeness table displays the first R class of the column: character, numeric, factor, Date, and so on. This can reveal columns that became character during import.

25. Sequence lengths#

When refseq and Biostrings are available, Description calculates minimum, maximum, mean, median, and standard deviation of sequence length in base pairs.

25.1. Interpretation#

A multimodal or very wide distribution may indicate multiple amplified regions, multiple markers, truncated sequences, indels, nonspecific products, poorly filtered sequences, or genuine biological variation.

Expected length must be interpreted according to the marker, primers, whether primers are still present, and the pipeline used.

26. GC percentage#

GC percentage is calculated from A, C, G, and T bases:

GC (%) =
number of G + number of C
÷ total number of A, C, G, and T
× 100

Ambiguous bases are excluded from the ACGT denominator. A sequence with many ambiguous characters may therefore have a GC value based only on its unambiguous portion.

27. Sequence names#

Description uses the names stored in refseq. If sequences lack valid names, generic display identifiers are generated:

ASV_1
ASV_2
ASV_3

The module does not explicitly verify that every sequence name corresponds to a taxon in the OTU table.

28. Automatic interpretation message#

The summary card builds a short text from median reads, median richness, sparsity, and component availability.

This is descriptive assistance. It is not scientific validation, definitive quality control, a filtering decision, or an automatic statistical recommendation.

29. Quick dataset reading#

The section covers four areas.

29.1. Structure#

Summary of median reads, median richness, and sparsity.

29.2. Available content#

Presence or absence of the OTU table, taxonomy, metadata, and sequences.

29.3. Sequences#

When available: median length and median GC.

29.4. Filtration#

When filtration_log exists: number of removed ASVs and removed samples.

30. Automatic diagnostics#

The diagnostic grid may flag:

  • high sparsity;
  • heterogeneous depth;
  • missing metadata;
  • missing taxonomy;
  • missing sequences;
  • presence of a filtration history.

These alerts do not change anything and should not be used alone to exclude data.

31. OpenMetaBar provenance#

The OpenMetaBar provenance box reads attr(ps, "openmetabar_run"). It does not contact the cluster. It is a snapshot stored in the phyloseq object when it was imported.

31.1. Run summary#

May include run ID, label, launch date, technology, marker, engine, database type and path, design file, sample count, and FASTQ count.

31.2. Demultiplexing#

May include MiniBar activation, method, tolerances, and other stored options.

31.3. Filters#

May include orientation, quality, length, coding filter, and genetic code.

31.4. LotuS3#

May include platform, amplicon type, clustering, assignment, and other stored settings.

31.5. LCA#

May include coverage, identity thresholds, agreement fraction, and assignment mode.

31.6. IDMABIO#

Present only when that route was used.

31.7. NextITS#

Present only when that route was used.

31.8. Cluster environment#

May include partition, memory, CPUs, modules, and remote paths.

31.9. FASTQ files#

The file list may be displayed. Paths represent recorded provenance, not necessarily files that are still accessible.

31.10. Sample renaming#

Provenance may retain original name, corrected name, date, and reason.

31.11. Missing provenance#

Missing provenance does not prove that the dataset was never produced by OpenMetaBar. The attribute may have been removed, lost during conversion, overwritten, absent from an older version, or not retained in an external export.

32. Interactive visualizations — Overview#

The overview contains:

  1. Reads versus richness.
  2. Sample detail card.
  3. Top 15 samples.
  4. Top 15 taxa.
  5. Cumulative sample contribution.
  6. Cumulative taxon contribution.

33. Reads versus richness#

Each point represents one sample.

X = total abundance
Y = observed richness

Color represents the selected group, and shape represents status: circle for standard, diamond for outlier.

33.1. Interpretation#

The plot helps identify relationships between depth and richness, shallow samples, rich but shallow samples, points far from the main cloud, and differences between groups.

33.2. Limitation#

A positive reads–richness relationship does not prove that depth is the only cause of biological differences.

33.3. Interaction#

Clicking a point updates the sample detail card.

34. Sample detail card#

The card displays SampleID, reads, richness, dominance, zero proportion, status, and up to six available metadata values.

34.1. Initial sample#

Before any click, the card displays the first detected outlier if one exists; otherwise it displays the first sample in the dataset.

34.2. Displayed metadata#

Columns that are completely missing for the selected sample are excluded. Only the first six usable columns are shown, so the card is not exhaustive.

35. Top 15 samples#

The plot ranks samples by decreasing total abundance and displays at most fifteen. Clicking a bar updates the sample card.

35.1. Limitation#

The deepest samples are not necessarily the best, richest, most representative, or most reliable.

36. Top 15 taxa#

The plot ranks taxa by total abundance across all samples. The tooltip also shows the number and percentage of samples in which each taxon is present.

36.1. Prevalence#

Prevalence = number of samples where abundance > 0

Prevalence (%) =
prevalence
÷ total number of samples
× 100

36.2. Limitation#

The plot uses the taxon identifier rather than the taxonomic annotation. An ASV that is highly abundant in a single sample may rank first despite low prevalence.

37. Cumulative contribution of samples#

Samples are ranked by decreasing abundance. The curve shows the cumulative proportion of abundance explained by the leading samples.

A steep initial increase indicates that sequencing depth is concentrated in a small number of samples.

38. Cumulative contribution of taxa#

Taxa are ranked by decreasing total abundance. The curve shows the cumulative proportion of abundance explained by dominant taxa.

It does not account for taxonomy, prevalence, grouping, or biological rarity.

39. Abundance tab#

It includes:

  • reads histogram;
  • reads violin plot by group;
  • cumulative reads contribution by group.

40. Reads histogram#

The histogram describes the distribution of total abundance per sample. It helps reveal skewness, shallow or very deep samples, and multiple depth populations.

The number of bins is determined automatically by Plotly.

41. Reads by group#

The violin plot is available when the grouping variable contains several groups. It displays the distribution, a boxplot, the mean, and individual points.

41.1. No grouping#

If no grouping is selected, a message indicates that no qualitative grouping variable is available.

41.2. Interpretation#

The plot is descriptive. It performs no statistical test, normalization, adjustment for group sizes, or adjustment for covariates.

42. Cumulative reads contribution by group#

Within each group, samples are sorted by decreasing abundance and the cumulative proportion is calculated inside that group. Each curve therefore reaches 100% for its own group.

42.1. Consequence#

The curves show internal concentration of depth within each group. They do not show what proportion of all project reads belongs to each group.

A very small group and a very large group both reach 100%.

43. Richness tab#

It includes:

  • richness histogram;
  • richness by group;
  • richness versus dominance.

44. Richness histogram#

It displays the distribution of the number of observed taxa per sample.

This richness is not corrected for depth. A deeper sample may mechanically contain more observed taxa.

45. Richness by group#

The violin plot compares observed richness between groups. Like the reads plot, it is descriptive and performs no statistical test.

46. Richness versus dominance#

X = observed richness
Y = dominance of the most abundant taxon

The plot can distinguish rich and even communities, rich but dominated communities, poor and dominated communities, or atypical profiles.

46.1. This is not an evenness index#

Maximum-taxon dominance can be used as a simple proxy, but it is not Pielou, Shannon, Simpson, or a complete evenness measure.

Two communities with the same maximum dominance can have very different distributions among the remaining taxa.

47. Sequences tab#

It includes:

  • sequence-length histogram;
  • GC histogram;
  • length versus GC relationship.

These plots require refseq and the Biostrings package.

48. Length versus GC#

Each point represents a sequence. The plot may reveal groups with different lengths or composition, very short or long sequences, atypical GC values, or a mixture of markers.

It cannot by itself determine whether a sequence is a contaminant or is incorrect.

49. Rarefaction curves#

The Rarefaction sub-tab starts a separate calculation. It is not computed automatically when the tab opens.

Click Calculate curves.

50. Rarefaction method used#

The module uses:

vegan::rarefy()

This function calculates the analytical expected number of observed taxa at a specified depth.

It is not repeated random subsampling, does not create a new phyloseq object, does not call rarefy_even_depth(), does not replace abundances, and does not save a normalization.

The original data remain unchanged.

51. Rarefaction calculation requirements#

The calculation requires:

  • the vegan package;
  • an OTU table;
  • at least two samples with positive abundance;
  • at least two samples with at least 50 reads.

Samples with fewer than 50 reads are excluded.

51.1. The 50-read threshold#

The threshold is hard-coded and cannot currently be changed in the interface.

It is an internal practical rule, not a universal standard.

52. Expected data type for rarefaction#

vegan::rarefy() is designed for counts.

Rarefaction is not appropriate for:

  • relative abundances;
  • CLR data;
  • negative data;
  • continuous transformations;
  • non-integer values.

The module does not explicitly block every such situation. Verify the nature of the OTU table before calculating curves.

53. Calculated depths#

The module generates up to about 80 depths distributed between 1 and the maximum observed depth.

For each sample, only depths less than or equal to its total are retained. Depths are rounded and deduplicated.

54. Individual curves#

The Individual curves colored by group mode displays one line per sample. Color represents the group.

The tooltip includes:

  • SampleID;
  • group;
  • total reads;
  • rarefied depth;
  • expected richness;
  • observed richness;
  • outlier status.

55. Subsetting individual curves#

Options are:

  • All samples;
  • Top reads;
  • Bottom reads;
  • Outliers.

55.1. All samples#

All eligible curves are displayed.

In the current implementation, the Maximum number of curves field is not applied in this mode. A dataset with many samples can therefore produce a heavy plot.

55.2. Top reads#

Keeps the deepest samples, up to the selected limit.

55.3. Bottom reads#

Keeps the shallowest samples among those with at least 50 reads.

55.4. Outliers#

Keeps samples flagged as outliers by the IQR rule.

If there are no outliers, the plot may remain empty after calculation.

56. Maximum number of curves#

The value is limited between 2 and 200.

It applies to Top reads, Bottom reads, and Outliers, but currently not to All samples.

57. Curves aggregated by group#

The Curves aggregated by group mode sums abundance across all samples in each group. One curve is then calculated for the pooled community.

57.1. What the curve represents#

It represents expected richness in the group's pooled reads.

It does not represent:

  • the mean of individual curves;
  • mean richness per sample;
  • a mean with a confidence interval;
  • a comparison adjusted for sample count.

57.2. Effect of group size#

A group with more samples or more reads has a larger pool and may reach higher richness.

Interpret pooled curves together with the number of samples and total reads in each group. These values are shown in tooltips.

57.3. Without grouping#

If no grouping is selected, all samples are pooled into a single curve named All.

58. Display legend#

The legend is disabled by default. With many groups, enabling it can reduce plot readability.

For individual curves, only one legend entry is shown per group even when several samples share the same color.

59. Recalculation is required#

The rarefaction result belongs to the dataset that was active when the button was clicked.

Changing the dataset does not automatically recalculate it. Click Calculate curves again.

59.1. Changing the grouping variable#

Changing the grouping variable after calculation may update colors or aggregation using the already-computed result.

59.2. Risk of a stale result#

After changing datasets without recalculating, the stored result may still correspond to the previous dataset.

Always recalculate rarefaction after changing datasets.

60. Interpreting rarefaction curves#

A flattening curve suggests that adding reads progressively reveals fewer new taxa.

A curve that is still strongly increasing suggests that additional depth might reveal more taxa.

However, a lack of plateau does not necessarily prove poor quality, insufficient sequencing, or experimental failure. It may also reflect an extremely diverse community, many rare taxa, residual noise, sequencing errors, or strong biological heterogeneity.

61. Limitations of the displayed rarefaction#

The plot does not provide:

  • confidence intervals;
  • means over repeated random subsampling;
  • extrapolation;
  • Good's coverage;
  • Chao1;
  • statistical comparison of curves;
  • an automatic saturation threshold.

It is a descriptive tool.

62. Outlier detection#

Detection is based on three metrics:

  1. depth;
  2. richness;
  3. dominance.

Zero proportion is not used for flagging.

63. IQR rule#

For each metric, Description calculates:

Q1 = first quartile
Q3 = third quartile
IQR = Q3 - Q1

Limits:

Lower limit = Q1 - 1.5 × IQR
Upper limit = Q3 + 1.5 × IQR

A value outside these limits is flagged as an outlier. This is the conventional Tukey boxplot-whisker rule.

64. High and low outliers#

The rule applies to both tails.

A sample may be flagged for very low or very high depth, very low or very high richness, or very low or very high dominance.

Although some interface wording emphasizes excessive dominance, the actual calculation also detects exceptionally low dominance.

65. Minimum conditions for the IQR rule#

No outlier is detected for a metric when:

  • fewer than four values are available;
  • all values are missing;
  • the IQR is zero.

No detected outlier may therefore mean true homogeneity, too few samples, no variability, or an unusable signal.

66. Sample status#

A sample is labelled Outlier when it is atypical for at least one of the three metrics. Otherwise it is labelled Standard.

The status is descriptive. No sample is removed automatically.

67. Number of signals#

The number of signals is the number of atypical metrics among depth, richness, and dominance.

Possible values:

0, 1, 2, or 3

A sample flagged on three signals is prioritized before a sample flagged on one.

68. Outlier score#

For each metric, the amount beyond the limit is expressed in IQR units.

Conceptual example:

Depth score =
distance beyond the limit
÷ IQR

The global score is the sum of depth, richness, and dominance scores. Standard samples receive zero.

68.1. Interpretation#

A higher score indicates a value farther beyond the IQR limits.

It is not a probability, p-value, universal quality metric, or deletion threshold.

69. Outlier priority order#

Outliers are sorted by:

  1. number of signals;
  2. global score;
  3. number of reads.

The first becomes the spotlight sample.

70. Outlier summary#

The section displays:

  • total number of outliers;
  • percentage of affected samples;
  • number of depth outliers;
  • number of richness outliers;
  • number of dominance outliers;
  • most frequent signal;
  • most affected group, when grouping is active.

71. Outlier concentration by group#

For each group:

Outlier percentage =
number of outliers in the group
÷ total samples in the group
× 100

The four most affected groups are displayed.

71.1. Color thresholds#

Percentage Visual level
≥ 30% Danger
15 to <30% Warning
<15% Low

These are visual conventions only, not validated statistical thresholds.

72. Global detection and group interpretation#

Group concentration must be interpreted carefully: outlier thresholds are calculated globally, and the percentage is then calculated within each group.

A group that is naturally different from the rest of the dataset may contain many outliers without containing technically defective samples.

73. Samples-to-watch table#

The table contains SampleID, group, signals, signal count, score, reads, richness, and dominance.

It includes only samples detected by at least one IQR rule. It supports search, column filters, scrolling, and DataTables export.

74. Complete sample table#

The complete table displays SampleID, group, signals, signal count, reads, richness, dominance, zero proportion, and status.

Outliers appear first.

75. What an outlier does not mean#

An outlier is not automatically an error, contaminant, sample to remove, sequencing failure, or bad control.

It may represent genuine biology, a highly heterogeneous matrix, a different experimental group, true strong dominance, low biomass, or a rare event.

Any decision must be contextualized using metadata, protocol, controls, filtration results, and visualizations.

76. Tables and logs#

The box is initially collapsed. It contains:

  • OTU table;
  • Taxonomy;
  • Metadata;
  • Completeness;
  • Filtration logs.

77. Table summary#

Cards show:

  • OTU-table dimensions;
  • taxonomy dimensions;
  • metadata dimensions;
  • number of exportable log rows.

Dimensions exclude the identifier column added for display.

78. Displayed OTU table#

Description converts the table to a standard orientation with taxa in rows and samples in columns.

An explicit ASV column is added. Even when the units are OTUs or ZOTUs, the column is still named ASV.

78.1. Original orientation#

Description's export does not necessarily preserve the original phyloseq orientation. It exports the reoriented version used for display.

78.2. Content#

Values are not changed. They may remain integer, decimal, negative, transformed, or missing.

79. Displayed taxonomy#

The taxonomy table contains an ASV column and the taxonomic ranks.

79.1. Rank names#

Empty or duplicated column names are replaced with unique names for display.

Examples:

Unnamed_rank_1
Genus
Genus_1

This only affects the table displayed and exported from Description. The tax_table in the phyloseq object is not renamed.

80. Displayed metadata#

The row names of sample_data become a SampleID column.

If the metadata already contains a SampleID column, it is renamed to avoid collision:

SampleID_meta
SampleID_meta_2

The original phyloseq object is not modified.

81. Interactive-table features#

Tables provide:

  • filters above columns;
  • search;
  • vertical scrolling;
  • horizontal scrolling;
  • a fixed first column;
  • pagination;
  • Copy button;
  • CSV button.

For large matrices, the complete data are still prepared in R memory before display.

82. Dedicated CSV export#

Each table has a dedicated export button.

Files:

<dataset>_otu_table.csv
<dataset>_tax_table.csv
<dataset>_metadata.csv
<dataset>_filtration_logs.csv

82.1. Format#

Files are produced with write.csv(): comma separator, row names excluded, identifiers included as an explicit column, and standard R representation of missing values.

82.2. Visual filters#

The dedicated export contains the full calculated table. It is not restricted to currently visible or filtered rows in the interactive table.

82.3. Missing component#

If a component is absent, the button may produce an empty CSV file.

83. Taxonomic completeness#

For each rank, the table displays the filled percentage and missing percentage.

It helps distinguish nearly complete, partially filled, and largely empty ranks. The most complete rank is also shown in the summary.

84. Metadata completeness#

For each variable, the table displays:

  • R type;
  • missing percentage;
  • number of unique values.

This helps identify completely empty columns, almost constant variables, potential grouping variables, numeric columns converted to text, and nearly unique identifiers.

85. Groupable variables#

The number of groupable variables is the number of columns meeting these criteria:

  • 2 to 15 levels;
  • non-temporal.

This does not guarantee biological relevance. A variable such as Replicate_number = 1, 2, 3 may be offered even though it is not necessarily an appropriate experimental group.

86. Filtration logs#

Description reads:

attr(ps, "filtration_log")

It looks in particular for removed_taxa and removed_samples.

86.1. Removed ASVs#

The table may contain identifier, abundance, prevalence, reason, parameters, and other columns stored by Filtration. Content depends on the version and step that created the log.

86.2. Removed samples#

The table may contain SampleID, depth, reason, and other stored information.

86.3. No explicit identifier#

If row names are used as identifiers, Description adds an ASV or SampleID column.

87. Log export#

Taxon and sample logs are combined into one CSV.

A log_type column is added with values removed_taxa or removed_samples.

Columns present in only one log type are added to the other with missing values.

88. Scope of filtration logs#

The log represents information attached to the current object.

It does not guarantee a complete history of all earlier versions, that the parent still exists, that every external step was documented, that manual edits were logged, or that logs were never overwritten.

89. Project view#

Project view works with all datasets currently present in datasets().

It does not directly read every project saved on disk. It compares only the objects currently loaded into memory in the open project.

90. Global project summary#

The summary contains:

  • number of loaded datasets;
  • number selected for comparison;
  • summed sample count;
  • summed abundance;
  • mean sparsity.

91. Cumulative sample count#

The value is the sum of the sample count in each dataset.

It is not the number of unique samples. If the same samples exist in several datasets, they are counted repeatedly.

Example:

COI: 100 samples
16S: the same 100 samples
Displayed total: 200

92. Cumulative reads#

The value is the sum of abundance across all datasets.

It is meaningful only when the datasets contain comparable values. Adding raw counts, proportions, and CLR data has no common interpretation.

93. Mean project sparsity#

Mean sparsity is the simple mean of dataset sparsities.

Each dataset has the same weight regardless of its dimensions. A 10 × 10 dataset and a 50,000 × 500 dataset contribute equally to this mean.

94. Project summary table#

The table includes, among other fields:

  • Dataset;
  • ASVs;
  • samples;
  • total reads;
  • mean and median reads;
  • mean richness;
  • sparsity;
  • taxonomic completeness;
  • missing metadata;
  • component presence;
  • log presence;
  • number of removed ASVs;
  • number of removed samples;
  • selection status for plots.

95. Datasets to compare#

The multiple selector defines which datasets are included in comparison plots.

By default, all datasets are selected unless a previous selection was restored from the project's UI state.

The selection does not modify the registry, change the active dataset, or filter objects. It only affects comparison plots.

96. Reference dataset#

The reference dataset is used only in the Difference versus reference plot.

It is not used in the heatmap, dotplot, absolute barplots, or filtration comparison.

96.1. Reference outside the selection#

The selector may offer a dataset that is not included in the comparison selection.

In that case, the plot silently uses the first selected dataset as fallback reference.

To avoid ambiguity, always include the reference dataset in the selection.

97. Key metric#

Available metrics are:

  • ASVs;
  • samples;
  • reads;
  • mean richness;
  • sparsity.

The chosen metric affects the synthetic interpretation text and the Difference versus reference plot.

98. Synthetic project reading#

The text identifies the dataset with the highest value for the selected metric.

A higher value does not necessarily mean higher quality.

  • More reads may reflect greater depth or sequencing imbalance.
  • More ASVs may reflect higher diversity, noise, or a different method.
  • More sparsity means more zeroes and is not necessarily desirable.

99. Synthetic heatmap#

The heatmap compares:

  • ASVs;
  • samples;
  • reads;
  • mean richness;
  • sparsity.

99.1. Normalization#

Each metric is scaled separately between 0 and 1:

Normalized value =
value - minimum
÷ maximum - minimum

99.2. Identical values#

If every dataset has the same value for a metric, the normalized value is set to 0.5.

99.3. Interpretation#

Color indicates a dataset's relative position for one metric.

It cannot directly compare a read count, sparsity value, and sample count. Units differ and were normalized independently.

Raw values remain available in the tooltip.

100. Comparative dotplot#

The dotplot uses the same 0–1 normalization.

Each point represents a dataset, a metric, and its relative position.

It provides a quick general profile but is not a global score, multivariate analysis, or quality ranking.

101. Difference versus reference#

For the selected metric:

Difference (%) =
dataset value - reference value
÷ reference value
× 100

The reference dataset is not shown as a bar because its difference is zero by definition.

101.1. Zero reference#

The plot is not produced when the reference value is zero or missing.

101.2. One dataset only#

At least one additional dataset must be selected besides the reference.

101.3. Metric-dependent interpretation#

A positive difference means more ASVs, samples, reads, richness, or sparsity depending on the chosen metric.

It does not always mean improvement.

102. Filtration comparison#

The plot displays the number of removed ASVs and removed samples using filtration_log.

102.1. Important limitation#

Values are absolute. They are not divided by initial ASV count, initial sample count, read volume, or dataset size.

Removing 1,000 ASVs from a dataset of 100,000 ASVs is not equivalent to removing 1,000 from a dataset of 2,000.

102.2. Missing log#

A dataset without a log appears as missing. No log does not prove that no filtration was performed.

103. Comparative barplots#

Project view includes absolute barplots for:

  • number of samples;
  • number of ASVs;
  • total reads;
  • mean richness;
  • sparsity.

These plots perform no normalization and no statistical test.

104. Dataset comparability#

Two datasets are not automatically comparable simply because they are loaded into the same project.

Before interpreting plots, verify:

  • same technology;
  • same marker;
  • same region;
  • same pipeline;
  • same filters;
  • same taxonomic database;
  • same samples;
  • same abundance type;
  • same transformation level;
  • same definition of taxonomic units.

105. Comparing different markers#

Comparing COI, 16S, and ITS may be useful for describing their respective dimensions.

However, ASV count, richness, read count, and sparsity should not be interpreted as equivalent biological measurements across markers.

Each marker has different resolution, primers, databases, biases, and biological targets.

106. Before-and-after filtration comparison#

Project view is useful for comparing a raw dataset with a filtered dataset.

Still verify that the filtered object truly derives from the raw object, the same samples are compared, abundances were not transformed, the log is present, and the parent has not been renamed or deleted.

107. Performance#

Description performs several calculations in memory.

Potentially expensive operations include:

  • summing large matrices;
  • computing metrics for every dataset;
  • converting full tables;
  • displaying a very wide OTU table;
  • sequence calculations;
  • rarefaction;
  • Plotly rendering;
  • comparing many datasets.

107.1. Lazy initialization#

The module is initialized when the Description tab is opened. The first display may therefore be slower.

107.2. Large tables#

Deferred rendering improves display, but the complete table is prepared in R memory.

107.3. Rarefaction#

Displaying every curve for hundreds of samples can slow the browser. Use Top reads, Bottom reads, or Outliers to reduce the plot.

108. Troubleshooting#

108.1. No dataset appears#

Possible causes: no dataset loaded, wrong project open, failed import, or session restored without a registry.

Correction: use Input data, OpenMetaBar, or Datasets.

108.2. The displayed dataset changes in other tabs#

Cause: the Description selector is synchronized with the global active dataset.

Correction: this is expected. Use a module-local selection where available.

108.3. The project becomes unsaved after simple inspection#

Possible cause: the active dataset was changed in Description.

Correction: save the project if this choice should persist.

108.4. Values displayed as reads are decimal#

Cause: the OTU table probably contains transformed or normalized values.

Consequence: depth metrics and rarefaction must not be interpreted as raw counts.

108.5. Richness seems inconsistent#

Possible causes: transformed abundance, negative values, unpruned taxa, depth differences, structural zeros, or an unexpected object orientation.

Richness counts only values strictly greater than zero.

108.6. Sparsity seems too low#

Possible cause: the matrix contains NA values, which are not counted as zeroes but remain in the denominator.

108.7. No grouping variable is offered#

Possible causes: missing metadata, only one level, more than fifteen levels, date variable, or only missing values.

Correction: inspect metadata in Data Edition.

108.8. A numeric variable appears as a group#

Cause: it has between two and fifteen distinct values.

Correction: do not select it if a categorical interpretation is inappropriate.

108.9. Missing values appear as an NA group#

Cause: Description converts missing values into a group label.

Correction: clean or complete the metadata if needed.

108.10. The View logs button appears to do nothing#

Cause: it selects the Logs sub-tab but does not automatically expand the box.

Correction: scroll to Tables and logs and expand it.

108.11. Sequences are reported as absent#

Possible causes: no refseq, unavailable Biostrings, or an invalid sequence object.

108.12. GC values look unusual#

Possible causes: ambiguous bases, very short sequences, multiple markers, non-nucleotide sequences, or many non-ACGT characters.

108.13. Taxonomic rank names changed#

Cause: Description makes empty or duplicated names unique for display. The original object is unchanged.

108.14. A SampleID_meta column appears#

Cause: metadata already contained a SampleID column. Description reserves SampleID for row names.

108.15. Rarefaction curves are not calculated#

Possible causes: missing vegan, missing OTU table, fewer than two positive samples, fewer than two samples with 50 reads, unsuitable data, or count errors.

108.16. Rarefaction curves belong to the previous dataset#

Cause: calculation was not rerun after changing datasets.

Correction: click Calculate curves again.

108.17. Maximum curve count is not respected#

Cause: All samples currently ignores this limit.

Correction: choose Top reads, Bottom reads, or Outliers.

108.18. Pooled rarefaction for a large group is much higher#

Cause: reads are summed across all samples in the group.

Consequence: it is not a per-sample mean.

108.19. No outlier is detected#

Possible causes: true homogeneity, fewer than four samples, zero IQR, missing values, or a global threshold poorly suited to group structure.

108.20. A biologically normal sample is flagged#

Possible cause: the rule is applied globally rather than within its group.

Correction: interpret using metadata and experimental context.

108.21. A very atypical sample is not flagged#

Possible causes: the relevant metric is not used, zero IQR, too few samples, an outlier only in zero proportion, or transformed data.

108.22. A group has 30% outliers and appears red#

Cause: color uses an internal 30% visual threshold.

Consequence: this is not a p-value or evidence of a group effect.

108.23. OTU export does not preserve original orientation#

Cause: Description always exports taxa in rows.

108.24. CSV export does not match the visual table filter#

Cause: the dedicated button exports the complete table.

Alternative: use DataTables' built-in CSV button for an export linked to the current table state.

108.25. The CSV file is empty#

Likely cause: the corresponding component is absent.

108.26. Logs are absent#

Possible causes: the dataset was never filtered in BarCodeR, the attribute was removed, the object came from another tool, an older version was used, or logs were not preserved.

108.27. Project view counts the same samples twice#

Cause: counts are summed across datasets without deduplication.

108.28. Heatmap values look similar despite different orders of magnitude#

Cause: each metric is normalized separately between 0 and 1.

108.29. An entire heatmap column equals 0.5#

Cause: every dataset has the same value for that metric.

108.30. The selected reference dataset is not used#

Possible cause: it is not included in the comparison selection.

Correction: add the reference dataset to the selection.

108.31. The difference plot does not work#

Possible causes: zero reference, missing reference, only one selected dataset, or missing metric.

108.32. Filtration comparison seems unfair#

Cause: it compares absolute counts rather than percentages.

Correction: relate removals to original dimensions before concluding.

108.33. Project view is slow#

Possible causes: many datasets, large matrices, many sequences, or very wide tables.

Correction: temporarily remove some datasets, limit the comparison selection, avoid opening large tables unnecessarily, or use filtered datasets.

109. Checklist when opening a dataset#

  • Verify the selected dataset name.
  • Verify sample count.
  • Verify taxon count.
  • Verify total abundance.
  • Verify whether the OTU table is raw or transformed.
  • Verify taxonomy availability.
  • Verify metadata availability.
  • Verify sequence availability.
  • Verify log availability.
  • Read sparsity and depth alerts.

110. Checklist before group-based analysis#

  • Choose a biologically relevant grouping variable.
  • Verify its levels.
  • Verify missing values.
  • Verify group sizes.
  • Ensure the variable is not quantitative by mistake.
  • Examine depth by group.
  • Examine richness by group.
  • Examine outliers.
  • Do not confuse description with statistical testing.

111. Checklist before rarefaction#

  • Confirm abundances are raw counts.
  • Confirm they are integer and non-negative.
  • Confirm at least two samples have 50 reads.
  • Select the correct dataset.
  • Select the correct grouping variable.
  • Click Calculate.
  • Recalculate after every dataset change.
  • Distinguish individual curves from pooled groups.
  • Do not treat a plateau as definitive validation.

112. Checklist before excluding an outlier#

  • Identify the three responsible metrics.
  • Review metadata.
  • Review the experimental group.
  • Review positive and negative controls.
  • Review logs.
  • Review depth.
  • Review taxonomic dominance.
  • Determine whether the difference is biologically expected.
  • Do not remove samples from Description.
  • Use Filtration only with justification.

113. Checklist before comparing datasets#

  • Same abundance type.
  • Same marker or an explicit comparison objective.
  • Same technology or known biases.
  • Same unit definition.
  • Same filtration level.
  • Same sample set or documented differences.
  • Reference dataset included in the selection.
  • Understand that sums are not deduplicated.
  • Understand 0–1 normalization.
  • Do not interpret “higher” as “better.”

114. Current limitations#

114.1. Abundances are not validated as raw counts#

Every metric can be misleading with transformed data.

114.2. ASV count is a generic label#

The module does not know how units were generated.

114.3. The tree is not summarized#

Presence and consistency of phy_tree are not displayed.

114.4. Sequences are not explicitly aligned to taxa#

The module describes available sequences without an exhaustive correspondence check.

114.5. Sparsity and completeness use simple summaries#

They may hide important heterogeneity.

114.6. Diagnostics use internal thresholds#

They are not universal standards.

114.7. Outliers are detected globally#

They are not calculated within groups.

114.8. Zero proportion is not an outlier signal#

It is displayed but does not affect status.

114.9. Rarefaction must be rerun manually#

Changing datasets does not automatically reset the result.

114.10. The curve limit does not affect All samples#

A large dataset can produce a very heavy plot.

114.11. Aggregated curves use pooled counts#

They are not sample means.

114.12. Tables are fully prepared in memory#

Very large objects may be expensive to display.

114.13. Description exports reorient some tables#

The OTU table is exported with taxa in rows.

114.14. Column names may be adjusted for display#

The original phyloseq object remains unchanged.

114.15. Project view sums dimensions#

It deduplicates neither samples nor taxa.

114.16. The heatmap compares relative positions#

It does not compare common units.

114.17. Filtration comparison uses absolute numbers#

It does not adjust for original size.

114.18. No statistical test is performed#

Displayed differences remain descriptive.

115. Recommended workflow#

  1. Open Description after import.
  2. Verify the active dataset.
  3. Examine dimensions and components.
  4. Read structure alerts.
  5. Verify the nature of abundance values.
  6. Examine reads versus richness.
  7. Examine abundance distributions.
  8. Examine richness.
  9. Examine sequences when available.
  10. Choose a relevant grouping variable.
  11. Inspect outliers.
  12. Calculate rarefaction when data are counts.
  13. Examine tables.
  14. Examine completeness.
  15. Examine logs.
  16. Compare datasets in Project view.
  17. Move to Data Edition or Filtration when an action is required.
