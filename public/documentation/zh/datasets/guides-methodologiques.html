数据集 — 方法指南

1. 总览#

Datasets 选项卡管理 BarCodeR 中两个不同层级的内容：

  1. 内存中的数据集：当前会话中可用的命名 phyloseq 对象。
  2. 持久化项目：保存在磁盘上的工作目录，可包含数据集、活动数据集、界面状态、图形历史和各模块文件。

数据集操作包括设置活动对象、重命名、添加备注和标签、复制、调整顺序、导出以及从内存中删除。项目操作包括保存、恢复、新建、打开、重命名、复制、导出、导入和删除工作空间。

2. 必要定义#

2.1. 数据集#

数据集是反应式命名列表中的一个条目：

datasets()

每个条目通常都是一个 phyloseq 对象。列表名称在整个应用中作为该数据集的标识。

2.2. 活动数据集#

活动数据集单独保存在：

active_ds()

它只是被选作全局默认对象的名称，并不是对象的额外副本。

2.3. 数据集注册表#

注册表是当前内存中的数据集列表，包括名称、顺序、属性和活动名称。它不会自动与磁盘上最后一次保存的版本保持一致。

2.4. 会话#

会话指浏览器中应用的当前状态。注册表修改首先发生在内存中。关闭应用或恢复旧保存时，未保存的修改可能丢失。

2.5. 项目#

项目保存在：

save/projects/<项目内部标识>/

其中可能包含 registry.rds、manifest.rds、ui_state.rds，以及 barplot/、alpha_div/、Ordination/、DAA/、Analyse/、multiview/ 等模块目录。

3. 数据集与项目的区别#

属性 数据集 项目
包含 phyloseq 对象 是 一个或多个
可以处于活动状态 是 是，作为当前项目
包含图形历史 否 是
可以只从内存删除 是 否
可以从磁盘物理删除 数据集删除操作不会 是

因此，删除数据集和删除项目是完全不同的操作。

4. 选项卡结构#

该选项卡包含三个主要区域：

  1. 全局活动数据集；
  2. 数据集注册表；
  3. 项目管理。

5. 全局活动数据集#

5.1. 选择器的作用#

所选数据集会成为 Description、Data Edition、Filtration、Exploration 和 Analysis 等模块的默认工作对象。

5.2. 同步#

该选择器与 active_ds() 及其他全局数据集选择器同步。

5.3. 模块内的局部选择#

部分模块可以临时使用另一个数据集。执行操作前，应同时检查全局选择器和模块自己的选择器。

5.4. 更改活动数据集的影响#

更改活动数据集不会编辑、过滤、复制或删除数据，只会改变应用的全局引用。但由于活动名称会保存到项目中，该操作仍会把项目标记为存在未保存修改。

6. 内存中没有数据集#

当注册表为空时，可通过 Input data 加载对象、从 OpenMetaBar 导入 phyloseq、打开已保存项目、导入项目归档或恢复已有注册表。

7. 数据集注册表#

表格为 datasets() 当前内存中的每个条目显示一行。它不会直接扫描磁盘文件。

8. 注册表列#

8.1. 活动状态#

星号表示活动数据集，圆点表示非活动数据集。该图标不表示数据质量、过滤程度或保存状态。

8.2. 名称#

名称是选择器、报告、导出、历史、谱系属性、图例和部分文件名所使用的键。

8.3. ASV#

显示值来自：

phyloseq::ntaxa()

它实际上是分类单元数量。根据上游流程，这些单元可能是 ASV、OTU、ZOTU 或其他类型。

8.4. 样本#

显示值来自：

phyloseq::nsamples()

8.5. 来源#

  • 已加载：没有识别到过滤或 OpenMetaBar 来源属性。
  • OpenMetaBar：对象具有 openmetabar_run。
  • 已过滤：filtration_log 中存在有名称的父数据集。

“已过滤”的优先级高于 “OpenMetaBar”。

8.6. 父数据集#

父名称来自：

filtration_log$parent_dataset

它是存储的字符串，而不是对象之间的动态链接。父数据集重命名或删除时，BarCodeR 会更新可识别后代中的该字段。

8.7. 备注和标签#

它们保存在属性：

list(note = "...", tags = c("tag1", "tag2"))

这些信息会随单个数据集导出、项目保存和复制一起保留。

8.8. 修改日期#

显示日期首先取自 edit_log 的最后一条记录，其次取自 filtration_log。重命名、备注、标签、顺序和活动选择不一定更新该日期。

8.9. 操作#

每一行都可以设为活动、编辑、复制、导出、上移、下移或从内存删除。

9. 刷新注册表#

刷新 只会根据当前反应式对象重新构建可见表格。它不会读取 registry.rds、扫描项目或恢复数据。

10. 设为活动数据集#

激活某行会更新 active_ds()、同步全局选择器并将项目标记为已修改。要在重启后保留该选择，需要保存项目。

11. 编辑数据集#

编辑窗口包含数据集名称、自由文本备注和逗号分隔的标签。

12. 重命名数据集#

12.1. 名称清理#

bcr_clean_label() 会去除首尾空格，把不安全字符替换为 _，删除首尾下划线，并在结果为空时使用 dataset。

12.2. 非 ASCII 字符#

清理结果部分依赖 R 的区域设置。为获得最大的跨系统兼容性，建议使用 ASCII 字母、数字、_ 和 -。

12.3. 名称冲突#

如果名称已存在，会添加 _2、_3 等后缀，不会静默覆盖现有对象。

12.4. 更新活动数据集#

如果被重命名的数据集处于活动状态，active_ds() 会更新为最终名称。

12.5. 已过滤后代#

可识别后代中的 parent_dataset 会更新为新的父名称。

12.6. 不会重命名的内容#

以前导出的文件、源 RDS 文件、旧图形、旧报告、项目名称和项目 slug 不会随之重命名。

13. 添加备注#

备注可用于记录处理步骤、限制、数据库版本、验证状态或预期用途。它保存在 phyloseq 对象内部。修改备注不一定更新注册表的修改日期。

14. 添加标签#

标签按逗号拆分并去除首尾空格。空标签会被删除，但重复项和大小写差异会保留。建议使用一致的命名规则。

15. dataset_meta 属性#

保存编辑时，dataset_meta 会被替换为仅包含 note 和 tags 的列表。此前存放在该属性中的其他自定义字段可能丢失。

16. 复制数据集#

16.1. 建议名称#

默认名称为 <名称>_副本，如有冲突会添加数字后缀。

16.2. 复制内容#

整个对象都会复制：丰度表、metadata、分类表、序列、树、日志、来源、备注、标签和其他属性。

16.3. 活动数据集#

新副本会自动成为活动数据集。

16.4. 后续独立性#

之后两个注册表条目可独立修改。

16.5. 来源#

复制不会创建专门的“副本”来源。副本保留源对象的来源属性和父信息。

17. 调整数据集顺序#

上下箭头改变列表顺序。该顺序可能影响选择器、多数据集操作和默认回退选择。只有保存项目后才会持久化。

18. 导出单个数据集#

行导出会把当前 phyloseq 对象写入类似以下文件：

dataset_<名称>_<时间戳>.rds

其中包含对象组件和属性，但不包含其他数据集、项目图形、模块历史、原始 FASTQ、OpenMetaBar 远程运行目录或原始分类数据库。可通过 Input data 重新导入。

19. 从会话中删除数据集#

19.1. 立即影响#

对象会从 datasets() 中移除，从选择器中消失，并在当前会话中不可再用。项目会被标记为未保存。

19.2. 删除活动数据集#

第一个剩余数据集会成为活动数据集；如果没有剩余对象，active_ds() 变为空。

19.3. 已过滤后代#

如果被删除对象是父数据集，后代中的 parent_dataset 会被清空。由于“已过滤”徽标目前依赖非空父名称，可见来源可能改变。

19.4. 仅影响内存#

磁盘上的最后一次保存不会立即改变。重新从磁盘加载可能使数据集重新出现。

19.5. 让删除持久化#

删除行、检查注册表，然后点击 保存项目。

19.6. 删除最后一个数据集#

快速保存会拒绝空注册表，因此磁盘上可能仍保留旧的非空 registry.rds。若需要真正持久的空工作区，建议新建项目。

20. 未保存修改状态#

datasets() 或 active_ds() 变化时，项目会被标记为已修改。该指示器主要跟踪注册表和活动名称，并不是所有模块文件的完整审计。

21. 项目区域#

项目管理器控制当前持久化工作空间、保存、恢复、创建、导出、导入和项目列表。

22. 当前项目#

当前 slug 保存在：

save/projects/.current

BarCodeR 启动时会尝试重新打开它。如果不可用，则回退到 sans-titre。

23. 显示名称与内部 slug#

项目具有显示名称、ASCII 安全的内部 slug 和磁盘目录。重命名只改变显示名称，slug 和路径保持不变。

24. 项目磁盘结构#

24.1. registry.rds#

保存数据集、顺序、活动数据集和格式元数据。

24.2. manifest.rds#

保存显示名称、创建/修改时间和已保存数据集数量。

24.3. ui_state.rds#

可保存主选项卡、子选项卡和可恢复界面参数。

24.4. 模块目录#

各模块可在自己的目录中保存图形、R 对象、参数和历史元数据。

25. 项目不会自动包含的内容#

项目不是所有科研输入的完整副本。原始 FASTQ/BAM、参考 FASTA、分类数据库、OpenMetaBar design、远程结果、外部脚本和工具数据库必须单独归档。

26. 保存项目#

26.1. 保存内容#

保存操作会写入数据集列表、顺序、完整对象及属性、活动数据集、清单中的数量和可用界面状态。

26.2. 图形历史#

图形历史通常由模块直接写入。保存操作主要同步数据集注册表。

26.3. 空项目#

没有数据集时会拒绝保存。

26.4. 防止空内存覆盖#

非空已保存注册表会受到保护，避免在加载失败等情况下被空内存覆盖。

26.5. 成功保存#

成功后会清除未保存标记并更新项目元数据。

27. 可用保存状态#

显示时间是 registry.rds 的修改时间，不一定是最后一张图、最后一次分析或最后一个历史文件的时间。

28. 从磁盘重新加载#

重新加载会用 registry.rds 的内容替换当前内存中的所有数据集，不会合并。未保存的导入、编辑、删除、过滤、备注、标签、顺序和活动选择都可能丢失。

29. 找不到保存#

没有 registry.rds 可能表示新项目、仅有图形的项目、从未保存的项目、文件被手动删除或导入不完整。

30. 保存无法读取#

如果 registry.rds 无法读取，项目可能以空内存打开并显示警告。BarCodeR 会防止用空注册表静默覆盖该文件。尝试恢复前应先复制整个项目目录。

31. 仅导出数据为 .rds#

该导出包含版本化的 datasets() 和 active_ds() 列表，不包含图形、历史、清单、项目显示名称、界面状态和外部文件。可从 Input data 重新导入。

32. 导出完整项目为 .zip#

ZIP 包含当前项目目录。BarCodeR 会先尝试保存内存注册表。如果保存失败，归档仍可能包含磁盘上最后一个有效版本，而不是当前内存状态。必须检查通知。

33. 大小警告#

项目超过 200 MB 时显示警告。大小包含全部项目文件，并可能短暂缓存。应用上传限制为 500 MB，因此更大的 ZIP 可能可以导出，但无法通过界面重新导入。

34. 导入项目 .zip#

归档总是解压为新项目，不会与当前项目合并。导入后需从项目列表中打开。BarCodeR 会识别 registry.rds、manifest.rds 或已知历史目录；因此仅包含图形的项目可能以零数据集导入。

35. 新建项目#

系统会创建目录和清单，当前项目进入正常的保存/切换流程，新项目成为当前项目，应用重新加载。空名称或重复名称会被拒绝。

36. 打开另一个项目#

BarCodeR 会尝试保存当前项目，把新 slug 写入 .current，重新加载会话，并使用新项目路径初始化模块。保存错误并不总能阻止切换，因此不能忽略红色通知。

37. 多个 BarCodeR 浏览器标签页#

当前项目在 R 进程层面共享。其他标签页可能仍使用旧项目路径，并把文件写入错误位置。切换项目之前应保存并关闭其他 BarCodeR 标签页。

38. 重命名当前项目#

只改变显示名称。slug、目录、历史、数据集和活动数据集都不会移动。其他项目已使用的名称会被拒绝。

39. 项目列表#

项目按清单最近修改时间排序。数据集数量反映磁盘上已保存的注册表，不一定等于内存中未保存的状态。

40. 复制项目#

整个项目目录都会复制，包括注册表、清单、界面状态、数据集、图形和历史。复制当前项目之前建议手动保存，因为内部预保存结果不是严格阻断条件。

41. 删除项目#

只能删除已关闭项目。整个 save/projects/<slug>/ 目录会被永久删除，没有内部回收站。删除前应先导出 ZIP。

42. 三种导出的区别#

导出 内容 图形 重新导入位置
单个数据集 .rds 一个 phyloseq 否 Input data
项目数据 .rds 数据集列表 + 活动名称 否 Input data
完整项目 .zip 项目目录 是 Datasets

43. 项目与 OpenMetaBar 数据#

导入 phyloseq 不会复制远程 OpenMetaBar 运行目录。原始 reads、Nextflow 日志、work/、容器、参考数据库和集群输出需要单独归档。

44. 项目与图形历史#

只有实际保存在模块历史中的图形才能保证位于项目内。仅在屏幕显示的图形可能没有归档。

45. 项目物理位置#

项目位于 <BarCodeR工作目录>/save/projects/。在 Docker 或服务器部署中，该目录必须使用持久存储。在共享实例上，隐私取决于权限、认证和部署配置。

46. 推荐的日常流程#

  1. 打开或创建正确项目。
  2. 加载数据。
  3. 检查注册表和活动数据集。
  4. 添加有用的备注和标签。
  5. 大规模编辑前先复制。
  6. 定期保存。
  7. 导出关键数据集。
  8. 定期把完整 ZIP 保存到 BarCodeR 之外。

47. 高风险操作之前#

在过滤、大规模编辑、删除、恢复、切换项目或升级应用之前，应保存项目、确认成功、导出重要数据集、必要时导出完整项目，并验证下载文件。

48. 故障排除#

48.1. 注册表中缺少数据集#

检查导入是否完成、当前项目是否正确、对象是否已删除以及是否恢复了旧注册表。

48.2. 模块使用了错误数据集#

同时检查全局和模块局部选择器。

48.3. 活动选择未保留#

更改后保存项目。

48.4. 输入名称被修改#

不安全字符被规范化。

48.5. 添加了 _2#

已有相同最终名称。

48.6. 修改日期没有变化#

备注、标签和重命名不使用该日期来源。

48.7. 副本保留原始来源#

复制会复制属性。

48.8. 已过滤数据集不再显示为已过滤#

父数据集可能已删除。检查 attr(ps, "filtration_log")。

48.9. 已删除数据集重新出现#

删除未保存，之后恢复了旧注册表。

48.10. 无法保存空项目#

快速保存至少需要一个数据集。需要空工作区时新建项目。

48.11. 重新加载删除了修改#

重新加载会用保存的注册表替换内存。

48.12. 没有保存文件#

项目尚未写入 registry.rds。

48.13. 项目以空状态打开并提示注册表错误#

不要覆盖。先复制目录，并在外部测试 readRDS()。

48.14. 新项目名称被拒绝#

名称为空或已存在（忽略大小写和首尾空格）。

48.15. 重命名后目录仍为旧名称#

设计上只改变显示名称。

48.16. 打开项目会重新加载应用#

这是重新初始化模块路径所必需的。

48.17. 打开另一个项目时出现保存错误#

切换仍可能继续。应重新打开并检查前一个项目。

48.18. 多标签页警告#

切换项目之前关闭其他标签页。

48.19. 项目副本缺少最新修改#

复制前显式保存。

48.20. 无法删除当前项目#

先打开另一个项目。

48.21. 删除项目失败#

检查权限、文件锁、磁盘错误和目标目录。

48.22. ZIP 很大#

删除不必要的历史或仅导出数据。

48.23. ZIP 超过 500 MB#

提高 shiny.maxRequestSize、缩小归档、直接复制项目目录或使用外部存储。

48.24. 导入项目未自动打开#

在列表中选择并点击 打开。

48.25. 归档无效#

检查 ZIP 完整性和可识别的项目标记。

48.26. 导入项目有零个数据集#

它可能只有历史，或注册表缺失/无法读取。

48.27. ZIP 不包含最新数据#

导出前保存可能失败；检查通知。

48.28. 项目列表中的数据集数量不正确#

保存并刷新；列表反映持久化元数据。

48.29. 项目大小延迟更新#

大小计算会短暂缓存。

48.30. 重新部署后项目消失#

把 save/projects/ 挂载到持久存储。

49. 保存前检查清单#

  • 当前项目正确。
  • 预期数据集均存在。
  • 活动数据集正确。
  • 名称、备注和标签正确。
  • 删除和复制均为有意操作。
  • 没有重要操作仍在等待。
  • 没有错误通知。

50. 切换项目前检查清单#

  • 保存当前项目。
  • 确认成功通知。
  • 导出关键数据集。
  • 关闭对话框并结束计算。
  • 关闭其他 BarCodeR 标签页。
  • 核对目标项目名称。

51. 删除数据集前检查清单#

  • 核对准确名称和活动状态。
  • 检查已过滤后代。
  • 必要时导出。
  • 归档项目。
  • 删除并检查新的活动数据集。
  • 保存项目。

52. 删除项目前检查清单#

  • 确认它不是当前项目。
  • 导出并验证 ZIP。
  • 单独导出关键数据集。
  • 确认原始数据和 OpenMetaBar 输出已在其他位置归档。
  • 完成以上检查后再删除。

53. 推荐备份策略#

至少使用三层备份：

  1. 定期点击 保存项目；
  2. 对关键数据集进行单独 RDS 导出；
  3. 定期生成完整 ZIP 并存放在 BarCodeR 安装目录之外。

仅使用内部存储无法防止磁盘丢失、部署替换或服务器故障。

54. 可追溯性原则#

使用明确的项目和数据集名称、一致的标签、有意义的备注、保留的来源信息、大规模编辑前的副本、频繁保存、参考导出、记录的 BarCodeR 版本，以及独立的原始数据归档。

55. 当前限制#

  • 数据集操作首先发生在内存中，保存后才持久化。
  • 空项目无法快速保存。
  • 修改日期并不完整。
  • “已过滤”来源依赖有名称的父数据集。
  • 复制会保留来源属性。
  • 数据集名称不保证全部为 ASCII。
  • 项目切换对整个 R 实例生效。
  • 保存错误不一定阻止项目切换或复制。
  • 保存指示器主要跟踪注册表和活动数据集。
  • ZIP 不包含外部科研文件。
  • 超过 500 MB 的归档可能无法通过界面导入。
  • save/projects/ 必须使用持久存储。
