输入数据 — 方法指南

1. 概述#

Input data 选项卡用于把一个或多个已经构建好的 phyloseq 对象导入 BarCodeR。

支持以下 R 序列化格式：

  • .rds；
  • .RData；
  • .rda；
  • .rdata。

应用会自动判断文件中包含：

  1. 一个 phyloseq 数据集；
  2. 一个包含多个 phyloseq 数据集的项目；
  3. 多个兼容对象，需要用户选择；
  4. 不支持的对象，此时拒绝导入。

Input data 不会根据独立表格重新构建 phyloseq，而是读取已经序列化的 R 对象。

2. Input data 在 BarCodeR 中的位置#

需求 使用的选项卡
加载已有 phyloseq Input data
加载 .rds 项目中的多个 phyloseq Input data
获取集群上生成的 phyloseq OpenMetaBar
从独立表格构建或补全 phyloseq Data Edition
重命名、复制、删除或导出数据集 Datasets
导入含图形和历史记录的完整项目 Datasets
恢复当前项目的内部备份 Datasets

2.1. 当前不再由 Input data 处理的操作#

当前版本不再直接提供删除、重命名、复制、导出数据集或管理命名项目的功能。这些操作集中在 Datasets 中。

3. 当前界面#

界面只有一个主要区域：

加载文件（.rds / .RData / .rda）

其中包括自动检测说明、文件选择器、清理规则说明，以及数据集管理位于 Datasets 的提示。

当前不再提供独立的“加载数据集/加载项目”选择器、OTU table 方向选择、metadata 转置、分类表修正或删除区域。

4. 文件大小限制#

文件通过 Shiny fileInput 上传。BarCodeR 当前全局限制为：

500 MB

大于此限制的文件通常无法通过该字段上传。

4.1. 磁盘大小与内存大小#

.rds 可能被压缩。磁盘上的文件可能远小于加载后的 R 对象。

导入时需要同时容纳已加载对象、当前已有数据集以及清理过程产生的临时副本，因此实际内存需求可能远高于文件大小。

4.2. 远程服务器上的 BarCodeR#

当应用运行在远程机器上时，文件会发送到 Shiny 服务器。耗时取决于文件大小、网络速度、服务器负载和可用内存。

读取和清理是同步执行的，大对象导入期间界面可能暂时无响应。

5. 支持的文件格式#

5.1. .rds#

.rds 保存一个 R 对象。BarCodeR 使用 readRDS() 读取并判断对象类型。

默认数据集名称来自去掉扩展名的文件名：

metabarcoding_coi.rds
→ metabarcoding_coi

5.2. .RData 或 .rda#

.RData 可包含多个 R 对象。BarCodeR 会：

  1. 在隔离的临时环境中加载文件；
  2. 检查每个对象；
  3. 只保留被识别为数据集或项目的对象；
  4. 若只有一个兼容对象则自动选择；
  5. 若有多个则要求用户选择。

不兼容对象会被忽略。

5.3. 不支持的扩展名#

Input data 不直接导入 .csv、.tsv、.xlsx、.biom、.qza、.zip、.RDS.gz、FASTA、FASTQ 或 Newick。

独立表格应在 Data Edition 中处理；完整 BarCodeR .zip 项目应在 Datasets 中导入。

6. 自动内容检测#

检测基于对象真实结构，而不是只看文件名或扩展名。

6.1. 单个数据集#

继承 phyloseq 类的对象被识别为数据集。

6.2. 项目#

以下对象会被识别为项目：

  • 包含 datasets 元素的列表；
  • 包含历史字段 ps_registry 的列表；
  • 非空且所有元素都是 phyloseq 的列表。

6.3. 结构式识别#

项目识别不一定依赖版本号、format 字段、文件名或专用类。这有利于兼容旧格式，但任意带有 datasets 元素的列表也可能被误判为项目。

7. 数据集与项目的区别#

7.1. 数据集#

一个数据集对应一个 phyloseq 对象，可包含 otu_table、sample_data、tax_table、系统发育树和参考序列。

导入到通用注册表时，真正必需的是 OTU table。

7.2. 数据型 .rds 项目#

Input data 加载的 .rds 项目主要包含数据集列表、活动数据集名称和可选保存信息：

list(
  version = 2,
  format = "version_ok_project",
  saved_at = ...,
  datasets = ...,
  active_ds = ...
)

7.3. 完整 .zip 项目#

完整 .zip 还可包含图形历史、模块文件、参数和项目清单。请使用 Datasets → 导入项目（.zip）。

7.4. 导入 .rds 不会切换当前 BarCodeR 项目#

它不会创建新的命名项目、自动切换当前项目、恢复图形或模块历史，也不会恢复全部导航状态。它只在当前项目内存中添加或替换数据集。

8. 加载文件#

8.1. 选择文件#

一次只能选择一个兼容文件。选择后 BarCodeR 立即读取并决定后续流程。

8.2. 读取错误#

文件损坏、并非有效 R 序列化、依赖缺失、类不可用或内容与扩展名不符时，导入会停止。

文件字段会被重置，以便修复后重新选择同一文件。

9. 含多个对象的 .RData#

检测到多个兼容对象时，会显示 选择要加载的对象。

每个选项显示 R 对象名称和检测类型：

ps_coi       (dataset)
ps_16s       (dataset)
my_project   (project)

9.1. 使用所选对象#

点击 使用此对象 进入对应的数据集或项目流程。

9.2. 取消#

取消 会关闭窗口、清空文件选择器并删除临时待处理对象。

9.3. 使用右上角关闭按钮#

当前实现中，右上角关闭按钮与“取消”执行的清理并不完全相同。同一文件可能无法立即再次触发导入。放弃导入时优先使用 取消。

10. 加载单个 phyloseq 数据集#

检测到单个数据集后，BarCodeR 显示 准备加载数据集。

该窗口用于设置名称、选择“添加”或“替换”，并说明将执行的自动清理。

11. 数据集名称#

11.1. 建议名称#

.rds 通常使用文件名；.RData 优先使用 R 对象名。

11.2. 名称清理#

确认时会去除首尾空格、将不支持字符替换为 _、移除首尾 _，结果为空时使用 dataset。

注册表主要保留字母数字、_ 和 -。非 ASCII 字符的处理也受 R locale 影响。

11.3. 名称冲突#

“添加”模式下，已有名称会通过后缀保护：

COI
COI_2
COI_3

原对象不会被静默覆盖。

12. 添加或替换#

12.1. 添加到当前会话#

默认模式。保留当前所有数据集，添加新对象，必要时使名称唯一，并把新对象设为活动数据集。

12.2. 替换当前内存数据#

清除当前内存中的所有数据集，只保留新数据集并设为活动。

注意： 磁盘源文件不会被删除，但尚未保存的数据集可能丢失。替换前应在 Datasets 中保存项目。

12.3. 空会话#

当前没有数据集时，不显示添加/替换选择，相当于替换一个空列表。

13. 实际执行的 phyloseq 清理#

清理是有限且有针对性的。BarCodeR 不会重建整个对象，也不会自动转置表格。

主要操作：

  1. 确定 OTU table 中样本所在轴；
  2. 必要时规范样本名称；
  3. 与 metadata 同步；
  4. 将 metadata 空白单元格替换为 NA；
  5. 检查部分标识符一致性。

14. OTU table 方向#

BarCodeR 保留原方向，并使用 taxa_are_rows() 判断样本轴。

14.1. 分类单元在行#

taxa_are_rows(ps) == TRUE 时，样本位于列，因此处理列名。

14.2. 分类单元在列#

taxa_are_rows(ps) == FALSE 时，样本位于行，因此处理行名。

14.3. 不自动转置#

应用不会强制 ASV 在行、样本在列或所有数据集方向一致。旧文档中“选择方向”的弹窗已不再适用。

15. 样本名称规范化#

15.1. 转换规则#

会尝试音译重音字符、去除首尾空格、将内部空格和不安全字符替换为 _、合并连续 _、移除首尾 _、补充空名称并为重复项添加后缀。

15.2. 示例#

原始名称 可能结果
Station 01 Station_01
Station-01 Station_01
Échantillon A Echantillon_A
sample/1 sample_1
sample sample
空名称 sample_1
两个 sample sample, sample_1

15.3. 为什么要清理#

复杂名称可能在统计公式、表连接、R 包、文件名、图形、导出和 Shiny 选择器中引发问题。

15.4. 并非所有情况下都保留清理结果#

只有 metadata 仍能正确对齐时，OTU table 的重命名才会保留。

如果无法安全匹配，BarCodeR 会撤销 OTU 重命名，保留原始名称并在报告中警告。表间一致性优先于外观清理。

16. Metadata 处理#

sample_data 可缺失。没有 metadata 的 phyloseq 可以导入，但需要样本变量的分析不可用。

16.1. 行名对齐#

如果 metadata 行名与 OTU 原始样本名一致，会对二者应用相同转换。

若无法直接证明匹配，会单独尝试清理 metadata，只有仍与 OTU 兼容时才应用。

匹配不确定时保留原名称，并在报告中给出警告。

17. Metadata 空白单元格#

空字符串和只含空格的字符串会替换为真正的 NA。

原值 导入后
"" NA
" " NA
"0" "0"
"NA" "NA"
真正 NA NA

文本 "NA" 不会自动变成缺失值。

17.1. 列类型影响#

当前实现会先把每个 metadata 列转为字符，再替换空白。

因此 numeric、integer、logical、factor、Date 等列可能变成 character。导入后必须在 Description、Data Edition 或 R 中检查列类型。

这是数据的真实转换，不只是显示变化。

18. 不会被修改的 phyloseq 内容#

Input data 不直接修改 OTU 丰度、方向、ASV 名称、分类值与等级名、参考序列、系统发育树、零值、零丰度分类单元、零深度样本、负值/小数或 OTU table 中的 NA。

因此它不等于完整科学验证。

19. 单数据集一致性检查#

19.1. Phyloseq 类#

对象必须是真正的 phyloseq。

19.2. 必需的 OTU table#

必须包含 otu_table。

19.3. 样本标识符#

如果存在 sample_data，其行名必须覆盖全部样本。顺序可不同，但集合必须一致。部分 metadata 会被拒绝。

19.4. 分类单元标识符#

如果存在 tax_table，其行名必须覆盖 OTU table 中全部分类单元。

19.5. 未检查内容#

通用 guard 不直接检查 refseq/树覆盖、序列有效性、计数是否为整数、是否非负、分类生物学合理性、分类重复或最小测序深度。

20. 因不一致而拒绝导入#

样本或分类标识符不一致、缺少 OTU table 或对象不是 phyloseq 时，单数据集导入会被拒绝。

不会向会话添加数据集，原始文件也不会被修改。

21. 单数据集导入报告#

成功后显示 数据集已加载并检查。

报告包含最终名称、样本数、分类单元/ASV 数、操作总数、源文件、R 对象名、添加/替换模式、内存中数据集总数、OTU 与 metadata 名称的“之前 → 之后”表、空白单元格数量以及警告和备注。

只展示前十项名称变化，但总数仍会显示。

22. 加载 .rds 项目#

BarCodeR 会提取项目中的 phyloseq 数据集。

22.1. 空会话#

没有现有数据集时，直接以替换模式加载，并显示恢复报告。

22.2. 已有数据集#

加载项目 窗口显示当前名称、项目中的名称以及添加/替换选择。

23. 添加项目数据集#

添加模式保留当前数据集、逐个添加 phyloseq、解决名称冲突并设置活动数据集。

23.1. 名称冲突#

已有 COI 时，导入的 COI 可变为 COI_2。

23.2. 导入后的活动数据集#

如果项目含有效 active_ds，对应数据集通常会被激活；若因冲突改名，则使用新名称。否则激活第一个导入数据集。

24. 用项目替换#

替换模式清除内存中现有数据集，加载项目列表，并在有效时恢复 active_ds，否则选择第一个数据集。

它不会删除磁盘文件，但未保存的当前数据集可能丢失。

25. 项目中的数据集名称#

有效名称会保留，并在添加模式下处理冲突。

若名称缺失、为空或部分缺失，会生成：

dataset_1
dataset_2
dataset_3

当前实现中，一个缺失名称可能导致整组名称重新生成。

26. 项目中的非 phyloseq 内容#

对于包含 datasets 或 ps_registry 的结构，最终只保留真正继承 phyloseq 的元素，其余忽略。

预览中的名称可能多于实际加载数量，应以最终报告为准。

结构上被识别但不含有效 phyloseq 的项目，在替换模式下可能得到空注册表。

27. 项目数据集清理#

每个 phyloseq 都执行相同的样本名、metadata 行名和空白单元格清理。

项目报告按数据集汇总样本数、分类单元数、OTU 名称变化、metadata 名称变化和空白单元格数，但不会显示每个对象的全部前后对照表。

28. 单数据集与项目的验证差异#

单个数据集在插入前明确经过 bcr_guard_ps()。

项目中的每个 phyloseq 会被清理，但当前不会在整组插入前逐个显式运行同一 guard。

活动数据集切换时会进行全局检查。因此导入项目后，应逐个检查重要数据集的警告、维度、组件和标识符。

29. 会话内存#

数据集存储在反应式注册表 datasets() 中，活动名称存储在 active_ds() 中。

导入后注册表发生变化，下游模块可见新内容，当前项目被标记为已修改且未保存。

29.1. 导入不等于保存#

关闭前应使用 Datasets → 保存项目。

30. 活动数据集#

单个新数据集导入后会成为活动数据集。项目会尝试恢复保存的 active_ds，否则选择第一个数据集。

之后可通过全局控件、Datasets 或同步模块更改活动数据集。

31. 导入不提供的科学保证#

成功导入主要表示对象可读、属于 phyloseq、具有 OTU table，并通过部分标识符检查。

它不保证原始计数、未经过转换、已移除空样本/分类单元、分类正确、等级顺序正确、序列/树覆盖完整、实验设计有效、重复足够、metadata 类型保持不变或适合所有统计分析。

32. 导入后建议检查#

打开 Description，至少检查：

  • 样本数、分类单元数、总 reads；
  • OTU、metadata、taxonomy、tree、reference sequence 是否存在；
  • 样本和 ASV 名称及自动重命名；
  • metadata 列类型、缺失值、数值变量、因子和日期；
  • OTU 方向、负值、小数、NA、零深度样本和零丰度分类单元；
  • 分类等级、列名、未分类值和 ASV 对应；
  • 树与参考序列覆盖。

33. 后续数据集管理#

在 Datasets 中选择活动数据集、重命名、复制、删除、导出、保存项目、恢复内部备份或切换项目。

34. 故障排除#

34.1. 文件未显示#

检查扩展名是否为 .rds、.RData、.rda 或 .rdata，以及是否额外压缩。

34.2. 超过 500 MB#

缩小对象、移除不必要组件、拆分数据集、逐个导出，或在受控部署中调整限制。

34.3. 小文件占用大量内存#

序列化文件在内存中展开。释放内存并避免同时保留多个大副本。

34.4. .rds 读取错误#

obj <- readRDS("file.rds")
class(obj)

检查文件损坏、传输不完整、类缺失或扩展名错误。

34.5. .RData 中没有兼容对象#

load("file.RData")
ls()
class(object_name)

34.6. 出现多个对象#

这是正常情况，选择目标对象。

34.7. 普通列表被识别为项目#

它可能含 datasets 或 ps_registry。直接保存目标 phyloseq：

saveRDS(my_phyloseq, "dataset.rds")

34.8. 缺少 OTU table#

phyloseq::otu_table(ps)

34.9. 样本 ID 不一致#

setequal(
  phyloseq::sample_names(ps),
  rownames(as.data.frame(phyloseq::sample_data(ps)))
)

应返回 TRUE。

34.10. 分类单元 ID 不一致#

setequal(
  phyloseq::taxa_names(ps),
  rownames(as(phyloseq::tax_table(ps), "matrix"))
)

34.11. 部分 metadata 被拒绝#

补齐缺失样本、一致地移除未记录样本，或重新构建对齐对象。

34.12. 样本名称变化#

查看导入报告中的“之前 → 之后”。

34.13. 名称未被清理#

可能为了保持 metadata 对齐而撤销了 OTU 重命名。

34.14. 数值列变成文本#

str(as.data.frame(phyloseq::sample_data(ps)))
metadata$Depth <- as.numeric(metadata$Depth)

转换前先检查内容。

34.15. 文本 "NA" 不是缺失值#

metadata[metadata == "NA"] <- NA

若 "NA" 是合法类别，应谨慎处理。

34.16. 项目加载的数据集少于预期#

某些元素可能不是 phyloseq 或被忽略。以最终报告为准。

34.17. 名称全部变为 dataset_1 等#

至少有一个列表名称缺失或为空：

names(project$datasets) <- c("COI", "16S", "ITS")

34.18. 名称出现 _2#

添加模式保护了已有名称。

34.19. 原数据集消失#

可能确认了替换模式。请从保存项目、.rds、.zip 或原始文件恢复。

34.20. .rds 项目没有恢复图形#

Input data 只加载数据型项目。完整图形和历史应通过 Datasets 导入 .zip。

34.21. 同一文件无法再次触发#

上一次可能用右上角关闭按钮结束。临时选择其他文件、重置字段或重新加载选项卡。

34.22. 没有 metadata#

导入仍可成功，但依赖样本变量的分析不可用。

34.23. 没有 taxonomy#

依赖 tax_table 的分析与可视化不可用。

34.24. 没有 tree#

部分 UniFrac 等依赖树的方法不可用。

34.25. 没有参考序列#

直接使用序列的分析不可用。

35. 导入前检查清单#

文件#

  • 格式为 .rds、.RData 或 .rda。
  • 小于 500 MB。
  • 内存足够。
  • 可在 R 中读取。

Phyloseq#

  • 存在 OTU table。
  • 样本 ID 唯一。
  • 分类单元 ID 唯一。
  • metadata 覆盖全部样本。
  • taxonomy 覆盖全部分类单元。
  • tree 与 sequences 在存在时保持一致。

Metadata#

  • 缺失值已识别。
  • 数值列已明确。
  • 有序因子和日期已记录。
  • 样本名与 OTU table 对齐。

当前会话#

  • 已保存现有数据集。
  • 理解添加/替换差异。
  • 已考虑名称冲突。

36. 导入后检查清单#

  • 阅读完整清理报告。
  • 检查样本重命名。
  • 检查样本和分类单元数量。
  • 检查 metadata 列类型。
  • 检查转换为 NA 的单元格。
  • 打开 Description。
  • 检查 OTU table 与 taxonomy。
  • 检查 sequences 与 tree。
  • 在 Datasets 中保存项目。

37. 当前限制#

  1. 不进行完整科学验证。
  2. Metadata 列可能转为 character。
  3. 不自动转置。
  4. 不清理 taxonomy。
  5. 项目验证弱于单数据集。
  6. 项目识别是结构式的。
  7. 使用关闭按钮可能残留临时状态。
  8. 上传上限为 500 MB。

38. 推荐流程#

  1. 在 R 中构建并检查 phyloseq。
  2. 使用 saveRDS() 保存。
  3. 打开 Input data。
  4. 选择文件。
  5. 选择添加或替换。
  6. 检查名称。
  7. 确认导入。
  8. 阅读报告。
  9. 打开 Description。
  10. 检查维度和组件。
  11. 检查 metadata 类型。
  12. 在 Datasets 中保存项目。

41. 可追溯性原则#

保留原始文件，不覆盖旧导出，记录导出日期，保留原对象名，检查清理报告，记录自动重命名，检查 metadata 类型，保存 BarCodeR 项目，并区分源对象与内存中的清理对象。

BarCodeR 中的对象可能因样本名清理、metadata 同步、空白替换和列类型转换而与源文件不同。

已核实的内部来源#

  1. modules/data/mod_data_loader_ui.R — 当前界面与支持的扩展名。
  2. modules/data/mod_data_loader_server.R — 临时状态、检测、清理、弹窗、插入与报告。
  3. modules/_shared/_dataset_naming.R — 安全且唯一的数据集名称。
  4. modules/_shared/_ps_guard.R — phyloseq 类、OTU table 与标识符一致性。
  5. modules/datasets/mod_datasets_server.R 与 mod_datasets_ui.R — 数据型和完整项目格式。
  6. app.R — 500 MB 限制、datasets() 注册表、活动数据集与未保存状态。
