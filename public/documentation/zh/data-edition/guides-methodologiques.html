数据编辑 — 方法指南

1. 总体介绍#

Data Edition 会直接修改已加载 phyloseq 数据集的内部组件：样本 metadata、OTU 丰度、分类表、参考序列和系统发育树。它还支持组件导入、导出、删除、ASV 重命名以及描述性编辑日志。

2. 基本原则：修改会立即生效#

Data Edition 不是独立草稿区。大多数操作都会立即替换 datasets() 中的当前对象，包括单元格编辑、列操作、合并、ASV 重命名、分类值替换、完整导入和组件删除。

3. “保存”按钮不会应用待处理修改#

修改在点击之前已经生效。保存仅用于按当前名称重新注册、创建新条目或覆盖另一个注册表条目；它不会把项目保存到磁盘。

4. 对原始版本的重要影响#

编辑 COI_raw 后再保存为 COI_edited，并不会保留未修改的 COI_raw，因为源条目早已被修改。编辑前应在 Datasets 中复制原始数据集。

5. 对源文件的影响#

Data Edition 不会重写原始 RDS、RData、CSV、FASTA、Newick 或远程文件，只会修改内存中的对象。要持久化结果，需要保存项目或导出数据集。

6. 选项卡结构#

包含数据集选择、metadata 编辑、OTU 编辑、分类编辑、完整组件导入/导出/删除、日志以及注册表保存。

7. 选择要编辑的数据集#

选择器列出注册表中的数据集，并与 active_ds() 同步。因此在此切换数据集会改变全局活动数据集。

8. 编辑过程中切换数据集#

切换后会重新加载 metadata、OTU 和 taxonomy 编辑器的本地状态，并重置初始状态、上一步状态和预览。这里的“初始状态”不一定是原始文件状态。

9. 切换离开后再返回时的重置#

若先修改 COI，再打开其他数据集，之后返回 COI，此时重置会回到返回时加载的已修改版本，而不是第一次编辑前的版本。

10. 编辑与项目持久化#

每次操作都会更新 datasets()，并可能将项目标记为未保存。关闭应用前需使用 Datasets → 保存项目。

11. 两种导入方式的区别#

表格编辑器中的 合并 只根据共同标识符添加缺失列；完整组件导入则在选择文件后立即替换整个组件。

12. Data Edition 不适合的操作#

它不是进行生物学过滤、归一化、丰度转换或阈值删除的首选工具。此类操作应使用 Filtration 或受控外部流程。

13. 编辑历史#

操作可向 attr(ps, "edit_log") 添加记录，包括时间、数据集、表、动作、说明、修改前后维度和警告。

14. 日志不是备份#

日志不保存完整旧表，只是审计记录，不能作为完整版本控制或恢复系统。

15. 日志语言#

edit_log 中的动作和警告保持法语，即使界面使用其他语言。

16. 三种日志视图#

最近全局动作显示当前模块会话的最后动作，完整历史显示已存日志，摘要统计动作、表、警告和时间范围。

17. 总动作数包括什么#

可能包括单元格编辑、结构变化、导入、导出、撤销、重置、注册、重命名和自动同步。

18. 撤销：仅一步#

每个编辑器只保存一个上一步状态。撤销不会遍历全部历史，多次点击可能在两个最近状态之间切换。

19. 重置#

重置回到子模块加载数据集时捕获的本地状态。它立即生效、会写日志并可撤销，但不保证回到原始文件。

20. Metadata 编辑 — 概述#

作用于 sample_data(ps)，可编辑值、添加/删除/重命名变量、合并文件、撤销和重置。

21. 自动创建缺失的 metadata#

若不存在可用 metadata，打开编辑器会创建最小 sample_data，包含 SampleID 列和每个样本一行。该变化可能没有专门日志记录。

22. 样本标识符#

真正标识符是与 sample_names(ps) 对齐的 rownames。显示的 SampleID 列只是普通变量，编辑它不会重命名 OTU 样本。

23. 可编辑 metadata 表#

单元格可直接编辑，并在确认该单元格后立即应用，没有统一“应用全部”按钮。

24. 因子处理#

因子会在本地转为字符，首次重写后可能丢失 levels 和顺序。

25. 列表列处理#

列表列会被压平为逗号分隔文本，可能无法恢复原结构。

26. 编辑数值列#

有效数字保持数值，空单元格变为 NA_real_，非数值文本可能让整列转为字符，并产生警告。

27. 数值转文本的后果#

连续协变量变为 character 后，可能无法作为定量变量用于统计分析。编辑后必须检查列类型。

28. 逻辑、日期和特殊类型#

显式保留主要针对数值列。logical、Date、POSIXct、有序因子和自定义类可能丢失。

29. 添加 metadata 列#

新列全部初始化为 NA。名称必须以 ASCII 字母开头，只含字母、数字或 _，不能含点且必须唯一。

30. 兼容名称建议#

模块可能给出规范化建议，但不会自动应用。

31. 重命名 metadata 列#

保留值并要求名称有效且唯一，但不会修改 rownames 或样本名称。

32. 重命名对分析的影响#

使用旧变量名保存的公式或参数不会自动更新，需要重新配置。

33. 删除 metadata 列#

必须使用区分大小写的准确名称；可能显示大小写或近似名称建议。

34. 删除最后一列#

没有通用保护保证至少保留一列。若要完全删除 metadata，应使用完整组件删除。

35. Metadata 行一致性#

缺失样本会补 NA，行会按 sample_names(ps) 排序，额外行会被丢弃。

36. 将文件合并到 metadata#

支持 CSV、TSV 和 TXT，分隔符可为逗号、分号或制表符。

37. 自动检测 metadata 分隔符#

最多检查三十行非空、非注释行，比较字段数和规则性。若不确定，可手动覆盖。

38. 第一列作为标识符#

启用后第一列成为 rownames。未启用时，数字 rownames 通常无法与样本匹配。

39. Metadata 合并的实际行为#

只为共同 rownames 添加新列；匹配样本写入值，其余当前样本填 NA。

40. 已存在的列#

合并不会更新现有列。若没有新列，则不修改任何内容。

41. 合并文件中的额外样本#

不在 phyloseq 中的标识符会被忽略，不会创建新样本。

42. 文件中缺失的当前样本#

仍保留在数据集中，并在新列中得到 NA。

43. OTU 表编辑 — 概述#

支持单元格编辑、列添加/删除、合并、显示排序、ASV 重命名、方向声明、撤销和重置。

44. OTU 表方向#

保留 taxa_are_rows()。taxa 在行时列是样本；否则列是 taxa。

45. “ASV 在列”不是转置操作#

该开关主要用于自动重命名。单独切换不会转置矩阵，也不会立即修改 taxa_are_rows。

46. 选择错误轴的风险#

可能把样本重命名为 ASV、改变声明方向，并使 taxonomy、序列和树不同步。

47. 可编辑 OTU 表#

每个单元格可编辑，之后模块会重建数值矩阵。

48. OTU 表数值转换#

每次动作后整表转为数值。无法转换的值变为 NA 并产生警告。

49. OTU 空值#

空单元格、空格和 NA 会被报告，但不会自动替换为零。

50. 非数值 OTU 值#

如 absent、low、? 通常在数值转换时变为 NA。

51. 负数和小数#

不会阻止。表中可能包含计数、比例、转换值或 CLR，但下游方法可能不接受。

52. 向 OTU 表添加列#

taxa 在行时添加样本；taxa 在列时添加 taxon。新列初始化为 NA。

53. 添加样本的风险#

不会自动创建对应 sample_data 行，因此对象可能不一致。

54. 添加 taxon 的风险#

不会自动创建 taxonomy、参考序列或树叶。RefSeq 或树可能因覆盖不完整而被删除。

55. 结构性添加建议#

若要加入新样本或 taxa，应在 R 中重建并验证完整 phyloseq，而不是只扩展一张表。

56. 删除 OTU 列#

根据方向删除样本或 taxon。metadata 或 taxonomy 不一定自动同步。

57. 生物学删除应使用 Filtration#

Filtration 用于按明确标准删除样本或 taxa，并产生一致且有记录的子数据集。

58. ASV 自然排序#

显示时按 ASV1、ASV2、ASV10 排序，不改变内部顺序。

59. 排序状态下编辑#

模块会把显示行映射回原始标识符，确保修改正确元素。

60. 将文件合并到 OTU 表#

自动检测分隔符，使用 rownames，寻找共同的行，并只添加新列。

61. 导入列的含义#

取决于当前方向；模块不会判断这些列是样本还是 taxa。

62. OTU 合并文件中的额外行#

会被忽略，不会创建新标识符。

63. 文件中缺失的当前行#

这些行在新列中保持 NA。

64. 自动重命名 ASV#

结合前缀、声明的 ASV 轴和当前标识符。

65. 保留末尾数字#

若每个标识符都以唯一数字结尾，则保留数字，例如 ASV128 变为 Feature128。

66. 顺序重命名#

只要有一个标识符没有可用末尾数字，就会按内部顺序对全部标识符顺序重命名。

67. 新名称冲突#

若生成名称不唯一，则使用顺序命名作为后备。

68. 前缀验证#

只去除首尾空格。建议使用简单前缀：ASV、OTU、ZOTU 或 Feature。

69. ASV 重命名传播#

旧标识符唯一时，新名称会传播到 tax_table、refseq 和树叶。

70. 重命名前存在重复标识符#

传播会被禁用，结果可能仍不一致。应先在上游修复重复名称。

71. OTU 修改后重新对齐序列#

无名称且数量一致时按顺序命名；完整命名序列会重新排序。若有 taxon 缺少序列，则整个 refseq 被删除。

72. OTU 修改后重新对齐树#

额外叶子会被修剪。若任一 OTU taxon 不在树中，则整个树被删除。

73. 缺少 ape 包#

OTU 修改时若 ape 不可用，树会被删除并记录警告。

74. 结构性 OTU 修改后的 taxonomy#

ASV 重命名时会显式传播，但其他结构修改不保证同步。之后必须检查标识符。

75. 分类编辑 — 概述#

作用于 tax_table(ps)：单元格、rank、文件合并、自动替换、撤销和重置。

76. 缺少 taxonomy#

若没有分类表，应使用完整组件导入添加。

77. 第一次分类编辑前确认#

第一次尝试只显示说明窗口，不执行动作。关闭窗口后需再次执行。

78. 切换数据集后再次确认#

选择数据集变化时确认状态会重置。

79. 编辑分类单元格#

值作为文本保存，不进行命名法或分类学验证。

80. 不检查分类层级#

不会验证 species、genus、family 之间的一致性或科学名称有效性。

81. 添加分类 rank#

在末尾添加全 NA 新列，名称必须严格、有效且唯一。

82. Rank 顺序#

不强制分类顺序，需要手动保持一致。

83. 重命名分类 rank#

没有直接按钮。可新增 rank、迁移值、删除旧 rank，或在 R 中完成。

84. 删除 rank#

使用准确名称立即删除；可能显示建议。

85. 删除所有 rank#

没有通用保护。若要移除全部 taxonomy，应使用完整组件删除。

86. 按 ASV 对 taxonomy 排序#

自然排序只影响显示，并使用标识符中第一段数字。

87. ASV 重命名后的同步#

当 taxonomy rownames 变化且行数相同，本地状态会更新并添加同步日志。

88. 分类同步限制#

若完整替换但标识符不变，本地显示值可能不刷新。切换数据集后返回。

89. 将文件合并到 taxonomy#

只添加缺失 rank 列，共同 taxa 写入值，其余为 NA。

90. 不自动检测 taxonomy 分隔符#

必须手动选择。

91. 已存在的分类列#

合并不会替换已有 Genus 等 rank。要替换整表，应完整导入。

92. 自动替换分类值#

可将 NA、unidentified、unclassified、unknown、missing 等模式替换为统一文本。

93. 不区分大小写的精确匹配#

模式会去除首尾空格并转小写，然后进行精确比较，不是宽泛子字符串搜索。

94. NA 模式#

同时匹配真实缺失值和文本形式的 NA。

95. 空模式#

匹配空字符串或仅包含空格的字符串。

96. 替换范围#

同时作用于所有 taxonomy rank，不能只选一列。

97. 强制预览#

确认前显示总单元格数、按模式和按列的计数。

98. 重叠模式#

一个单元格可匹配多个模式，因此各模式计数可能重叠。

99. 替换值不能为空#

不允许使用空字符串作为替换值。

100. 替换的科学影响#

把 NA 改为 Unassigned 会把缺失信息变成真实类别，从而改变完整度、聚合和图形。

101. 未分配 taxon 的聚合#

具有相同文本的 taxa 可能被 tax_glom() 合并，这与真实缺失值不同。

102. 初始 taxonomy 状态与重置#

本地编辑器加载数据集时重新捕获初始状态，因此切换数据集可能改变重置基准。

103. 导入、导出和删除 — 概述#

此区域管理完整组件：metadata、OTU、taxonomy、RefSeq 和树。

104. 自动导入#

选择文件后立即开始，没有额外确认按钮，也没有统一预览。

105. 文件大小限制#

使用 BarCodeR 全局上传限制，目前约 500 MB。

106. 完整导入的分隔符检测#

主要检查第一行：优先分号，其次制表符，否则逗号。比合并时的检测更简单。

107. 完整导入 metadata#

第一列是标识符。未知样本会导致拒绝；缺失的当前样本补 NA。旧 metadata 整体替换。

108. 完整导入 OTU 表#

解释为 taxa 在行、样本在列，并强制 taxa_are_rows = TRUE。

109. OTU 导入允许的标识符#

文件中的 taxa 和样本必须是现有标识符的子集，不能新增样本或 taxa。

110. OTU 导入中缺失的标识符#

当前对象中缺失于文件的样本或 taxa 用零补齐，并按当前对象顺序重排。

111. OTU 导入数值转换#

整表转为数值。无效值变为 NA，但导入可能继续并给出警告。

112. 完整导入 taxonomy#

第一列是 taxa。未知 taxa 会被拒绝；缺失 taxa 补 NA。旧表和旧 rank 被替换。

113. 导入 RefSeq#

FASTA 标识符必须匹配并完整覆盖所有 taxa。部分覆盖或未知标识符会被拒绝。

114. 导入树#

Newick 叶子必须匹配并完整覆盖所有 taxa。未知叶子或缺失 taxon 会导致拒绝。

115. 完整替换组件#

旧组件不会作为快照保存；日志只记录维度、文件和警告。

116. 完整导入后刷新编辑器#

数据集名称不变时，本地编辑器可能保留旧副本。继续编辑前应切换到其他数据集再返回。

117. 组件导出#

Metadata、OTU、taxonomy 导出为 CSV；RefSeq 为 FASTA；树为 Newick。

118. CSV 导出分隔符#

尽管扩展名为 .csv，实际使用分号 ;。

119. Metadata 导出#

从 rownames 创建 SampleID 列，缺失值导出为空单元格。

120. OTU 导出#

保留当前存储方向，文件中不明确记录 taxa_are_rows。

121. Taxonomy 导出#

Taxon 标识符写在第一列，缺失注释写为空单元格。

122. RefSeq 导出#

按当前名称写出 FASTA；需要 Biostrings。

123. 树导出#

写出 Newick；需要 ape。

124. 导出与日志#

每次导出都会向 edit_log 添加记录，因此可能把项目标记为未保存。

125. 组件删除#

窗口列出当前存在组件，可多选后确认。

126. 删除 metadata#

移除 sam_data，依赖分组或协变量的分析不可用。

127. 删除 taxonomy#

移除 tax_table，分类相关分析不可用。

128. 删除 RefSeq#

长度、GC 和序列分析不再有参考序列。

129. 删除树#

UniFrac、Faith PD 和系统发育可视化不可用。

130. 删除 OTU 表#

界面允许该操作，但它移除核心组件，使数据集在大多数模块中无法使用。

131. 同时删除多个组件#

可以删除多个 slot，即使剩余对象内部不一致。

132. 撤销组件删除#

此区域没有 Undo。必须重新导入、恢复项目或加载旧导出。

133. 删除与磁盘文件#

保存项目前，删除只作用于内存。源文件和旧备份不会被删除。

134. 在注册表中保存数据集#

名称字段可用于同名注册、创建新条目或替换现有条目。

135. 名称留空#

按当前名称重新注册，保持活动状态并添加日志；项目不会写入磁盘。

136. 可用的新名称#

创建包含当前编辑状态的新条目并设为活动。源条目仍在，但已被原地修改。

137. 名称已被其他数据集使用#

确认后，目标被编辑后的源状态完全覆盖，而源条目仍然保留。

138. 数据集名称清理#

共享 helper 会先清理名称，再检查冲突。

139. 覆盖另一个数据集#

所有表、序列、树、属性、日志和来源都会被替换，不是合并。

140. 保存完整项目#

编辑后使用 Datasets → 保存项目 将注册表持久化到磁盘。

141. 故障排查#

以下小节列出常见问题和真实原因。

141.1. 修改了错误的数据集#

选择器跟随全局活动数据集。每次动作前确认名称。

141.2. 想创建新名称但原始条目也变了#

修改发生在复制之前。恢复备份、导出或原始文件。

141.3. 保存按钮没有保存项目#

它只修改内存注册表。请在 Datasets 中保存。

141.4. Metadata 自动出现#

原数据集没有 sample_data，模块创建了最小表。

141.5. 修改 SampleID 没有重命名样本#

真实标识符是 rownames。

141.6. 数值变量变成文本#

输入了非数值。修复整列或重新导入带正确类型的 metadata。

141.7. 因子变成 character#

编辑器会压平因子。需要时在 R 中恢复 levels。

141.8. 新列类型错误#

列从 NA 开始，其类型由输入值推断。之后需检查和转换。

141.9. Metadata 合并没有更新已有列#

合并只添加缺失列。应完整导入或手动编辑。

141.10. 没有找到共同标识符#

检查第一列、rownames 选项、大小写、空格和拼写。

141.11. 分隔符检测错误#

文件不规则时应手动选择。

141.12. OTU 值变为 NA#

数值转换因文本、符号、空格或小数逗号失败。

141.13. 小数逗号变成 NA#

预期小数点为句点，应先修正文件。

141.14. 新 OTU 列使 metadata 不同步#

样本只加入 OTU。应添加对应 metadata 或重建对象。

141.15. OTU 修改后 RefSeq 消失#

它不再覆盖全部 taxa。

141.16. OTU 修改后树消失#

缺少 taxon、重命名未传播，或 ape 不可用。

141.17. 树叶消失#

OTU 中不存在的额外叶子会自动修剪。

141.18. 样本被重命名为 ASV#

声明了错误轴。恢复副本或备份。

141.19. ASV 前缀产生异常名称#

前缀不严格验证，应使用简单前缀。

141.20. Taxonomy 与 OTU 不再匹配#

检查 rownames、重复标识符并刷新编辑器；在 R 中比较标识符集合。

141.21. 第一次分类修改没有执行#

第一次只打开警告窗口，需要再次执行。

141.22. 分类替换修改了多个 rank#

替换作用于所有列，应查看按 rank 的预览。

141.23. NA 现在被当成真实类别#

缺失值被文本替换，可能在聚合时被视为已注释分类。

141.24. 分类合并没有替换 Genus#

该 rank 已存在；合并只添加缺失 rank。

141.25. 未自动检测 taxonomy 分隔符#

此编辑器要求手动选择。

141.26. 完整导入删除了列#

它替换整个组件。恢复备份或使用合并进行增量添加。

141.27. 完整 OTU 导入改变方向#

它总是强制 taxa 在行。

141.28. 完整导入拒绝新样本#

标识符必须已存在。需要重建完整 phyloseq。

141.29. 完整导入拒绝新 taxa#

Rownames 必须属于 taxa_names(ps)。

141.30. FASTA 导入被拒绝#

检查格式、标识符唯一性、完整覆盖和 Biostrings。

141.31. 树导入被拒绝#

检查 Newick、未知叶子、缺失 taxa 和 ape。

141.32. 导入后编辑器仍显示旧表#

切换到其他数据集再返回以刷新本地状态。

141.33. 删除的旧表在编辑后重新出现#

过期本地状态可能重新写入旧副本。删除或完整导入后必须刷新。

141.34. 下载文件后项目变为未保存#

导出会写入 edit_log。

141.35. 表删除无法撤销#

组件删除区域没有 Undo。重新导入或恢复。

141.36. 删除 OTU 后数据集无法使用#

应恢复完整版本，OTU 是核心组件。

141.37. 撤销不能退回多步#

只保存一个上一步状态。

141.38. 重置不能回到原始文件#

它回到本地编辑器加载时捕获的状态。

141.39. 其他语言界面中日志仍为法语#

内部审计文本以法语存储。

141.40. 导出后动作总数增加#

导出被记录为动作。

142. 编辑前检查清单#

  • 确认当前项目和数据集。
  • 复制原始数据集。
  • 保存项目并导出重要数据。
  • 检查组件和 OTU 方向。
  • 关闭可能写入同一项目的其他会话。

143. Metadata 编辑前检查清单#

  • 检查 rownames，不要与 SampleID 列混淆。
  • 记录类型、因子、日期和缺失值。
  • 使用有效列名。
  • 编辑后重新检查类型。

144. OTU 编辑前检查清单#

  • 检查 taxa_are_rows 和 ASV 轴。
  • 确认丰度性质和无文本值。
  • 结构修改前检查 metadata、taxonomy、RefSeq 和树。
  • 批量重命名前导出。

145. 分类替换前检查清单#

  • 检查模式、大小写和空格。
  • 查看每个 rank 的计数。
  • 理解 NA 与文本类别的区别。
  • 预估聚合影响。
  • 保存原 taxonomy。

146. 完整导入前检查清单#

  • 检查数据集、分隔符、第一列、标识符和覆盖度。
  • 备份旧组件。
  • 明确它会被替换。
  • 之后刷新编辑器并在 Description 中验证。

147. 删除组件前检查清单#

  • 导出组件并保存项目。
  • 检查依赖模块。
  • 除特殊情况外不要删除 OTU。
  • 记住没有 Undo。

148. Data Edition 后检查清单#

  • 打开 Description 检查维度、总和、类型、缺失值、taxonomy、RefSeq 和树。
  • 检查标识符一致性并阅读日志。
  • 在 Datasets 中保存项目。

150. 当前限制#

  • 修改立即生效，原始版本不会自动保留。
  • 保存按钮不会持久化项目。
  • 撤销只保存一步，重置依赖本地加载。
  • Metadata 可能自动创建。
  • 因子和特殊类可能丢失。
  • ASV 开关不是转置命令。
  • OTU 编辑可能使组件不同步。
  • 分类替换作用于所有 rank。
  • 完整导入没有预览且不能扩展标识符。
  • 本地编辑器可能显示旧副本。
  • 导出会修改日志。
  • 可以删除 OTU 表。
  • 每次动作后不会运行完整一致性保护。

151. 推荐流程#

  1. 保存项目并复制原始数据集。
  2. 编辑副本。
  3. 检查 OTU 方向。
  4. 编辑 metadata 并验证类型。
  5. 仅在必要时编辑 OTU。
  6. 结构修改后检查 taxonomy、RefSeq 和树。
  7. 使用分类预览。
  8. 完整导入或删除后刷新。
  9. 在 Description 中验证。
  10. 保存项目并导出最终数据集。
