OpenMetaBar — 方法指南

1. 总体介绍#

OpenMetaBar 选项卡用于从 FASTQ 文件启动并监控完整的宏条形码（metabarcoding）数据处理流程。

分析并不是直接在 Shiny 应用中执行。BarCodeR 负责准备、提交和监控：

  1. 用户选择分析的生物学和技术背景；
  2. 选择 FASTQ 文件、实验设计文件和参考数据库；
  3. BarCodeR 检查文件并准备传输；
  4. 用户配置集群资源和流程参数；
  5. BarCodeR 为本次运行创建隔离目录；
  6. 应用内置的 OpenMetaBar 流程被复制到集群；
  7. 检查或安装所需的 Singularity 镜像；
  8. 提交 Slurm 作业；
  9. 应用持续监控执行状态并检测生成的文件；
  10. 最后可将 phyloseq 对象导入 BarCodeR。

OpenMetaBar 支持多种技术和分析路线：

  • Oxford Nanopore Technologies（ONT）；
  • PacBio；
  • Illumina；
  • LotuS3；
  • NextITS；
  • IDMABIO 报告路线。

2. OpenMetaBar 会做什么，不会做什么#

2.1. 自动完成的工作#

OpenMetaBar 可自动完成：

  • 工作目录准备；
  • 文件初步验证；
  • 本地文件传输；
  • 在 design file 中重写 FASTQ 路径；
  • 生成 Nextflow 配置；
  • 准备 Slurm 资源；
  • 部署流程；
  • 管理 Singularity 镜像；
  • 提交作业；
  • 监控 Slurm 状态；
  • 检测结果；
  • 导入 phyloseq 对象。

2.2. 仍由用户负责的内容#

应用无法自动判断：

  • 所选 marker 是否真正对应实验使用的引物；
  • 输入的预期长度是否具有生物学合理性；
  • 参考数据库是否适合该 marker 和研究对象；
  • 质量阈值是否适合所用测序技术；
  • 编码序列过滤是否适用；
  • 聚类或去噪方法是否符合研究目标；
  • 分类学参数能否提供足够可靠的鉴定；
  • 请求的 Slurm 资源是否适合数据规模。

重要原则 — 应用提供的默认值不等于通用推荐值。

3. 推荐操作流程#

建议按以下顺序操作：

  1. 检查或建立集群连接。
  2. 定义分析背景。
  3. 验证背景。
  4. 选择 FASTQ、design file 和参考数据库。
  5. 必要时创建或修正 design file。
  6. 验证文件并准备传输。
  7. 配置运行和 Slurm 资源。
  8. 验证通用配置。
  9. 配置所选路线专用参数。
  10. 检查可选预览。
  11. 启动分析。
  12. 查看步骤和执行日志。
  13. 检查结果。
  14. 将 phyloseq 导入 BarCodeR。
  15. 从历史记录管理运行。

验证分析背景不要求连接集群。但浏览远程文件、传输文件、检查远程目录、检测 Slurm 分区、准备容器、提交和监控运行以及查看历史记录都需要有效连接。

4. 选择分析路线#

组合 测序技术 + marker + 分析引擎 决定执行哪个子流程。

4.1. 可用路线#

技术 Marker 可用引擎 主路线
ONT COI LotuS3 标准 ONT
ONT 16S LotuS3 标准 ONT
ONT 18S LotuS3 标准 ONT
ONT COI-idmabio LotuS3 + IDMABIO ONT IDMABIO
ONT 16S-idmabio LotuS3 + IDMABIO ONT IDMABIO
ONT 18S-idmabio LotuS3 + IDMABIO ONT IDMABIO
PacBio 16S LotuS3 PacBio 16S
PacBio ITS LotuS3 或 NextITS PacBio ITS
PacBio LSU LotuS3 或 NextITS PacBio LSU
Illumina 16S LotuS3 Illumina
Illumina ITS LotuS3 Illumina
Illumina LSU LotuS3 Illumina

只有应用识别到兼容的 biglogin 集群连接时，才会显示 -idmabio 变体。

4.2. 路线选择的影响#

背景会决定：

  • 是否显示 MiniBar；
  • 是否允许 NextITS；
  • 显示哪些参数；
  • 哪些 Singularity 镜像为必需；
  • 执行哪些流程步骤；
  • 可生成哪些输出。

验证后如果修改技术、marker 或引擎，背景会失效，相关步骤必须重新检查。

5. 连接集群#

5.1. 打开连接窗口#

选项卡顶部按钮显示连接状态：

  • 集群未连接：没有活动 SSH 连接；
  • 连接已建立但需检查：SSH 已连接，但部分集群前置条件尚未确认；
  • 集群已连接：连接和主要必需命令均已检测到。

点击按钮可打开连接窗口。

5.2. 需要提供的信息#

连接需要服务器地址、SSH 端口、用户名以及必要时的密码。如果已配置并可使用 SSH 密钥认证，密码可以留空。

5.3. 自动检查#

连接后，BarCodeR 会检查 Bash、find、tar、sbatch、squeue、sacct、scancel、sinfo、Rscript、可用 Slurm 分区以及时间、内存和 CPU 限制。

因此，SSH 连接成功并不一定意味着集群已经满足运行 OpenMetaBar 的条件。

5.4. biglogin 情况#

在支持的基础设施上，应用可以直接连接，也可以在直接连接不可用时通过 bigm9 中继。该过程由应用自动管理。

5.5. 运行期间断开连接#

断开应用不会取消 Slurm 作业。作业提交后会继续在集群运行。重新连接到同一集群、使用兼容的根目录并具备相应权限后，可从历史记录恢复该运行。

6. 定义分析背景#

第一个配置卡决定流程路线。

6.1. 测序技术#

Oxford Nanopore Technologies

选择 ONT 会显示 COI、16S 和 18S，可在兼容环境中显示 IDMABIO 变体，显示 MiniBar，并使用 ONT + LotuS3 路线。

PacBio

选择 PacBio 会显示 16S、ITS 和 LSU。ITS/LSU 可选择 LotuS3 或 NextITS；MiniBar 隐藏；使用 PacBio 专用路线。

Illumina

选择 Illumina 会显示 16S、ITS 和 LSU，使用 LotuS3，隐藏 MiniBar，并根据 design file 支持单端或双端文件。

6.2. Marker 或目标区域#

Marker 用于选择路线、建议数据库类型、建议 NextITS 区域、识别 IDMABIO 变体并调整可见参数。它不会验证 design file 中的引物是否真正扩增该 marker。

Marker 建议数据库类型
COI BOLD
16S SILVA
18S PR2
ITS UNITE
LSU SILVA

建议只会更改声明的数据库类型，不会自动选择新的 FASTA 文件。

6.3. 参考数据库类型#

可选 BOLD、SILVA、PR2、UNITE、NCBI nt 和自定义。声明类型主要用于告诉流程如何解析 FASTA 头并构建分类学映射。

声明类型与实际选中的 FASTA 是两个独立信息，必须一致。把个人 FASTA 声明为 BOLD 并不会使它成为 BOLD 数据库。

6.4. 分析引擎#

仅在 PacBio + ITS 或 PacBio + LSU 时显示。可选 LotuS3 和 NextITS。其他情况下该选择器隐藏且不影响路线。

6.5. 验证背景#

点击 验证背景 后才能选择文件。随后修改技术、marker 或引擎会再次锁定该步骤。

7. 选择运行文件#

验证背景后，选择运行文件 按钮可用。必须定义 FASTQ、design file 和参考数据库；NextITS 还需要嵌合体数据库。

7.1. 选择 FASTQ#

本地来源

本地 FASTQ 通过应用文件浏览器选择。它们不是普通的网页上传：BarCodeR 使用真实路径，然后传输到集群。

因此不受常规 Shiny 上传大小限制，但在传输完成前文件必须保持可访问。

集群来源

文件也可以已经存在于集群上，可通过输入路径或远程浏览器选择。需要活动 SSH 连接。

一个或多个 FASTQ

应用可接受多个文件，并保持独立，不自动拼接。会保留文件名，因此不同目录下同名文件会冲突。

有问题的示例：

/run1/sample.fastq.gz
/run2/sample.fastq.gz

预期扩展名：.fastq、.fastq.gz、.fq 或 .fq.gz。

已拆分样本的 FASTQ

如果每个文件已经对应一个样本，ONT 应关闭 MiniBar，design 每行一个样本，并映射到正确文件。

未拆分的 FASTQ

如果一个文件包含多个带 barcode 的样本，启用 MiniBar，并为每个样本填写 barcode 和引物。多行 design 可以指向同一个 FASTQ。

7.2. 选择 design file#

Design file 可以来自本地、集群，或通过内置编辑器创建/修改。支持 TSV 和 CSV。

流程要求的列

列 用途
Sample_ID 唯一样本标识符
fastq_path 一个或多个 FASTQ 路径
barcodeF Forward barcode
barcodeR Reverse barcode
primerF Forward primer
primerR Reverse primer

即使不使用 barcode，这些列也必须存在。根据流程要求，可以用明确的 NA 而不是空单元格。

注意 — 编辑器可能认为两列表格“可编辑”，但完整流程验证要求上述六列。编辑器显示“结构一致”并不保证启动时通过验证。

样本标识符

必须非空、唯一，建议只使用 A-Z、a-z、0-9、.、- 和 _。

自动修正会转写重音字符、替换无效字符、清理首尾分隔符并为重复名称添加后缀。大小写会保留。

路径列

第二列必须被识别为路径列。支持 path、fastq_path、filepath、file_path、input_dir、directory、dir、folder。为避免歧义，建议直接使用 fastq_path。

启动前该列会被统一命名为 fastq_path，并重写为远程运行目录中的路径。

双端文件

Illumina 双端数据可在 fastq_path 中用逗号分隔两个文件：

sample_R1.fastq.gz,sample_R2.fastq.gz

两个文件都必须已选择，名称必须完全一致。

Design 与 FASTQ 的一致性

Design 中引用的每个文件必须匹配已选择文件名。扩展名、大小写、后缀或拼写差异都会导致错误。

单一 FASTQ 情况

如果所有行都指向同一个原始文件，应用可以重写路径，使所有样本使用同一个远程 FASTQ，常用于 MiniBar 前。

7.3. Design 中的引物#

primerF 和 primerR 用于方向校正。必须按 5′→3′ 输入，使用有效 IUPAC 核苷酸字符且不含空格。支持简并碱基。

启用方向校正时，每个 FASTQ 必须对应唯一一对引物。找不到引物、多对不同引物对应同一 FASTQ，或包含非法字符都会报错。

7.4. Design 中的 barcode#

MiniBar 使用 barcodeF 和 barcodeR。如果 barcode 彼此过近且允许较多错误，样本误分配风险会增加。

7.5. 选择参考数据库#

数据库可以是本地或远程的兼容 FASTA（.fa、.fna、.fasta、.fas，也可 gzip 压缩）。

它用于生成清理后的 FASTA、从头信息提取分类学表并执行分类学注释。

应检查：marker 匹配、字母表正确、标识符唯一、头信息含可用分类学信息、声明类型匹配，并且集群可读取。

8. 使用 design 编辑器#

8.1. 编辑单元格#

可直接编辑。每次修改后，应用会重新检查最小结构、路径列、样本名和 FASTQ 对应关系。

8.2. 添加或删除行#

可以添加行或批量删除。完全空白的行在保存时被忽略，但会产生警告。

8.3. 添加、重命名或删除列#

支持三种操作，至少保留两列。完整 design 必须包含 Sample_ID、fastq_path、barcodeF、barcodeR、primerF、primerR。

8.4. 修正样本名称#

按钮会清理字符、防止空名称并保证唯一。必须复核，因为这些名称会进入结果和 phyloseq。

8.5. 从 FASTQ 生成 design#

仅在 MiniBar 关闭时可用。应用初始生成 SampleID 和 path。

这还不是完整 design。需要重命名为 Sample_ID 和 fastq_path，添加另外四列并填写所需值。

8.6. 保存 design#

检测到结构错误时不能保存。保存后会用临时本地文件 design_edite.tsv 替换当前选择。完整流程验证在启动时进行。

9. 验证并准备文件#

验证并传输 需要活动连接。该步骤检查文件选择、存在性、FASTQ 开头、design 的部分问题、样本名和远程磁盘空间；将本地文件传到暂存区，并保留远程文件路径。

磁盘空间检查是预防性的，在某些系统上可能只是估算。完成后主按钮显示 文件已准备好。

10. 配置运行和集群#

10.1. 运行根目录#

每次运行都会在该根目录下创建唯一子目录。用户需要创建、写入、执行、读取和清理权限。内置流程被复制到运行目录，并按清理逻辑删除。

10.2. Slurm 分区#

如果 sinfo 可用，应用会显示检测到的分区。分区影响资源、最长时间、优先级和账户限制。可见不代表有权使用。

10.3. LotuS3 内存#

内存必须带单位，例如 16G、70G、120G。不要只输入 70，Slurm 可能把它解释为约 70 MB。

过小可能导致 OUT_OF_MEMORY，过大可能增加排队时间。

10.4. LotuS3 CPU 核数#

该值控制 Slurm CPU、LotuS3 线程和部分子进程资源。更多 CPU 不保证线性加速，也可能更难调度。

10.5. 容器模块#

必须与提供 Singularity 或 Singularity-CE 的模块名完全一致，例如 singularity-ce/4.1.0。

10.6. Nextflow 模块#

指定 Nextflow 版本，例如 nextflow/25.10.4。不存在或不兼容的模块会阻止启动。

10.7. 运行名称#

用于识别目录、Slurm 作业和历史记录。应用会自动添加日期、会话标识和随机后缀。避免过长、特殊字符和敏感信息。

10.8. 保留中间文件#

调试选项会在成功后保留 work/。它有助于检查命令和诊断，但可能非常大。失败后中间文件本就会保留。之后可从历史记录清理。

11. 理解初始值#

应用初始值主要针对 ONT + COI：方向校正开启、长度过滤开启、长度 658、最低质量 20、编码过滤开启、翻译表 5。

这些值不自动适合 16S、18S、ITS 或 LSU。至少应重新检查编码过滤、长度、遗传密码、扩增子类型和分类群。

首次修改某些参数时会提示初始值已优化。这只表示存在受控初值，不表示适用于所有实验方案。

12. MiniBar 拆分 — ONT 路线#

12.1. 启用或关闭 MiniBar#

一个 FASTQ 中含多个 barcode 样本且 design 信息完整时启用。MiniBar 会生成每样本 FASTQ 和拆分/保留 reads 指标。未知或歧义 reads 不会作为已分配样本发布。

文件已按样本拆分或上游已完成拆分时关闭。

12.2. 识别方法 — M#

方法 1、2、3 直接作为 -M 传给 MiniBar，改变基于 barcode 和引物的内部分配策略。

应用没有说明算法差异。应保持已验证的方法；比较的批次之间不要无理由改变；修改后检查指标。

12.3. Barcode 最大错误数 — e#

低值提高特异性但可能丢失有测序错误的 reads；高值可恢复更多错误 barcode，但更容易混淆相似 barcode。0 要求完全匹配。

12.4. 引物最大错误数 — E#

较高容差可恢复更多噪声 reads，但可能增加非特异匹配；较低容差更严格，但可能删除有效 reads。

12.5. MiniBar 参数 — l#

界面将其描述为搜索窗口，而流程 schema 描述为最小 read 长度。该值直接传给 -l。

由于定义不一致，在没有验证过的值时建议留空，不要随意解释，并比较修改前后的拆分指标。

13. 扩增子方向校正#

13.1. 单端 reads#

流程寻找引物、检测两个方向、将序列转为 primerF → primerR、去除引物并保留内部区域。缺少完整引物对的 reads 被删除。

13.2. 非简并和简并引物#

引物只含 A/C/G/T 时，目前最多允许一个差异。含简并 IUPAC 字符时使用简并模式匹配，不启用额外差异模式。

13.3. 双端 reads#

FASTQ 对会跳过方向校正，并报告 SKIPPED_PAIRED_END。因此该步骤不会对双端 reads 重定向或去除引物。

13.4. NextITS 路线#

NextITS 有自己的 ITS 区域和引物处理，因此通用方向步骤并非以相同方式应用。

13.5. 何时关闭方向校正#

如果引物已经去除、所有序列方向一致，或上游流程保证了方向，则可关闭。

14. 过滤顺序#

过滤是累积的，顺序为：质量、长度、编码。每一步只接收前一步保留的 reads。多个中等严格条件叠加后可能极其严格。没有 reads 时流程停止。

15. 长度过滤#

15.1. 启用和输入#

关闭时输入长度不生效。启用时输入一个或多个逗号分隔整数，例如 480 或 450,550。

15.2. 实际区间#

流程对每个长度使用 ±100 nt 容差。

658 对应 558–758；500,800 对应 400–600 和 700–900。

15.3. 如何选择长度#

应根据引物之间的区域、过滤时是否仍含引物、生物学变异、技术和目标类群决定。658 仅属于初始 COI 背景，不应自动保留。

15.4. 空值或无效值#

当前实现可能把空值或无法解析的值静默替换为 658。启用过滤时不要留空，除非确实需要 658。

15.5. 双端 reads#

R1 和 R2 在重新配对前分别过滤。评估的是单个 read 长度，不是合并后的扩增子。250 nt reads 使用 658 会删除两端。

15.6. 重新同步#

过滤后按标识符重新配对。没有保留配对端的 read 成为 orphan。只有完整配对继续。

16. 质量过滤#

最低阈值传给 SeqKit。高值更严格、reads 更少；低值保留更多深度，也保留更多噪声。应根据技术、测序代次和上游预处理选择。

双端数据对 R1、R2 分别过滤，再同步。只删除一端时，另一端成为 orphan。

17. 编码序列过滤#

该过滤保留至少一个阅读框可按所选遗传密码翻译且无内部终止密码子的 reads，并测试当前方向的三个阅读框。

主要适用于 COI 等编码区，通常不适合 16S、18S、ITS、LSU。若方向校正关闭，反向的编码序列可能被拒绝。

值 遗传密码表
1 标准密码表
2 脊椎动物线粒体
5 无脊椎动物线粒体
11 细菌、古菌和质体

表 5 是针对无脊椎动物线粒体 COI 的初始建议，但并不适用于所有 COI 或其他 marker。

双端数据在同步前分别过滤两端。如果每个 read 只覆盖编码区的一部分，需要谨慎解释。

18. LotuS3 — 聚类与分类注释#

除 PacBio ITS/LSU 使用 NextITS 作为主引擎外，其他路线均显示 LotuS3 参数。

18.1. 平台#

可选 auto、PacBio、454、miSeq、hiSeq。auto 时 BarCodeR 不强制赋值。显式值会改变内部策略，必须与技术和预处理一致。

18.2. 扩增子类型#

可选 SSU、LSU、ITS、ITS1、ITS2、custom。应对应实际扩增区域，而不是仅对应项目的宽泛 marker 名称。

18.3. 分类群#

可选 auto、bacteria、fungi、eukarya。显式值会指导部分分类决策。异质样本或未验证情形宜使用 auto。

18.4. 聚类或去噪#

可选 UPARSE、Swarm、CD-HIT、UNOISE、DADA2、VSEARCH。不同方法不一定产生相同生物学单位，可能改变单位数量、丰度、稀有序列敏感度和错误处理。不同方法的结果不能直接视为等价。

18.5. 分类学工具#

可选 RDP classifier、BLAST、Lambda、UTAX、SINTAX、VSEARCH、USEARCH。选择会影响算法、速度、灵敏度、远缘序列处理和可用得分。

18.6. RDP 置信阈值#

仅在 RDP_classifier 时显示。高值更严格但未分类更多；低值分类更多但稳健性可能下降。

18.7. 保留未分类单位#

0 删除，1 保留。保留有助于研究未知多样性和后续重新注释，但后续分析需要明确处理。

18.8. 分类排除#

输入模式用于排除分类群。过宽表达式可能删除大量结果。应检查数据库用词、测试模式并记录排除规则。

19. 保存拆分后的 reads#

模式 效果
0 不发布专门的拆分 FASTQ
1 保留所有未过滤的拆分 reads
2 保留拆分 reads 后停止流程
3 保留质量过滤后的拆分 reads

如果期望 phyloseq 或完整分析，不要使用模式 2。模式 1 和 3 会增加磁盘占用，但便于检查和复用。

20. LCA 与高级分类#

20.1. 分类模式#

反直觉约定：0 启用 LCA；1 使用最佳 BLAST hit。

LCA 寻找多个兼容 hit 的共同祖先，通常更保守。最佳 hit 表面上更精确，但更易受错误参考、不平衡数据库或近似等价 hit 影响。

20.2. 最低覆盖度#

范围 0–1。高值要求序列大部分对齐；低值接受部分匹配。短片段高 identity 不等同于整个扩增子高 identity。

20.3. 各分类等级 identity 阈值#

初始示例 97,95,93,91,88,78。它们不是 identity 与分类等级之间的通用映射。差异取决于 marker、类群、数据库和区域长度。修改会直接改变可接受的分类深度。

20.4. 一致比例#

高值要求更强共识，可能返回更高分类等级；低值允许较少一致，冲突可能增加。

20.5. 系统发育树#

0 不建树；1 FastTree；2 IQ-TREE 2。建树增加计算量并要求可用比对，IQ-TREE 2 通常更耗资源。

20.6. 最大 read 重叠#

主要用于短双端 reads。应与 read 长度、扩增子长度和 R1/R2 理论重叠一致。

21. 标准 ONT 路线#

适用于 ONT + COI、16S 或 18S。

根据设置可执行 design 验证、MiniBar、每样本 FASTQ、方向校正、过滤、映射准备、LotuS3、分类和报告。

COI 应检查真实长度、引物、目标生物、遗传密码、编码过滤和数据库。16S/18S 通常应关闭编码过滤，替换或关闭 658，并选择正确扩增子类型、类群和数据库。

22. ONT IDMABIO 路线#

适用于 COI-idmabio、16S-idmabio、18S-idmabio。仅在识别到兼容集群时出现。由 marker 后缀触发，而不是分析引擎选择器。

它在 ONT 步骤基础上增加 ZOTU hit 验证、IDMABIO 输出、MAFFT 比对和 Word 报告。

22.1. 基因类型#

可选 auto、coding、non-coding。auto 时 COI 视为编码，其他视为非编码。显式选择会覆盖推断。

22.2. 保留的 BLAST hits#

定义最多保留多少 hits。高值增加信息、文件大小和可能的处理时间；低值可能隐藏有用次级 hits。

22.3. 每样本比对数#

控制输出中显示多少比对，不等于总保留 hit 数。

22.4. 报告语言#

可选法语或英语，控制生成的 Word 报告。

23. PacBio + LotuS3 路线#

适用于 PacBio + 16S，或 PacBio + ITS/LSU 且选择 LotuS3。MiniBar 不使用。

如果启用方向校正，应确认 reads 仍含引物；长度应匹配实际 reads；16S/ITS/LSU 应关闭编码过滤；质量阈值应适合校正后的 PacBio reads。

随后配置平台、扩增子类型、类群、聚类方法、分类工具和 LCA。

24. PacBio + NextITS 路线#

仅适用于 PacBio + ITS 或 LSU 且选择 NextITS。

该路线执行验证、启用的预过滤、NextITS、ITSx、校正与聚类、嵌合体检测、专用 LotuS3 分类、phyloseq 生成和汇总。

24.1. ITS 区域#

可选 ITS1、ITS2、LSU、SSU、ALL。LSU 会建议 LSU，ITS 初始建议 ITS1，但不代表真实扩增区域已验证。

24.2. ITSx 类群#

可选 all、fungi、tracheophyta、metazoa。过窄的类群可能不适合异质环境样本。

24.3. NextITS 聚类#

可选 UNOISE、VSEARCH、Swarm。会改变聚类或去噪；不同方法输出不应视为完全相同。

24.4. UNOISE 选项#

启用单独的 UNOISE 去噪步骤，与通用方法选择器不同。

24.5. 同聚物校正#

启用 homopolymer polishing。它会改变序列；用于比较的运行应保持一致。

24.6. 嵌合体数据库#

可本地或远程，必须存在、可读、格式正确并匹配类群和区域。初始建议路径可能只适用于开发环境，应明确重新选择。

24.7. 引物一致性#

路线期望一致的引物对。同一运行中使用不同引物对可能报错或产生非预期行为。

25. Illumina + LotuS3 路线#

适用于 Illumina + 16S、ITS 或 LSU。

Design 中单端使用一个文件，双端使用逗号分隔两个文件。双端会跳过方向步骤，因此该步骤不去除引物。

质量、长度、编码过滤分别作用于 R1/R2，再同步。长度过滤不是针对合并扩增子。配对端被删除时，另一端成为 orphan。

16S/ITS/LSU 通常应关闭编码过滤，替换或关闭 658，并检查扩增子类型、类群和数据库。

26. Design 与目标路径预览#

预览为可选，初始关闭。会显示运行名、示例 Run ID、design、未来目录、FASTQ 目标、重写后的 design 路径、配置、技术、marker、数据库类型和路径、分区、资源和 Singularity 缓存。

预览显示初始 design；路径只在启动时重写。

27. 生成配置预览#

显示根据表单构建的 Nextflow overlay：路径、启用参数、数值、LotuS3、IDMABIO、NextITS 参数和 Singularity 目录。

文件可能包含其他路线的参数，并不表示都会使用。但 nf-schema 会验证发出的值，因此无效值可能在任何进程启动前阻止运行。

28. 启动前检查#

背景#

  • 技术正确；
  • marker 与引物一致；
  • 引擎正确；
  • 数据库类型与 FASTA 一致。

FASTQ#

  • 所有文件已选择；
  • 没有重复文件名；
  • 扩展名正确；
  • R1/R2 顺序正确。

Design#

  • 六列齐全；
  • 标识符唯一；
  • 路径完全一致；
  • 引物为 5′→3′；
  • MiniBar 开启时 barcode 完整；
  • 引物对一致。

过滤#

  • 长度适当；
  • 编码过滤适用；
  • 遗传密码正确；
  • 质量阈值适合；
  • 方向设置兼容。

集群#

  • 连接为绿色；
  • 目录可访问；
  • 分区可用；
  • 内存带单位；
  • 模块存在；
  • 磁盘空间足够。

NextITS#

  • 嵌合体数据库存在；
  • 区域正确；
  • ITSx 类群适合；
  • 引物一致。

29. 启动时发生什么#

BarCodeR 重新读取背景，检查 FASTQ，阻止同名文件，重新检查 design、样本名和数据库，创建 Run ID，建立 results/、work/、meta/，重写 design，整理 FASTQ，传输文件，准备镜像，解压流程，生成配置和 Slurm 脚本，写入元数据，使用 sbatch 提交，获取 Job ID 并启动监控。

如果当前会话已监控另一个运行，会要求确认。新提交不会自动取消旧运行。

30. Singularity 镜像#

根据路线，OpenMetaBar 使用 SeqKit、LotuS3、报告、MiniBar、MAFFT、phyloseq 和 NextITS 镜像，保存在 <remote_root>/_barcoder_singularity。

应用尝试使用或复制共享镜像、准备或下载缺失镜像，并检查存在性和大小。不是所有路线都需要全部镜像：ONT 需要 MiniBar，IDMABIO 需要 MAFFT，NextITS 需要 NextITS 和 phyloseq 环境。缺失必需镜像会阻止启动。

31. 阅读运行时间线#

显示步骤：FASTQ 已选择、连接、design 就绪、远程目录、传输、Singularity 镜像、流程部署、sbatch 提交、Slurm 监控。

时间线结合本地操作、SSH、提交状态、Slurm 状态和文件检测。等待、运行、成功、警告和错误都应在具体步骤背景下解释。

32. 理解 Slurm 状态#

PENDING#

等待资源。原因可能为资源不足、优先级、分区繁忙、内存/CPU 请求过高、账户限制或依赖。修改配置前先阅读 Slurm 原因。

RUNNING#

正在执行。暂时没有新文件不一定表示卡住。

COMPLETED#

Slurm 脚本成功结束。仍需检查 Nextflow 退出码、结果、phyloseq 和报告。

FAILED#

查看错误日志、Slurm 输出、.nextflow.log、报告和历史记录。

OUT_OF_MEMORY#

内存超限。增加数值前先判断是全局内存、特定进程、LotuS3、报告还是 NextITS。

TIMEOUT#

达到最长时间。选择更合适分区、降低复杂度或申请更高限制。

CANCELLED#

被用户、管理员、规则或依赖取消。

未知或作业消失#

不再出现在 squeue 的作业可能在 sacct 中有最终状态。BarCodeR 在可能时查询两者。

33. 执行日志#

33.1. 本地操作#

包括 BarCodeR 的选择、验证、连接、建目录、传输、准备、启动和文件检测。

33.2. Monitoring#

包括 Job ID、Slurm 状态、检测到的进度、新输出、结束状态和 phyloseq 检测。

33.3. Standard output 与 standard error#

它们不是当前日志的两个主标签页，但可在历史详情、运行文件、错误预览和下载中查看。

33.4. .nextflow.log#

详细记录进程、命令、错误、恢复、工作文件和验证，是主要诊断来源。

34. 生成的结果#

根据路线可能位于：

  • Steps/files：准备文件和发布输入；
  • Steps/demultiplexing_files：拆分结果和指标；
  • Steps/filters：方向、质量、长度、编码和 orphan；
  • Steps/lotus3：LotuS3 输出；
  • Steps/nextITS：NextITS 输出；
  • Steps/lotus3_taxo：NextITS 相关分类；
  • Steps/phyloseq：NextITS phyloseq 生成/存储；
  • Steps/tax_db：清理数据库和提取分类；
  • OMB_logs：汇总、报告、timeline、trace、流程图、版本和参数；
  • final_table/idmabio_outputs：IDMABIO 表、比对和报告。

具体结构取决于路线和选项。

35. 导入 phyloseq 对象#

BarCodeR 搜索可能含 phyloseq 的 .rds、.rda 或 .RData 文件。文件名看起来像 phyloseq 不代表内容有效。

导入时，应用临时下载文件、打开、查找 phyloseq 对象、检查兼容性、必要时让用户选择，并添加所选对象。

名称根据运行、文件和对象生成并保证唯一。运行参数可以附加到对象以保留来源。

失败运行中也可能检测到 phyloseq。它可能不完整或在失败步骤之前生成。使用前应检查日志和内容。

36. 提交后的操作#

36.1. 调整后重新运行#

保留文件和参数，允许修改并准备新提交。不会取消旧运行。

36.2. 新分析 — 从头开始#

重置文件、背景、分析参数和时间线，保留连接和部分集群设置。已提交的作业继续运行并保留在历史记录。

36.3. 不重新运行#

只关闭选择面板，不取消或改变监控，可稍后重新打开。

37. 分析历史#

扫描会在配置的根目录下查找运行。结果取决于路径、权限、元数据、文件和 Slurm。

可显示 Run ID、目录、Job ID、状态、日期、时长、FASTQ 和样本数、大小、内存、CPU、phyloseq 和清理状态。

37.1. 详情与恢复监控#

详情显示参数、路径、退出码、Slurm 信息、文件和错误。恢复监控只重新连接界面，不会重新计算。

37.2. 浏览文件#

支持搜索、展开分组、预览文本最后 200 行、下载和导入 phyloseq。

37.3. 取消作业#

通过 Slurm 取消主作业和可识别的子作业。目录和已生成文件仍保留。

37.4. 清理运行#

删除中间文件，通常保留 results/ 和 meta/。该操作不可逆，能释放空间，但会删除恢复缓存和诊断材料。

37.5. 删除运行#

删除整个远程目录，包括结果、元数据、日志、中间文件和 phyloseq。操作前先备份需要的文件。

40. 解释与可重复性原则#

结果同时受原始文件、拆分、引物、过滤、聚类方法、数据库、分类算法和阈值影响。参数不同的运行不能在忽略这些差异的情况下直接比较。

为保证可重复性：

  • 保留 design file；
  • 保留数据库或其版本；
  • 保留运行参数；
  • 保留 Nextflow 报告；
  • 记录所有相对初始值的修改；
  • 保留软件版本；
  • 保留每一步的指标；
  • 不要只解释最终 phyloseq 对象。
