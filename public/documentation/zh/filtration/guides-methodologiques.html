过滤 — 方法学指南

1. 选项卡的总体作用#

过滤选项卡用于从 BarCodeR 中已加载的 phyloseq 对象构建子数据集。它可以根据分类注释删除分类单元，删除低丰度或低出现率的 ASV，根据测序深度、丰富度、名称或元数据删除样本，以及删除不满足技术条件的序列。

结果首先以临时反应式对象的形式构建：

ps_filtered

随后可在摘要中检查、以新名称保存、用于替换父数据集、在 Description 中检查、与其他数据集比较或导出。

与 Data Edition 的区别#

Data Edition 过滤
直接修改所选数据集的表 先构建临时派生对象
修改立即写入 datasets() 调参期间父数据集保持不变
适合修正单元格和结构 适合按条件删除样本或分类单元
将编辑记录到 edit_log 将过滤记录到 filtration_log

结果在保存前不会出现在 Datasets 中，其他模块无法使用，也不会写入磁盘；重新加载会话时可能丢失。

2. 自动运行方式与结果生命周期#

界面中没有应用过滤器按钮。只要活动参数发生变化，过滤就会自动重新计算，例如启用某个模块、修改阈值、选择分类值、添加元数据条件或切换数据集。

对于大型数据集，每次修改都可能重新读取 OTU 表、计算丰度与出现率、执行多个 prune_taxa() 或 prune_samples()、分析序列并重建日志和摘要。建议逐步修改参数，并等待计算完成后再继续。

调参期间父数据集保持不变#

父数据集
   ↓
反应式计算
   ↓
临时过滤结果

只有在以父数据集相同名称保存时，父数据集才会被替换。

空名称字段的风险#

保存名称默认为空。空值表示：

使用父数据集名称保存结果，并替换父数据集。

不会再弹出额外确认。为了保留原始数据，应显式输入不同名称，例如 COI_raw 和 COI_filtered。

保存只修改 BarCodeR 内存。要持久化结果，还必须使用 Datasets → 保存项目。

3. 固定的过滤顺序#

过滤始终按以下顺序执行：

1. 分类学
2. ASV 丰度
3. 样本
4. 序列

此顺序固定，与打开或设置各个框的顺序无关。

后果#

每个模块使用前一个模块的结果。例如：

  1. 删除叶绿体；
  2. 重新计算剩余 ASV 的总量和出现率；
  3. 重新计算样本 reads 和丰富度；
  4. 删除不满足条件的样本；
  5. 删除不满足技术标准的序列。

因此，样本阈值并不一定使用 Description 中显示的原始值。

只执行一次，不迭代至稳定#

最后一步之后，流程不会重新从第一步开始。因此：

  • 删除样本后，一些 ASV 的出现率可能降到阈值以下，但不会再次删除；
  • 序列过滤可能使样本 reads 或丰富度低于阈值，但不会再次应用样本条件；
  • 最终结果中可能保留零 reads 的样本或零丰度的分类单元。

第二次过滤可能因此删除比第一次更多的元素。

4. 数据集选择与参数保留#

主选择器与全局活动数据集同步。在过滤选项卡中切换数据集会更新 active_ds()，改变其他模块默认使用的数据集，并可能把项目标记为未保存。

参数不会全部重置#

切换数据集后，以下设置可能仍然保留：

  • 丰度阈值；
  • 样本阈值；
  • 序列条件；
  • 分类关键词；
  • 高级条件；
  • 保存名称。

与数据集相关的列表会更新，包括分类等级和值、样本名和元数据变量。

高级条件可能继续引用新数据集中不存在的变量，从而阻止过滤结果生成，直到该条件被修正或删除。

每次切换数据集后，在保存前都应检查全部模块。

5. 如何理解界面状态#

每个过滤模块都有颜色状态。

颜色 含义
灰色 没有活动或已修改的参数
橙色 参数已修改，但模块未启用
绿色 模块启用复选框已勾选

绿色边框不保证真正删除任何内容。例如 ASV 模块可以处于启用状态，但所有阈值均为 0；它会显示绿色，但条件是中性的。

全局提示栏会尝试识别真正设置了条件的模块，但即使没有删除任何内容，数据集仍可能获得 filtration_log。

图形预览#

阈值直方图基于所选父数据集计算，而不是逐步过滤后的对象。它们包括：ASV 总 reads、出现率、最大相对丰度、每个样本 reads、每个样本丰富度、序列长度和 GC。

阈值线用于查看初始分布，但不一定代表前面模块执行后真正使用的值。过滤前/后摘要才是最终结果的主要预览。

6. 分类学过滤#

分类学过滤需要 tax_table。它可以按某一分类等级排除值、仅保留选定值，以及删除包含关键词的注释。

默认选择的关键词#

默认已选择：

chloroplast
mitochondria

在模块启用前不会应用。但仅勾选启用过滤就可能立即删除包含这些词的分类单元。

这些词并不是通用污染物。根据标记基因和研究目标，它们可能正是目标生物信号。

按分类等级排除或保留#

对于所选等级：

  • 排除：删除值与所选值完全一致的 ASV；
  • 仅保留：保留与所选值一致的 ASV。

内部顺序为：

1. 排除
2. 保留
3. 关键词搜索

相互矛盾的规则可能删除全部分类单元。

关键词搜索#

关键词会在所有分类列中搜索，不区分大小写，按子字符串匹配，并使用 | 组合模式。

因此 chloroplast 可以匹配 Chloroplast、chloroplastidae 或 Unclassified chloroplast sequence。搜索不限于所选分类等级。

缺少分类表#

如果启用了模块但没有分类表，该模块会被跳过。其他模块仍可能生成结果。应查看真实摘要，而不是只依赖绿色状态。

7. 按丰度过滤 ASV#

有三个条件，按顺序执行：

1. 总 reads
2. 出现率
3. 最大相对丰度

这些条件假设 OTU 表中的值可解释为丰度。对于 CLR、相对丰度、对数转换、负值或已标准化矩阵，结果可能具有误导性。

每个 ASV 的总 reads#

总量 = 当前阶段所有剩余样本中的丰度之和

规则是严格大于：

总量 > 阈值

阈值为 10 时，总量等于 10 的 ASV 会被删除，总量 11 的会保留。

出现率#

出现率是丰度严格大于 0 的样本数。规则为：

出现率 ≥ 阈值

阈值为 3 时，恰好出现在 3 个样本中的 ASV 会保留。

绝对阈值必须结合样本总数解释。3 个样本在 10 个样本项目中是 30%，在 100 个样本项目中只有 3%。

最大相对丰度#

BarCodeR 对每个 ASV 在每个样本中计算相对丰度，并保留其中最大值：

最大值：ASV 丰度 / 样本总丰度 × 100

规则为：

最大相对丰度 ≥ 阈值

这可以保留总体稀少但在某个样本中很重要的 ASV。

该计算在总量和出现率过滤后执行。删除分类单元会改变分母，并机械性提高剩余分类单元的相对比例。

8. 样本过滤#

样本条件按以下顺序执行：

1. 最小 reads
2. 最小丰富度
3. 样本名称
4. 简单元数据条件
5. 高级条件

最小 reads#

在分类学和丰度过滤后重新计算：

Reads = 当前剩余分类单元丰度之和

规则包含等号：

Reads ≥ 阈值

最小丰富度#

丰富度为丰度严格大于 0 的分类单元数。规则为：

丰富度 ≥ 阈值

它可能与 Description 中父数据集显示的丰富度不同。

按样本名过滤#

名称与 sample_names(ps) 完全匹配，不支持部分匹配或忽略大小写。

  • 保留：只保留所选名称；
  • 排除：删除所选名称。

此步骤在 reads 和丰富度阈值之后执行。因此，即使某个样本被选择保留，它也可能已在前一步被删除。

简单元数据条件#

模块主要区分数值列与因子/字符列。日期、逻辑值和特殊类型可能无法在简单过滤器中正确处理。

数值变量

可用运算符为 ≥、>、≤、< 和“区间”。区间包含两端；如果输入顺序相反，BarCodeR 会自动使用较小和较大值。

默认提供的中位数或四分位数只是操作便利，不是科学推荐值。

使用保留时，缺失值通常会被删除；使用排除时，缺失值通常会被保留，因为反转前它们不满足条件。

分类变量

转换为文本后进行精确比较，区分大小写、空格和拼写。

同一条件中选择多个值时使用“或”。

缺失值通常在“保留”时被删除，在“排除”时被保留。

9. 高级元数据条件#

每个高级条件包含变量、保留/排除操作、比较或多个值，以及删除按钮。

所有条件之间使用且（AND）。

例如：

保留 Campaign = 2026
且
排除 Site = control
且
保留 Depth ≥ 50

不同变量之间不能直接使用“或”。

对于分类变量，同一行选择多个值提供内部“或”，例如 Site = A 或 B。

未识别为数值的变量会作为文本处理。日期可以作为分类值选择，但不能作为真实时间区间过滤。

不完整条件#

一个未完成的高级条件可能完全阻止临时结果生成，即使其他过滤条件都有效。必须补全或删除该条件。

10. 序列技术过滤#

技术过滤使用 refseq(ps)，可按长度、GC、模糊碱基和同聚物进行过滤，并在最后执行。

缺失或无法对齐的序列#

如果没有 refseq，该模块会跳过并在日志中记录。

BarCodeR 尝试将序列与 taxa_names(ps) 对齐：

  • 序列没有名称但数量完全相同时，假设顺序一致；
  • 有名称时按标识符匹配。

如果没有任何序列可对齐，模块会跳过。

如果覆盖不完整，有序列的 ASV 会接受评估，没有序列的 ASV 会保留且不检查。

长度和 GC 图使用更严格的对齐，因此图形可能缺失，即使过滤被部分应用。

长度#

边界包含端点：

最小长度 ≤ 长度 ≤ 最大长度

最大长度为 0 时禁用上限。如果最小值大于最大值，所有序列都可能被拒绝。

GC#

过滤器使用 A、C、G、T 计算 GC：

G + C
────────────── × 100
A + C + G + T

模糊碱基不进入分母。上下限均包含端点，中性范围为 0% 到 100%。

模糊碱基#

计数字符为：

N R Y S W K M B D H V

缺口、点和其他符号未被明确计入。

当前实现中，最大模糊数 = 0 表示禁用过滤，而不是强制要求零模糊碱基。

同聚物#

BarCodeR 查找最长的连续相同字符。AAAATCG 的最大同聚物长度为 4。

所有字符都可能被计数，包括模糊碱基和重复符号。最长连续长度小于或等于阈值时保留；0 同样表示禁用。

顺序带来的后果#

技术过滤后不会重新计算样本阈值，因此最终样本可能低于 reads 或丰富度阈值，甚至变为零 reads。

11. 防止空结果及验证边界#

如果某一步会删除全部分类单元或全部样本，BarCodeR 会停止并显示错误。

这只保证至少保留一个分类单元和一个样本，并不保证复制数足够、最终深度或丰富度达标、不存在零值，或适合统计分析。

最终结果必须在 Description 中检查。

12. 过滤日志与来源#

结果获得属性：

attr(ps, "filtration_log")

其中可包含父数据集名称、日期、过滤前后维度、描述文本、结构化参数、删除的分类单元和删除的样本。

结构化参数#

保存在：

filtration_log$params

包括启用模块、分类等级、排除/保留值、关键词、丰度阈值、名称过滤、元数据条件和序列参数。

这是复现和审计过滤过程最可靠的来源。

日志语言#

日志文本使用计算时的活动语言保存，之后不会自动翻译。

“活动模块”列目前会在文本日志中查找部分法语表达式，因此对于使用其他语言过滤的数据集可能显示 —。结构化参数更可靠。

删除元素表#

removed_taxa 和 removed_samples 使用所有过滤之前父数据集的指标。

例如，一个样本在分类学过滤后只剩 800 reads 而被删除，但删除样本表中可能仍显示原始的 5,000 reads。

这些表不一定为每一项提供精确删除原因；日志步骤主要记录总体影响。

连续过滤#

新一轮过滤会替换旧的 filtration_log，不会自动堆叠历史。

建议用不同名称保留阶段：

COI_raw
COI_tax
COI_abundance
COI_final

保留或可能丢失的属性#

BarCodeR 会显式复制 openmetabar_run 和 edit_log。

pruning 可能丢失其他非标准属性，例如 dataset_meta、备注、标签或自定义属性。过滤后应检查这些信息。

13. 保存结果与覆盖风险#

可能出现三种情况。

输入名称 行为
空字段或父数据集名称 立即替换父数据集
新名称 创建新数据集
其他数据集名称 替换前要求确认

名称使用 BarCodeR 通用 helper 规范化。与 Input data 不同，冲突时不会自动添加 _2。

只写入内存#

保存按钮修改 datasets()，不会把项目写入磁盘。

保存后的结果会成为活动数据集。

自动再次应用过滤#

由于过滤选择器跟随活动数据集，保存结果会立即成为新的父数据集，活动过滤条件会再次应用：

原始父数据集
    ↓
第一次保存结果
    ↓
过滤条件仍然活动
    ↓
新的临时结果

第二次点击保存可能继续删除更多元素。

保存后应：

  1. 不要立即再次点击；
  2. 禁用过滤或离开选项卡；
  3. 在 Description 中检查结果；
  4. 在 Datasets 中保存项目。

14. 数据集检查与导出#

下方区域显示注册表中的数据集，但不显示尚未保存的临时结果。

表格可显示名称、过滤状态、父数据集、日期、过滤前后维度、删除数量和活动模块。

只要存在 filtration_log，数据集就会显示为已过滤，即使没有删除任何元素。

如果结果以相同名称覆盖父数据集，可能显示为自己的父数据集。

之后若在 Data Edition 中修改，当前维度可能不再只反映过滤。

详细信息面板#

面板可查看日志、参数、删除的分类单元和样本、OTU 表、分类表、元数据、序列和直方图。

需要注意：

  • 名为 Reads 的图实际上显示每个分类单元的总量；
  • 对数图使用 log10(total + 1)；
  • 详细面板中的 GC 使用字符串总长度作为分母，可能与过滤 GC 不同；
  • OTU 表始终被转置，方向没有可靠标准化；
  • 对应组件缺失时，某些面板可能为空或报错。

TSV 导出#

文件名是通用的：

otu_table.tsv
taxonomy.tsv
metadata.tsv

不包含数据集名称或日期。行名作为第一列导出，有时没有明确列名。

OTU 表导出时同样始终转置，因此方向取决于原始 phyloseq。

BIOM 导出#

BIOM 只包含丰度矩阵，不自动包含分类、元数据、序列、树或日志。

直接使用存储方向。如果分类单元在列中，文件可能方向相反。

如果未安装 biomformat，BarCodeR 当前会生成扩展名为 .biom、但内容是文本提示的文件。该文件不是有效 BIOM。

15. 科学解释与推荐策略#

BarCodeR 无法自动决定合适阈值。阈值取决于标记基因、技术、实验流程、样本数、测序深度、对照、预期多样性、pipeline 和研究目的。

稀有分类单元#

稀有 ASV 可能是错误、污染、伪影、真实稀有分类单元或重要生物学事件。仅凭稀有性不能自动删除。

实验分组#

全局阈值可能严重破坏组间平衡。过滤后应检查每组样本数、保留的对照、重复数和各组深度。

比较过滤策略#

应从同一父数据集比较：

COI_raw → 方法 A
COI_raw → 方法 B

除非目标明确是逐步过滤，否则不要使用 COI_raw → 方法 A → 方法 B。

推荐流程#

  1. 保存项目。
  2. 保留原始数据集。
  3. 选择父数据集。
  4. 检查继承参数。
  5. 每次只启用一个模块。
  6. 检查每一步后的维度。
  7. 逐步增加其他条件。
  8. 检查分组与对照。
  9. 输入新名称。
  10. 只保存一次。
  11. 离开或禁用过滤。
  12. 在 Description 中检查。
  13. 检查零值、备注、标签和来源。
  14. 保存项目。
  15. 导出最终数据集。

备注或标签消失 pruning 时自定义属性丢失
没有删除却显示已过滤 只要日志存在即可
活动模块显示 — 文本日志使用其他语言

  • 检查从其他数据集继承的参数。

  • 阅读完整摘要。
  • 检查过滤前后 ASV 和样本数。
  • 检查被跳过的步骤。
  • 检查高级条件。

  • 在 Datasets 中保存。
  • 导出最终数据集。

17. 模块的主要限制#

需要注意：

  • 自动重算可能消耗较大；
  • 直方图基于原始父数据集；
  • 过滤顺序固定；
  • 阈值不会迭代重评估；
  • 没有最终零值清理；
  • 切换数据集时参数仍保留；
  • 分类关键词默认已选择；
  • 日期和特殊类型支持有限；
  • 高级条件行之间只支持 AND；
  • 当前控件无法强制零模糊碱基；
  • 无序列 ASV 可能被保留；
  • 新日志会替换旧日志；
  • 不总是记录每项精确原因；
  • 删除元素指标来自原始父数据集；
  • 自定义属性可能丢失；
  • 空名称会无确认覆盖父数据集；
  • 保存后过滤会再次应用；
  • 保存按钮不会把项目写入磁盘；
  • 多语言下活动模块检测不完善；
  • 导出方向可能含糊；
  • BIOM 导出内容最小且依赖 biomformat。
