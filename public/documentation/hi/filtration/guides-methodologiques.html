Filtration — कार्यप्रणाली मार्गदर्शिका

1. टैब का सामान्य उद्देश्य#

Filtration टैब BarCodeR में पहले से लोड किए गए phyloseq ऑब्जेक्ट से एक उप-डेटासेट बनाता है। यह टैक्सोनॉमिक annotation के आधार पर taxa, कम abundance या कम prevalence वाले ASV, depth, richness, नाम या metadata के आधार पर samples, तथा technical criteria पूरा न करने वाली sequences को हटा सकता है।

परिणाम पहले एक अस्थायी reactive object के रूप में बनता है:

ps_filtered

इसके बाद इसे summary में देखा जा सकता है, नए नाम से save किया जा सकता है, parent dataset को replace किया जा सकता है, Description में inspect किया जा सकता है, अन्य datasets से compare किया जा सकता है और export किया जा सकता है।

Data Edition से अंतर#

Data Edition Filtration
चुने गए dataset की tables सीधे बदलता है पहले एक अस्थायी derived object बनाता है
बदलाव तुरंत datasets() में लागू होते हैं parameter सेट करते समय parent अपरिवर्तित रहता है
cell और structure corrections के लिए criteria के आधार पर samples या taxa हटाने के लिए
edits को edit_log में रखता है filtering को filtration_log में रखता है

जब तक result save नहीं होता, वह Datasets में नहीं दिखता, अन्य modules में उपलब्ध नहीं होता, disk पर नहीं लिखा जाता और session reload होने पर खो सकता है।

2. स्वचालित कार्यप्रणाली और result life cycle#

कोई Apply filters button नहीं है। किसी active parameter के बदलते ही filtration स्वतः recalculated होती है, जैसे block enable करना, threshold बदलना, taxonomic value चुनना, metadata condition जोड़ना या dataset बदलना।

बड़े dataset पर हर बदलाव OTU table पढ़ सकता है, abundance और prevalence recalculated कर सकता है, कई prune_taxa() या prune_samples() चला सकता है, sequences analyse कर सकता है और log तथा summary दोबारा बना सकता है। Parameters धीरे-धीरे बदलें और calculation समाप्त होने दें।

सेटिंग के दौरान parent सुरक्षित रहता है#

parent dataset
      ↓
reactive calculation
      ↓
temporary filtered dataset

Parent तभी replace होता है जब result उसी नाम से save किया जाए।

खाली save name का जोखिम#

Save field default रूप से खाली है। खाली value का अर्थ है:

Result को parent के नाम से save करें और parent को replace करें।

कोई अतिरिक्त confirmation नहीं आता। Raw dataset बचाने के लिए अलग नाम दें, जैसे COI_raw और COI_filtered।

Save केवल BarCodeR memory बदलता है। Result को स्थायी रखने के लिए बाद में Datasets → Save project करना आवश्यक है।

3. Filters का निश्चित क्रम#

Filters हमेशा इस क्रम में लागू होते हैं:

1. Taxonomy
2. ASV abundance
3. Samples
4. Sequences

यह क्रम fixed है और boxes खोलने या parameters भरने के क्रम पर निर्भर नहीं करता।

परिणाम#

हर block पिछले block के result पर काम करता है। उदाहरण:

  1. chloroplast हटाए जाते हैं;
  2. बचे ASV का total और prevalence recalculated होता है;
  3. sample reads और richness recalculated होते हैं;
  4. अपर्याप्त samples हटते हैं;
  5. technical criteria पूरा न करने वाली sequences हटती हैं।

इसलिए sample thresholds जरूरी नहीं कि Description में दिखाए गए raw values पर लागू हों।

केवल एक pass, convergence नहीं#

अंतिम step के बाद pipeline फिर से शुरुआत पर नहीं जाता। इसलिए:

  • samples हटने के बाद कुछ ASV prevalence threshold से नीचे जा सकते हैं, पर ASV filter फिर से नहीं चलेगा;
  • sequence filtering के बाद sample reads या richness threshold से नीचे जा सकते हैं, पर sample filter फिर नहीं चलेगा;
  • final result में zero-read samples या zero-abundance taxa रह सकते हैं।

दूसरा filtering pass पहले से अधिक elements हटा सकता है।

4. Dataset selection और parameters का बने रहना#

मुख्य selector global active dataset से synchronized है। Filtration में dataset बदलने से active_ds() बदलता है, अन्य tabs का default dataset बदलता है और project unsaved माना जा सकता है।

सभी parameters reset नहीं होते#

Dataset बदलने पर ये settings बनी रह सकती हैं:

  • abundance thresholds;
  • sample thresholds;
  • sequence criteria;
  • taxonomy keywords;
  • advanced conditions;
  • save name।

Dataset-dependent lists update होती हैं: taxonomic ranks और values, sample names और metadata variables।

Advanced condition नए dataset में मौजूद न रहने वाली variable को refer कर सकती है। तब result बनना रुक सकता है, जब तक condition corrected या deleted न हो।

हर dataset change के बाद save करने से पहले सभी blocks जाँचें।

5. Interface states को समझना#

हर block की visual state होती है।

रंग अर्थ
Grey कोई active या modified parameter नहीं
Orange parameters बदले गए हैं, पर block disabled है
Green block activation checkbox selected है

Green border यह सुनिश्चित नहीं करता कि कोई element हटेगा। उदाहरण के लिए ASV block enabled हो सकता है और सभी thresholds zero हों; block green होगा, लेकिन criteria neutral होंगे।

Global banner configured blocks पहचानने की कोशिश करता है, पर बिना किसी removal के भी dataset को filtration_log मिल सकता है।

Graphical previews#

Threshold histograms selected parent dataset पर बनते हैं, progressively filtered object पर नहीं। इनमें total reads per ASV, prevalence, maximum relative abundance, reads per sample, richness per sample, length और GC शामिल हैं।

Threshold line initial distribution दिखाती है, पर previous blocks के बाद वास्तव में उपयोग हुए values हमेशा नहीं। Before/after summary final result का मुख्य preview है।

6. Taxonomic filtering#

Taxonomic filtering के लिए tax_table आवश्यक है। यह selected rank के values exclude कर सकता है, केवल selected values रख सकता है और keywords वाली annotations हटा सकता है।

पहले से चुने गए keywords#

Default selected keywords हैं:

chloroplast
mitochondria

Block enable होने तक ये लागू नहीं होते। लेकिन केवल Enable filtering चुनना भी इन terms वाले taxa को तुरंत हटा सकता है।

ये universal contaminants नहीं हैं। Marker और study objective के अनुसार ये target biological signal भी हो सकते हैं।

Rank के अनुसार exclude या keep#

Selected rank के लिए:

  • Exclude exact selected value वाले ASV हटाता है;
  • Keep only selected values से मेल खाने वाले ASV रखता है।

Internal order है:

1. Exclusion
2. Retention
3. Keyword search

विरोधी rules सभी taxa हटा सकते हैं।

Keyword search#

Keywords सभी taxonomy columns में, case-insensitive, substring के रूप में और combined | pattern से खोजे जाते हैं।

इसलिए chloroplast, Chloroplast, chloroplastidae या Unclassified chloroplast sequence से match कर सकता है। Search selected rank तक सीमित नहीं है।

Taxonomy absent#

Taxonomy table न होने पर enabled block skip हो जाता है। अन्य blocks result बना सकते हैं। केवल green state पर भरोसा न करें; actual summary देखें।

7. Abundance के आधार पर ASV filtering#

तीन criteria क्रम से लागू होते हैं:

1. Total reads
2. Prevalence
3. Maximum relative abundance

ये मानते हैं कि OTU table values meaningful abundances हैं। CLR, relative abundances, logarithmic data, negative values या normalized matrices पर interpretation गलत हो सकती है।

Total reads per ASV#

Total = इस stage पर मौजूद samples में abundance का sum

Rule strict है:

Total > threshold

Threshold 10 होने पर total 10 हटेगा और total 11 रहेगा।

Prevalence#

Prevalence उन samples की संख्या है जहाँ abundance strictly greater than zero है। Rule है:

Prevalence ≥ threshold

Threshold 3 पर exactly 3 samples में मौजूद ASV रखा जाता है।

Absolute threshold को sample count के संदर्भ में समझें। 3 samples, 10-sample project में 30% हैं, जबकि 100-sample project में 3%।

Maximum relative abundance#

हर ASV के लिए BarCodeR प्रत्येक sample में relative abundance calculate करता है और maximum value रखता है:

Maximum of: ASV abundance / total sample abundance × 100

Rule है:

Maximum relative abundance ≥ threshold

यह globally rare लेकिन किसी एक sample में important ASV को बचा सकता है।

यह calculation total और prevalence filters के बाद होती है। Taxa हटने से denominator बदलता है और remaining taxa की relative proportion स्वतः बढ़ती है।

8. Sample filtering#

Criteria इस क्रम में लागू होते हैं:

1. Minimum reads
2. Minimum richness
3. Sample names
4. Simple metadata condition
5. Advanced conditions

Minimum reads#

Taxonomic और abundance filtering के बाद reads recalculated होते हैं:

Reads = remaining taxa abundances का sum

Rule inclusive है:

Reads ≥ threshold

Minimum richness#

Richness उन taxa की संख्या है जिनकी abundance strictly greater than zero है। Rule है:

Richness ≥ threshold

यह parent dataset के Description value से अलग हो सकती है।

Name के अनुसार filtering#

Names exactly sample_names(ps) से match करते हैं। Partial या case-insensitive search नहीं है।

  • Keep केवल selected names रखता है;
  • Exclude selected names हटाता है।

यह step reads और richness thresholds के बाद आता है। Keep में चुना sample पहले ही हट चुका हो सकता है।

Simple metadata condition#

Module मुख्य रूप से numeric columns और factor/character columns में अंतर करता है। Dates, logical columns और special classes simple filter में सही तरह handle न हों।

Numeric variables

Operators हैं ≥, >, ≤, < और between। Between दोनों limits को include करता है। उल्टे limits दिए जाने पर BarCodeR lower और upper values स्वतः चुनता है।

Median या quartiles जैसी initial values केवल convenience हैं, scientific recommendations नहीं।

Keep के साथ missing values सामान्यतः हटते हैं। Exclude के साथ वे सामान्यतः रहते हैं, क्योंकि inversion से पहले condition satisfy नहीं करते।

Categorical variables

Text conversion के बाद exact comparison होती है और case, spaces तथा spelling sensitive है।

एक condition में कई values OR से जुड़ती हैं।

Missing values आम तौर पर Keep में हटते और Exclude में रहते हैं।

9. Advanced metadata conditions#

हर advanced condition में variable, Keep/Exclude action, comparison या values और delete button होता है।

सभी conditions आपस में AND से जुड़ते हैं।

उदाहरण:

Keep Campaign = 2026
AND
Exclude Site = control
AND
Keep Depth ≥ 50

अलग variables के बीच OR उपलब्ध नहीं है।

Categorical variable की एक ही row में कई values चुनना internal OR देता है, जैसे Site = A or B।

Non-numeric variables text के रूप में handle होते हैं। Date category के रूप में चुनी जा सकती है, पर वास्तविक time interval की तरह filter नहीं होती।

Incomplete condition#

एक अधूरी advanced condition temporary result बनना पूरी तरह रोक सकती है, भले अन्य filters valid हों। Condition complete या delete करें।

10. Technical sequence filtering#

Technical filtering refseq(ps) का उपयोग करता है और length, GC, ambiguous bases तथा homopolymers पर criteria लागू कर सकता है। यह सबसे अंत में चलता है।

Missing या misaligned sequences#

refseq absent होने पर block skip होता है और log में line जुड़ती है।

BarCodeR sequences को taxa_names(ps) से align करने की कोशिश करता है:

  • names absent हों और count exactly match करे तो order same माना जाता है;
  • names हों तो identifiers से match किया जाता है।

कोई sequence align न हो तो block skip होता है।

Coverage partial हो तो sequence वाले ASV evaluate होते हैं और sequence बिना ASV बिना test के retained रहते हैं।

Length और GC plots stricter alignment उपयोग करते हैं, इसलिए filter partially apply होने पर भी plots absent हो सकते हैं।

Length#

Limits inclusive हैं:

Minimum length ≤ length ≤ maximum length

Maximum zero होने पर upper limit disabled है। Minimum maximum से बड़ा हो तो सभी sequences reject हो सकती हैं।

GC#

Filter A, C, G और T पर GC calculate करता है:

G + C
────────────── × 100
A + C + G + T

Ambiguous bases denominator में नहीं हैं। Limits inclusive हैं; neutral range 0% से 100% है।

Ambiguous bases#

Count किए जाने वाले characters हैं:

N R Y S W K M B D H V

Gaps, dots और अन्य symbols explicitly count नहीं होते।

Current implementation में Maximum ambiguities = 0 filter disable करता है। इससे strictly zero ambiguous bases enforce नहीं किए जा सकते।

Homopolymers#

BarCodeR consecutive identical characters की longest run खोजता है। AAAATCG की maximum homopolymer length 4 है।

Ambiguous bases और repeated symbols सहित सभी characters count हो सकते हैं। Longest run threshold से कम या बराबर होने पर sequence रहती है। Zero इस criterion को भी disable करता है।

क्रम का परिणाम#

Technical filtering के बाद sample thresholds दोबारा नहीं चलते। Samples reads या richness threshold से नीचे, या zero reads पर रह सकते हैं।

11. Empty result protection और validation सीमाएँ#

यदि कोई operation सभी taxa या सभी samples हटा दे, BarCodeR calculation रोककर error दिखाता है।

यह केवल इतना सुनिश्चित करता है कि कम से कम एक taxon और एक sample रहे। यह पर्याप्त replicates, final minimum depth/richness, zero values की अनुपस्थिति या statistical suitability की guarantee नहीं देता।

Final result Description में जाँचें।

12. Filtration log और provenance#

Result को attribute मिलता है:

attr(ps, "filtration_log")

इसमें parent name, date, before/after dimensions, descriptive lines, structured parameters, removed taxa और removed samples हो सकते हैं।

Structured parameters#

Parameters यहाँ save होते हैं:

filtration_log$params

इनमें enabled blocks, taxonomic rank, excluded/retained values, keywords, abundance thresholds, name filters, metadata conditions और sequence parameters शामिल हैं।

Filtering reproduce या audit करने के लिए यह सबसे reliable source है।

Log language#

Text calculation के समय active language में save होता है और बाद में translate नहीं होता।

Active blocks column फिलहाल text log में कुछ French expressions खोजता है। अन्य भाषा में filtered dataset के लिए यह — दिखा सकता है। Structured parameters अधिक reliable हैं।

Removed-item tables#

removed_taxa और removed_samples सभी filters से पहले raw parent की metrics उपयोग करते हैं।

Taxonomic filtering के बाद 800 reads बचने के कारण हटाया sample table में original 5,000 reads के साथ दिख सकता है।

Tables हर item के लिए exact cause हमेशा नहीं देतीं। Log steps मुख्यतः global effects बताते हैं।

Successive filtering#

नई pass पिछले filtration_log को replace करती है; logs stack नहीं होते।

Stages अलग names में रखें:

COI_raw
COI_tax
COI_abundance
COI_final

Preserved और potentially lost attributes#

BarCodeR explicitly openmetabar_run और edit_log copy करता है।

Pruning अन्य non-standard attributes जैसे dataset_meta, notes, tags या custom attributes हटा सकता है। Filtering के बाद उन्हें जाँचें।

13. Result saving और overwrite risk#

तीन cases हैं।

Entered name Behaviour
Empty field या parent name Parent तुरंत replace होता है
New name नया dataset बनता है
किसी अन्य dataset का name Replacement से पहले confirmation

Name common BarCodeR helper से normalized होता है। Input data के विपरीत collision पर _2 स्वतः नहीं जुड़ता।

केवल memory में save#

Save button datasets() बदलता है। Project disk पर persist नहीं होता।

Saved result active dataset बन जाता है।

Filters का automatic reapplication#

Filtration selector active dataset को follow करता है, इसलिए saved result तुरंत नया parent बन जाता है और active filters फिर लागू होते हैं:

raw parent
    ↓
first saved result
    ↓
same active filters
    ↓
new temporary result

दूसरा Save click अधिक elements हटा सकता है।

Save के बाद:

  1. तुरंत दोबारा Save न करें;
  2. filters disable करें या tab छोड़ें;
  3. Description में result inspect करें;
  4. Datasets में project save करें।

14. Dataset inspection और exports#

नीचे का section registry के datasets दिखाता है, unsaved temporary result नहीं।

Table name, filtered status, parent, date, before/after dimensions, removed counts और active blocks दिखा सकती है।

filtration_log मौजूद होते ही dataset filtered माना जाता है, भले कुछ हटाया न गया हो।

Same name से parent overwrite होने पर dataset अपना ही parent दिख सकता है।

बाद में Data Edition में बदलाव होने पर current dimensions केवल filtration का प्रभाव नहीं रहेंगी।

Detail panel#

Panel log, parameters, removed taxa/samples, OTU table, taxonomy, metadata, sequences और histograms दिखाता है।

महत्वपूर्ण बातें:

  • Reads नाम वाला plot वास्तव में total per taxon दिखाता है;
  • log histogram log10(total + 1) उपयोग करता है;
  • detail GC total string length से divide करता है और filter GC से अलग हो सकता है;
  • OTU table हमेशा transpose होती है, orientation reliably standardized नहीं है;
  • component absent होने पर panel empty या error हो सकता है।

TSV exports#

taxonomy.tsv
metadata.tsv

इनमें dataset name या date नहीं होता। Rownames पहली column में export होते हैं, कभी-कभी explicit header के बिना।

OTU table export में भी हमेशा transpose होती है, इसलिए orientation original phyloseq पर निर्भर है।

BIOM export#

BIOM में केवल abundance matrix होती है। Taxonomy, metadata, sequences, tree और log स्वतः शामिल नहीं होते।

Stored orientation सीधे उपयोग होती है। Taxa columns में हों तो file reversed हो सकती है।

biomformat unavailable होने पर BarCodeR .biom extension वाला text-message file बनाता है। वह valid BIOM नहीं है।

15. Scientific interpretation और recommended strategy#

BarCodeR सही thresholds स्वतः निर्धारित नहीं कर सकता। वे marker, technology, protocol, sample count, depth, controls, expected diversity, pipeline और scientific objective पर निर्भर हैं।

Rare taxa#

Rare ASV error, contamination, artefact, वास्तविक rare taxon या महत्वपूर्ण biological event हो सकता है। केवल rarity removal justify नहीं करती।

Experimental groups#

Global threshold groups को असंतुलित कर सकता है। Filtering के बाद samples per group, retained controls, replicate count और group depth जाँचें।

Strategies की तुलना#

एक ही parent से methods compare करें:

COI_raw → method A
COI_raw → method B

COI_raw → method A → method B से बचें, जब तक progressive filtering स्पष्ट उद्देश्य न हो।

Recommended workflow#

  1. Project save करें।
  2. Raw dataset रखें।
  3. Parent select करें।
  4. Inherited settings जाँचें।
  5. एक समय में एक block enable करें।
  6. हर block के बाद dimensions देखें।
  7. अन्य criteria धीरे-धीरे जोड़ें।
  8. Groups और controls जाँचें।
  9. नया name दें।
  10. केवल एक बार save करें।
  11. Tab छोड़ें या filters disable करें।
  12. Description में result देखें।
  13. Zeros, notes, tags और provenance जाँचें।
  14. Project save करें।
  15. Final dataset export करें।

17. Module की मुख्य सीमाएँ#

इन सीमाओं को ध्यान में रखें:

  • automatic recalculation महँगा हो सकता है;
  • histograms raw parent पर आधारित हैं;
  • filter order fixed है;
  • thresholds iterative रूप से reevaluate नहीं होते;
  • final zero cleanup नहीं होता;
  • dataset change पर settings persist करती हैं;
  • taxonomy keywords preselected हैं;
  • dates और special classes का support सीमित है;
  • advanced condition rows के बीच केवल AND है;
  • current control zero ambiguities enforce नहीं कर सकता;
  • बिना sequence ASV retain हो सकते हैं;
  • नया log पुराने log को replace करता है;
  • exact per-item cause हमेशा नहीं रखा जाता;
  • removed-item metrics raw parent से आते हैं;
  • custom attributes खो सकते हैं;
  • empty name बिना confirmation parent overwrite करता है;
  • save के बाद filters reapply होते हैं;
  • Save project को disk पर नहीं लिखता;
  • active-block detection multilingual logs पर imperfect है;
  • export orientations ambiguous हो सकती हैं;
  • BIOM export minimal है और biomformat पर निर्भर है।
