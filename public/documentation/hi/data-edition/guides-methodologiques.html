डेटा संपादन — पद्धति संबंधी मार्गदर्शिका

1. सामान्य परिचय#

Data Edition लोड किए गए phyloseq dataset के आंतरिक components को सीधे बदलता है: sample metadata, OTU abundances, taxonomy, reference sequences और phylogenetic tree। यह component import/export/delete, ASV renaming और descriptive edit log भी प्रदान करता है।

2. मूल सिद्धांत: बदलाव तुरंत लागू होते हैं#

Data Edition अलग draft area नहीं है। Cell edits, column operations, merges, ASV renaming, taxonomy replacements, full imports और component deletion तुरंत datasets() में चुने हुए object को बदल देते हैं।

3. Save बटन pending बदलाव लागू नहीं करता#

बदलाव पहले ही लागू हो चुके होते हैं। Save केवल current edited state को उसी नाम, नए नाम या किसी दूसरे registry entry पर दर्ज करता है। यह project को disk पर save नहीं करता।

4. Original version के लिए महत्वपूर्ण परिणाम#

COI_raw को edit करके COI_edited नाम से save करने पर untouched COI_raw नहीं बचता, क्योंकि source entry पहले ही बदल चुकी है। Edit से पहले Datasets में raw dataset की duplicate copy बनाएँ।

5. Source files पर प्रभाव#

Data Edition original RDS, RData, CSV, FASTA, Newick या remote files को rewrite नहीं करता। यह memory में मौजूद object बदलता है। Changes बनाए रखने के लिए project save करें या dataset export करें।

6. Tab की संरचना#

इसमें dataset selection, metadata editor, OTU editor, taxonomy editor, full component import/export/delete, logs और registry saving शामिल हैं।

7. Edit करने वाला dataset#

Picker registry के datasets दिखाता है और active_ds() से synchronized है। यहाँ dataset बदलने से global active dataset बदलता है।

8. Editing के दौरान dataset बदलना#

Dataset बदलने पर metadata, OTU और taxonomy editors के local states reload होते हैं और initial/previous states तथा previews reset होते हैं। Local initial state हमेशा original file state नहीं होता।

9. Dataset बदलकर वापस आने के बाद Reset#

यदि COI edit किया, दूसरा dataset खोला और फिर COI पर लौटे, तो Reset लौटते समय load हुई already-edited state पर जाएगा, पहली edit से पहले वाली state पर नहीं।

10. Editing और project persistence#

हर action datasets() अपडेट करता है और project को unsaved mark कर सकता है। Application बंद करने से पहले Datasets → Save project उपयोग करें।

11. दो import mechanisms का अंतर#

Table editors में Merge matching identifiers के लिए केवल missing columns जोड़ता है। Full component import file चुनते ही पूरा selected component replace कर देता है।

12. Data Edition किन कामों के लिए नहीं है#

Biological filtering, normalization, abundance transformation या threshold-based removal के लिए यह preferred tool नहीं है। ऐसे काम Filtration या controlled external workflow में करें।

13. Edit history#

Actions attr(ps, "edit_log") में time, dataset, table, action, description, before/after dimensions और warnings जोड़ सकते हैं।

14. Log backup नहीं है#

Log complete old tables नहीं रखता। यह audit trail है, version control या full restoration system नहीं।

15. Log की भाषा#

edit_log की internal actions और warnings French में रहती हैं, चाहे interface किसी और भाषा में हो।

16. Logs की तीन views#

Latest global action current module session की अंतिम action दिखाता है, Full history stored log दिखाता है और Summary actions, tables, warnings और dates aggregate करता है।

17. Total में गिनी जाने वाली actions#

Cell edits, structural changes, imports, exports, undo, reset, registry saves, renaming और automatic synchronization सब count हो सकते हैं।

18. Undo: केवल एक step#

हर editor केवल एक previous local state रखता है। Undo पूरे history में पीछे नहीं जाता; बार-बार click करने पर दो recent states के बीच toggle हो सकता है।

19. Reset#

Reset उस local state पर लौटता है जो submodule ने dataset load करते समय capture की थी। यह तुरंत लागू, logged और undoable है, लेकिन original source file पर लौटने की guarantee नहीं।

20. Metadata editing — परिचय#

यह sample_data(ps) पर काम करता है और values edit, variable add/delete/rename, file merge, undo और reset देता है।

21. Missing metadata का automatic creation#

यदि usable metadata नहीं है, editor minimal sample_data बनाता है जिसमें SampleID column और प्रत्येक sample के लिए एक row होती है। यह dedicated log entry के बिना dataset बदल सकता है।

22. Sample identifiers#

असली identifiers rownames हैं जो sample_names(ps) से aligned हैं। Displayed SampleID column साधारण variable है; उसे edit करने से OTU sample names नहीं बदलते।

23. Editable metadata table#

Cells सीधे edit होती हैं और cell validation पर तुरंत लागू हो जाती हैं। कोई global Apply button नहीं है।

24. Factors का treatment#

Factors local रूप से character में बदलते हैं। पहली rewrite के बाद levels और order खो सकते हैं।

25. List columns का treatment#

List columns comma-separated text में flatten हो जाती हैं, जिसे original structure के बिना वापस बनाना कठिन हो सकता है।

26. Numeric column edit करना#

Valid number numeric रहता है, blank cell NA_real_ बनती है और nonnumeric text पूरी column को character में बदल सकता है तथा warning देता है।

27. Numeric से text conversion का परिणाम#

Continuous covariate character बनने पर statistical modules में quantitative variable की तरह काम नहीं कर सकती। Editing के बाद types जाँचें।

28. Logical, date और special classes#

Explicit preservation मुख्यतः numeric columns के लिए है। logical, Date, POSIXct, ordered factors और custom classes खो सकते हैं।

29. Metadata column जोड़ना#

नई column NA से भरी होती है। Name ASCII letter से शुरू हो, केवल letters, numbers या _ रखे, dot न हो और unique हो।

30. Compatible name suggestions#

Module normalized valid name suggest कर सकता है, लेकिन उसे automatic apply नहीं करता।

31. Metadata column rename करना#

Values सुरक्षित रहती हैं और valid unique name आवश्यक है। Rownames या sample identifiers नहीं बदलते।

32. Renaming का analyses पर प्रभाव#

Old variable name उपयोग करने वाली formulas या saved settings automatic update नहीं होतीं और फिर configure करनी पड़ती हैं।

33. Metadata column delete करना#

Exact case-sensitive name आवश्यक है। Case-insensitive या approximate suggestions दिखाई जा सकती हैं।

34. अंतिम column delete करना#

कम से कम एक column बचाने की general protection नहीं है। पूरी metadata हटानी हो तो full component deletion उपयोग करें।

35. Metadata rows की consistency#

Missing samples NA के साथ जोड़ी जाती हैं, rows sample_names(ps) के अनुसार reorder होती हैं और extra rows हट जाती हैं।

36. Metadata में file merge करना#

CSV, TSV और TXT accepted हैं; comma, semicolon या tab separator चुना जा सकता है।

37. Metadata separator की automatic detection#

अधिकतम तीस nonempty lines देखकर field count और regularity compare की जाती है। Uncertain result manually override किया जा सकता है।

38. First column as identifiers#

Enable करने पर first column rownames बनती है। Disable होने पर numeric rownames सामान्यतः sample matching रोकती हैं।

39. Metadata merge का वास्तविक behavior#

Matching rownames के लिए केवल new columns जोड़ी जाती हैं। Matching samples values पाते हैं, बाकी current samples NA पाते हैं।

40. Existing columns#

Merge existing columns update नहीं करता। यदि कोई new column नहीं है तो कुछ नहीं बदलता।

41. Merge file में extra samples#

Phyloseq में न मौजूद identifiers ignore होते हैं और new samples नहीं बनाते।

42. Merge file में missing current samples#

वे dataset में बने रहते हैं और new columns में NA पाते हैं।

43. OTU-table editing — परिचय#

यह cell edit, column add/delete, merge, display sorting, ASV renaming, orientation declaration, undo और reset देता है।

44. OTU-table orientation#

Editor taxa_are_rows() preserve करता है। Taxa rows में हों तो columns samples हैं; अन्यथा columns taxa हैं।

45. “ASV in columns” transpose command नहीं है#

Switch मुख्यतः automatic ASV renaming को बताता है। उसे बदलने से matrix transpose या taxa_are_rows तुरंत नहीं बदलता।

46. गलत axis चुनने का risk#

Samples को ASV की तरह rename किया जा सकता है, declared orientation बदल सकती है और taxonomy, sequences तथा tree desynchronize हो सकते हैं।

47. Editable OTU table#

हर cell edit की जा सकती है और module बाद में numeric matrix rebuild करता है।

48. OTU table की numeric conversion#

हर action के बाद पूरी table numeric में convert होती है। Nonconvertible values NA बनती हैं और warning आती है।

49. Blank OTU values#

Blank cells, whitespace और NA report होती हैं, लेकिन zero से automatic replace नहीं होतीं।

50. Nonnumeric values#

absent, low या ? जैसे text numeric conversion में सामान्यतः NA बनते हैं।

51. Negative और decimal values#

Block नहीं होते। Table counts, proportions, transformed values या CLR रख सकती है, हालांकि downstream methods उन्हें reject कर सकती हैं।

52. OTU table में column जोड़ना#

Taxa rows में हों तो sample जुड़ता है; taxa columns में हों तो taxon जुड़ता है। नई column NA से शुरू होती है।

53. Sample जोड़ने के risks#

Corresponding sample_data row automatic नहीं बनती, इसलिए phyloseq inconsistent हो सकता है।

54. Taxon जोड़ने के risks#

Taxonomy, sequence या tree tip automatic नहीं बनते। Coverage incomplete होने पर RefSeq या tree हट सकते हैं।

55. Structural additions के लिए recommendation#

New taxa या samples के लिए R में complete phyloseq rebuild और validate करें, केवल एक table extend न करें।

56. OTU column delete करना#

Orientation के अनुसार sample या taxon हटता है। Metadata या taxonomy हर बार synchronize नहीं होती।

57. Biological removal के लिए Filtration उपयोग करें#

Filtration documented criteria से samples/taxa हटाकर coherent child dataset बनाता है।

58. Natural ASV sorting#

Display में ASV1, ASV2, ASV10 numerical order में आते हैं; internal order नहीं बदलता।

59. Sorting enabled होने पर editing#

Displayed row original identifier से map की जाती है ताकि सही element edit हो।

60. OTU table में file merge करना#

Separator detect होता है, rownames उपयोग होती हैं, common rows खोजी जाती हैं और केवल new columns जुड़ती हैं।

61. Imported columns का अर्थ#

Current orientation पर निर्भर है; module यह infer नहीं करता कि columns samples हैं या taxa।

62. OTU merge file की extra rows#

Ignore होती हैं और new identifiers नहीं बनातीं।

63. File में missing current rows#

नई columns में उन rows के लिए NA रहता है।

64. Automatic ASV renaming#

Prefix, declared ASV axis और current identifiers को combine करता है।

65. Final numbers preserve करना#

यदि सभी identifiers unique number पर समाप्त होते हैं, numbers preserve होते हैं; ASV128 से Feature128।

66. Sequential renaming#

यदि किसी एक identifier में usable final number नहीं है, सभी identifiers internal order के अनुसार sequential rename होते हैं।

67. New-name collisions#

Generated names unique न हों तो sequential fallback उपयोग होता है।

68. Prefix validation#

केवल outer whitespace हटता है। ASV, OTU, ZOTU या Feature जैसे simple prefix उपयोग करें।

69. ASV renaming propagation#

Old identifiers unique हों तो names tax_table, refseq और tree tips तक propagate होते हैं।

70. Renaming से पहले duplicate identifiers#

Propagation disable हो जाती है और object inconsistent रह सकता है। Duplicates upstream ठीक करें।

71. OTU change के बाद sequences realign करना#

Unnamed sequences count match होने पर order से नामित होती हैं। Complete named sequences reorder होती हैं। किसी taxon की sequence missing हो तो पूरा refseq हटता है।

72. OTU change के बाद tree realign करना#

Extra tips prune होती हैं। कोई OTU taxon tree में missing हो तो पूरा tree हटता है।

73. ape package absent#

OTU change के समय ape उपलब्ध न हो तो tree हटता है और warning log होती है।

74. Structural OTU changes के बाद taxonomy#

ASV renaming में propagation explicit है, लेकिन हर structural edit में guarantee नहीं। बाद में identifiers जाँचें।

75. Taxonomy editing — परिचय#

यह tax_table(ps) पर cells, ranks, file merge, automatic replacement, undo और reset देता है।

76. Missing taxonomy#

Taxonomy table न हो तो full component import उपयोग करें।

77. First taxonomy edit से पहले confirmation#

पहली attempt केवल information modal दिखाती है और action नहीं चलाती। Modal बंद करके action दोहराएँ।

78. Dataset बदलने के बाद नई confirmation#

Dataset selection बदलने पर confirmation state reset होती है।

79. Taxonomy cell edit करना#

Value text के रूप में save होती है। Nomenclature या taxonomy validation नहीं होती।

80. Hierarchy validation नहीं#

Species–genus–family consistency या scientific-name validity check नहीं होती।

81. Taxonomic rank जोड़ना#

अंत में NA column जुड़ती है और strict valid unique name चाहिए।

82. Rank order#

कोई order enforce नहीं होता। Coherent order manually बनाए रखें।

83. Taxonomic rank rename करना#

Direct button नहीं है। New rank बनाएँ, values transfer करें और old rank delete करें, या R में करें।

84. Rank delete करना#

Exact name से तुरंत delete होता है; suggestions दिखाई जा सकती हैं।

85. सभी ranks delete करना#

General protection नहीं है। पूरी taxonomy हटानी हो तो full component deletion उपयोग करें।

86. ASV के अनुसार taxonomy sorting#

Natural sorting केवल display बदलती है और identifier की पहली numeric sequence उपयोग करती है।

87. ASV renaming के बाद synchronization#

Taxonomy rownames बदलें और row count समान रहे तो local states update होते हैं और synchronization log entry जुड़ती है।

88. Taxonomy synchronization की सीमा#

Same identifiers के साथ full replacement local values refresh न करे। दूसरा dataset चुनकर वापस आएँ।

89. Taxonomy में file merge करना#

Common taxa के लिए केवल missing rank columns जुड़ती हैं; अन्य taxa NA पाते हैं।

90. Taxonomy separator की automatic detection नहीं#

Separator manually चुनना आवश्यक है।

91. Existing taxonomy columns#

Merge existing Genus जैसे ranks replace नहीं करता। पूरी table replace करने के लिए full import उपयोग करें।

92. Automatic value replacement#

NA, unidentified, unclassified, unknown, missing जैसे patterns को common text से बदला जा सकता है।

93. Exact case-insensitive matching#

Patterns trim और lowercase होकर exact compare होते हैं; broad substring search नहीं है।

94. NA pattern#

True missing values और textual NA variants दोनों match होते हैं।

95. Empty pattern#

Empty या whitespace-only strings target होती हैं।

96. Replacement scope#

Replacement सभी taxonomy ranks पर लागू होता है; single-column targeting नहीं।

97. Mandatory preview#

Confirmation से पहले total cells और pattern/column counts दिखते हैं।

98. Overlapping patterns#

एक cell कई patterns match कर सकती है; per-pattern counts overlap कर सकते हैं।

99. Nonempty replacement value#

Empty replacement string reject होती है।

100. Replacement के scientific consequences#

NA को Unassigned करने से missing information वास्तविक category बनती है और completeness, agglomeration तथा plots बदलते हैं।

101. Unassigned taxa grouping#

Same text वाले taxa tax_glom() से group हो सकते हैं, true missing values से अलग behavior है।

102. Initial taxonomy state और Reset#

Local editor dataset load करते समय initial state recapture करता है; dataset switch Reset reference बदल सकता है।

103. Import, export और deletion — परिचय#

यह area whole components manage करता है: metadata, OTU, taxonomy, RefSeq और tree।

104. Automatic import#

File select होते ही import शुरू होता है; extra confirmation button या general preview नहीं है।

105. File-size limit#

Global BarCodeR upload limit लागू होती है, वर्तमान में लगभग 500 MB।

106. Full imports के separator detection#

मुख्यतः first line inspect होती है: semicolon priority, फिर tab, अन्यथा comma। Merge detection से कम robust है।

107. Full metadata import#

First column identifiers देती है। Unknown samples reject होते हैं; missing current samples NA के साथ जोड़ी जाती हैं। Old metadata पूरी replace होती है।

108. Full OTU-table import#

File taxa rows और samples columns के रूप में पढ़ी जाती है तथा taxa_are_rows = TRUE लागू होता है।

109. OTU import के accepted identifiers#

File taxa और samples existing identifiers के subsets होने चाहिए। New samples या taxa नहीं जुड़ते।

110. OTU import में missing identifiers#

Current samples या taxa file में missing हों तो zero से भरते हैं और current object order में reorder होते हैं।

111. OTU import की numeric conversion#

पूरी table numeric बनती है। Invalid values NA बनती हैं; import warning के साथ जारी रह सकता है।

112. Full taxonomy import#

First column taxa देती है। Unknown taxa reject होते हैं; missing taxa NA पाते हैं। Old table और ranks replace होते हैं।

113. RefSeq import#

FASTA identifiers सभी taxa से match और पूर्ण coverage देने चाहिए। Partial files या unknown identifiers reject होते हैं।

114. Tree import#

Newick tips सभी taxa से match और पूर्ण coverage दें। Unknown tips या missing taxa rejection करते हैं।

115. Complete component replacement#

Old component snapshot के रूप में नहीं बचता। केवल dimensions, file info और warnings log होते हैं।

116. Full import के बाद editors refresh करना#

Dataset name न बदले तो local editors old copy रख सकते हैं। आगे edit करने से पहले dataset switch करके वापस आएँ।

117. Component export#

Metadata, OTU और taxonomy CSV; RefSeq FASTA; tree Newick में export होते हैं।

118. CSV export separator#

.csv extension के बावजूद semicolon ; उपयोग होता है।

119. Metadata export#

Rownames से SampleID column बनती है और missing values blank cells के रूप में export होती हैं।

120. OTU export#

Stored orientation preserve होती है और file taxa_are_rows स्पष्ट रूप से record नहीं करती।

121. Taxonomy export#

Taxon identifiers first column में और missing annotations blank cells के रूप में लिखे जाते हैं।

122. RefSeq export#

Current names के साथ FASTA लिखा जाता है; Biostrings आवश्यक है।

123. Tree export#

Newick लिखा जाता है; ape आवश्यक है।

124. Export और audit log#

हर export edit_log entry जोड़ता है और project को unsaved mark कर सकता है।

125. Component deletion#

Modal present components दिखाती है और confirmation से पहले multiple selections अनुमति देती है।

126. Metadata delete करना#

sam_data हटता है और groups/covariates वाली analyses उपलब्ध नहीं रहतीं।

127. Taxonomy delete करना#

tax_table हटता है और taxonomy-based analyses उपलब्ध नहीं रहतीं।

128. RefSeq delete करना#

Length, GC और sequence-based functions reference sequences खो देती हैं।

129. Tree delete करना#

UniFrac, Faith PD और phylogenetic visualization उपलब्ध नहीं रहती।

130. OTU table delete करना#

Interface इसे अनुमति देता है, लेकिन core component हटने से dataset अधिकांश modules में unusable हो जाता है।

131. कई components साथ delete करना#

कई slots हट सकते हैं, भले remaining object internally inconsistent हो जाए।

132. Component deletion undo करना#

इस area में Undo नहीं है। Component reimport करें, project restore करें या earlier export load करें।

133. Deletion और disk files#

Project save होने तक deletion memory में है। Source files और previous disk backups नहीं हटते।

134. Dataset को registry में save करना#

Name field same-name registration, new entry या existing entry replacement देता है।

135. Empty name#

Dataset current name से re-register होता है, active रहता है और log entry मिलती है। Project disk पर save नहीं होता।

136. Available new name#

Current edited state का नया registry entry बनता है और active हो जाता है। Source entry रहती है, लेकिन पहले ही edited है।

137. Name किसी दूसरे dataset द्वारा उपयोग हो रहा हो#

Confirmation के बाद target edited source state से पूरी तरह overwrite होता है; source entry भी रहती है।

138. Dataset-name cleaning#

Shared naming helper collision check से पहले label clean करता है।

139. दूसरे dataset को overwrite करना#

Tables, sequences, tree, attributes, logs और provenance सब replace होते हैं। यह merge नहीं है।

140. Complete project save करना#

Editing के बाद registry disk पर persist करने के लिए Datasets → Save project उपयोग करें।

141. Troubleshooting#

नीचे common failures और वास्तविक causes दिए गए हैं।

141.1. गलत dataset modify हो गया#

Picker global active dataset follow करता है। हर action से पहले displayed name जाँचें।

141.2. New name चाहा लेकिन original भी बदल गया#

Edits copying से पहले होती हैं। Backup, export या original file restore करें।

141.3. Save ने project save नहीं किया#

यह केवल memory registry बदलता है। Datasets से save करें।

141.4. Metadata automatic दिखाई दी#

Dataset में sample_data नहीं था; minimal table बनाई गई।

141.5. SampleID edit करने से samples rename नहीं हुए#

True identifiers rownames हैं।

141.6. Numeric variable text बन गई#

Nonnumeric value दर्ज हुई। पूरी column ठीक करें या typed metadata reimport करें।

141.7. Factor character बन गया#

Editor factors flatten करता है। आवश्यकता हो तो R में levels restore करें।

141.8. New column का type गलत है#

यह NA से शुरू होती है और entered values से infer होती है। बाद में validate और convert करें।

141.9. Metadata merge ने existing column update नहीं की#

Merge केवल missing columns जोड़ता है। Full import या cell edit उपयोग करें।

141.10. कोई common identifier नहीं मिला#

First column, rownames option, case, whitespace और spelling जाँचें।

141.11. Detected separator गलत है#

Irregular file में manually override करें।

141.12. OTU values NA बन गईं#

Text, symbols, whitespace या decimal comma के कारण numeric conversion fail हुआ।

141.13. Decimal commas NA बनते हैं#

Expected decimal mark point है। Source file ठीक करें।

141.14. Added OTU column ने metadata desynchronize की#

Sample केवल OTU table में जुड़ा। Matching metadata जोड़ें या object rebuild करें।

141.15. OTU change के बाद RefSeq गायब हुई#

अब सभी taxa cover नहीं हो रहे थे।

141.16. OTU change के बाद tree गायब हुआ#

Taxon missing था, renaming propagate नहीं हुआ या ape unavailable था।

141.17. Tree tips गायब हुईं#

OTU table में न मौजूद extra tips automatic prune होती हैं।

141.18. Samples ASV की तरह rename हो गए#

गलत axis declare हुआ। Copy या backup restore करें।

141.19. ASV prefix ने unusual names बनाए#

Prefix strict validate नहीं होता। Simple prefix उपयोग करें।

141.20. Taxonomy OTU table से match नहीं करती#

Rownames, duplicates और editor refresh जाँचें; R में identifier sets compare करें।

141.21. First taxonomy change नहीं चला#

पहली attempt warning modal खोलती है। Action दोहराएँ।

141.22. Taxonomy replacement ने कई ranks बदले#

Replacement सभी columns पर लागू है। Per-rank preview देखें।

141.23. NA अब real category माना जा रहा है#

Missing value text से replace हुआ और assigned taxonomy की तरह aggregate हो सकता है।

141.24. Taxonomy merge ने Genus replace नहीं किया#

Rank पहले से मौजूद है; Merge केवल missing ranks जोड़ता है।

141.25. Taxonomy separator detect नहीं हुआ#

इस editor में manual selection आवश्यक है।

141.26. Full import ने columns मिटा दीं#

यह पूरा component replace करता है। Backup restore करें या additive changes के लिए Merge उपयोग करें।

141.27. Full OTU import ने orientation बदली#

यह हमेशा taxa rows लागू करता है।

141.28. Full import new samples reject करता है#

Identifiers पहले से मौजूद होने चाहिए। Extended sample universe के लिए नया complete phyloseq बनाएँ।

141.29. Full import new taxa reject करता है#

Rownames taxa_names(ps) में होने चाहिए।

141.30. FASTA import reject है#

Format, identifier uniqueness, full coverage और Biostrings availability जाँचें।

141.31. Tree import reject है#

Valid Newick, unknown tips, missing taxa और ape availability जाँचें।

141.32. Import के बाद editor old table दिखाता है#

दूसरा dataset चुनकर वापस आएँ ताकि local state refresh हो।

141.33. Deleted old table editing के बाद वापस आ गई#

Stale submodule state ने पुरानी copy rewrite की हो सकती है। Delete/full import के बाद refresh करें।

141.34. Download करने से unsaved modification बनी#

Exports log होती हैं और dataset attribute बदलता है।

141.35. Table deletion undo नहीं हो सकती#

Component-deletion area में Undo नहीं है। Reimport या restore करें।

141.36. OTU table delete करने के बाद dataset काम नहीं करता#

Complete version restore करें; OTU central component है।

141.37. Undo कई actions पीछे नहीं जाता#

केवल एक previous state store होती है।

141.38. Reset original file पर नहीं लौटता#

यह local editor load के समय captured state पर लौटता है।

141.39. दूसरी भाषा में भी log French है#

Internal audit messages French में store होती हैं।

141.40. Export के बाद action count बढ़ता है#

Exports actions के रूप में log होती हैं।

142. Editing से पहले checklist#

  • Current project और dataset confirm करें।
  • Raw dataset duplicate करें।
  • Project save और important data export करें।
  • Components और OTU orientation जाँचें।
  • Same project लिखने वाली other sessions बंद करें।

143. Metadata editing से पहले checklist#

  • Rownames जाँचें और SampleID column से अलग समझें।
  • Types, factors, dates और missing values document करें।
  • Valid column names उपयोग करें।
  • Editing के बाद types फिर जाँचें।

144. OTU editing से पहले checklist#

  • taxa_are_rows और ASV axis जाँचें।
  • Abundance nature और text absence confirm करें।
  • Structural changes से पहले metadata, taxonomy, RefSeq और tree जाँचें।
  • Mass renaming से पहले export करें।

145. Taxonomy replacement से पहले checklist#

  • Patterns, case और whitespace जाँचें।
  • Rank-wise counts देखें।
  • NA और text category का अंतर समझें।
  • Agglomeration effects anticipate करें।
  • Original taxonomy सुरक्षित रखें।

146. Full import से पहले checklist#

  • Dataset, separator, first column, identifiers और coverage जाँचें।
  • Previous component backup करें।
  • समझें कि component replace होगा।
  • Editors refresh करें और Description में validate करें।

147. Component delete से पहले checklist#

  • Component export और project save करें।
  • Dependent modules जाँचें।
  • Exceptional case के अलावा OTU delete न करें।
  • याद रखें Undo नहीं है।

148. Data Edition के बाद checklist#

  • Description खोलकर dimensions, sums, types, missing values, taxonomy, RefSeq और tree जाँचें।
  • Identifier alignment और edit log देखें।
  • Datasets में project save करें।

150. वर्तमान सीमाएँ#

  • Changes तुरंत लागू होती हैं और original automatic सुरक्षित नहीं रहता।
  • Save project persist नहीं करता।
  • Undo एक state रखता है और Reset local loading पर निर्भर है।
  • Metadata automatic बन सकती है।
  • Factors और special classes खो सकती हैं।
  • ASV switch transpose command नहीं है।
  • OTU edits components desynchronize कर सकती हैं।
  • Taxonomy replacements सभी ranks पर लागू होती हैं।
  • Full imports preview के बिना शुरू होती हैं और identifiers extend नहीं करतीं।
  • Local editors stale copies दिखा सकते हैं।
  • Export log बदलता है।
  • OTU deletion अनुमति है।
  • हर action के बाद full integrity guard नहीं चलता।

151. Recommended workflow#

  1. Project save करें और raw dataset duplicate करें।
  2. Copy edit करें।
  3. OTU orientation verify करें।
  4. Metadata edit और types validate करें।
  5. OTU केवल आवश्यकता पर edit करें।
  6. Structural changes के बाद taxonomy, RefSeq और tree जाँचें।
  7. Taxonomy previews उपयोग करें।
  8. Full import/delete के बाद refresh करें।
  9. Description में validate करें।
  10. Project save और final dataset export करें।
