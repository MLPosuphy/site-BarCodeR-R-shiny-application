इनपुट डेटा — पद्धति संबंधी मार्गदर्शिकाएँ

1. सामान्य परिचय#

Input data टैब BarCodeR में पहले से बनाए गए एक या कई phyloseq objects को import करता है।

समर्थित serialized R formats हैं:

  • .rds;
  • .RData;
  • .rda;
  • .rdata।

Application स्वतः पहचानता है कि file में:

  1. एक phyloseq dataset है;
  2. कई phyloseq datasets वाला project है;
  3. कई compatible objects हैं जिनमें से user को चुनना है;
  4. unsupported object है, जिसके कारण import रोका जाता है।

यह टैब अलग-अलग tables से नया phyloseq नहीं बनाता। यह पहले से serialized R objects को load करता है।

2. BarCodeR में Input data की भूमिका#

आवश्यकता उपयोग होने वाला टैब
मौजूदा phyloseq load करना Input data
.rds project से कई phyloseq load करना Input data
Cluster पर बना phyloseq प्राप्त करना OpenMetaBar
अलग tables से phyloseq बनाना या पूरा करना Data Edition
Dataset rename, duplicate, delete या export करना Datasets
Figures और history सहित पूरा project import करना Datasets
Current project का internal backup restore करना Datasets

2.1. अब इस टैब में उपलब्ध नहीं#

Current version में dataset delete, rename, duplicate, export और named BarCodeR projects की management सीधे Input data से नहीं होती। ये actions Datasets में centralized हैं।

3. Current interface#

Input data में एक मुख्य panel है:

File load करें (.rds / .RData / .rda)

इसमें automatic detection की जानकारी, एक file selector, applied cleaning की जानकारी और Datasets टैब की ओर संकेत शामिल हैं।

अब अलग dataset/project selectors, manual OTU orientation, metadata transpose, taxonomy correction या deletion box नहीं हैं।

4. File-size limit#

File Shiny fileInput से upload होती है। Current global limit है:

500 MB

इससे बड़ी file सामान्यतः इस field से upload नहीं हो सकती।

4.1. Disk size और memory size#

.rds compressed हो सकती है। Memory में object का आकार disk file से बहुत बड़ा हो सकता है।

Import के दौरान loaded object, पहले से मौजूद datasets और temporary copies एक साथ memory में रह सकते हैं। इसलिए पर्याप्त RAM आवश्यक है।

4.2. Remote server पर BarCodeR#

Remote deployment में file Shiny server को भेजी जाती है। समय file size, network, server load और available memory पर निर्भर करता है।

Reading और cleaning synchronous हैं, इसलिए बड़े object के दौरान UI कुछ समय के लिए freeze जैसी लग सकती है।

5. Accepted formats#

5.1. .rds#

.rds में एक R object होता है। BarCodeR readRDS() से पढ़कर object type पहचानता है।

Suggested dataset label file name से extension हटाकर बनता है:

metabarcoding_coi.rds
→ metabarcoding_coi

5.2. .RData या .rda#

.RData में कई objects हो सकते हैं। BarCodeR:

  1. isolated temporary environment में file load करता है;
  2. प्रत्येक object inspect करता है;
  3. dataset/project के रूप में पहचाने objects रखता है;
  4. केवल एक compatible object होने पर auto-select करता है;
  5. कई objects होने पर user से चयन कराता है।

Unsupported objects ignore कर दिए जाते हैं।

5.3. Unsupported extensions#

Input data सीधे .csv, .tsv, .xlsx, .biom, .qza, .zip, .RDS.gz, FASTA, FASTQ या Newick import नहीं करता।

Independent tables के लिए Data Edition और complete .zip project के लिए Datasets का उपयोग करें।

6. Automatic content detection#

Detection actual object structure पर आधारित है, केवल file name या extension पर नहीं।

6.1. Single dataset#

phyloseq class inherit करने वाला object dataset माना जाता है।

6.2. Project#

Project तब पहचाना जाता है जब object:

  • datasets element वाली list हो;
  • historical ps_registry list हो;
  • non-empty list हो जिसके सभी elements phyloseq हों।

6.3. Structural detection#

Version number, विशेष format, file name या dedicated class अनिवार्य नहीं हैं। इससे पुराने formats compatible रहते हैं, लेकिन किसी unrelated list में datasets होने पर वह project समझी जा सकती है।

7. Dataset और project का अंतर#

7.1. Dataset#

एक dataset एक phyloseq object है। इसमें otu_table, sample_data, tax_table, phylogenetic tree और reference sequences हो सकती हैं।

General registry में import के लिए OTU table वास्तव में अनिवार्य है।

7.2. Data-only .rds project#

Input data से load project में dataset list, active dataset name और optional save metadata होते हैं:

list(
  version = 2,
  format = "version_ok_project",
  saved_at = ...,
  datasets = ...,
  active_ds = ...
)

7.3. Complete .zip project#

Complete .zip में figures, histories, module files, parameters और manifest भी हो सकते हैं। इसे Datasets → Import project (.zip) से load करें।

7.4. Current BarCodeR project नहीं बदलता#

Input data से .rds project import करने पर नया named project नहीं बनता, current project auto-switch नहीं होता, figures/history/navigation restore नहीं होती। केवल current project memory में datasets add या replace होते हैं।

8. File load करना#

8.1. File selection#

एक बार में एक compatible file चुनें। Selection के बाद BarCodeR तुरंत content पढ़कर अगला workflow तय करता है।

8.2. Read error#

Corrupted file, invalid R serialization, unavailable class/package, missing dependency या misleading content होने पर import रुक जाता है।

File input reset होता है, जिससे correction के बाद वही file फिर चुनी जा सके।

9. कई objects वाली .RData#

कई compatible objects मिलने पर Load करने के लिए object चुनें modal खुलता है।

ps_coi       (dataset)
ps_16s       (dataset)
my_project   (project)

9.1. Selected object उपयोग करना#

Use this object संबंधित dataset या project workflow जारी रखता है।

9.2. Cancel#

Cancel modal बंद करता है, file selector साफ़ करता है और temporary pending object हटाता है।

9.3. ऊपर की cross से बंद करना#

Current implementation में top cross वही cleanup नहीं करती जो Cancel करता है। उसी file का event फिर trigger न हो सकता है। Import छोड़ते समय Cancel बेहतर है।

10. Single phyloseq dataset load करना#

Dataset detect होने पर Prepare dataset loading modal खुलता है।

इसमें label, add/replace mode और automatic cleaning की जानकारी होती है।

11. Dataset label#

11.1. Suggested label#

.rds के लिए file name और .RData के लिए R object name प्राथमिक होता है।

11.2. Label cleaning#

Leading/trailing spaces हटाए जाते हैं, unsupported characters _ से replace होते हैं, edge underscores हटते हैं और empty result पर dataset उपयोग होता है।

मुख्यतः alphanumeric characters, _ और - रखे जाते हैं। Non-ASCII behavior R locale पर भी निर्भर है।

11.3. Existing label collision#

Add mode में suffix लगाया जाता है:

COI
COI_2
COI_3

Existing dataset silently overwrite नहीं होता।

12. Add या replace#

12.1. Current session में add#

Default mode current datasets रखता है, नया dataset add करता है, label unique बनाता है और उसे active करता है।

12.2. Current memory replace करना#

सभी current in-memory datasets हटते हैं, केवल नया dataset रहता है और active बनता है।

सावधानी: Disk पर source files delete नहीं होतीं, लेकिन unsaved datasets खो सकते हैं। Replace से पहले project save करें।

12.3. Empty session#

कोई dataset न होने पर add/replace choice नहीं दिखती। Loading empty list replacement की तरह होती है।

13. Phyloseq पर actual cleaning#

BarCodeR पूरा object rebuild नहीं करता और tables को auto-transpose नहीं करता।

मुख्य operations:

  1. OTU table में sample axis पहचानना;
  2. sample names standardize करना;
  3. metadata से synchronize करना;
  4. blank metadata cells को NA बनाना;
  5. selected identifiers की consistency जाँचना।

14. OTU-table orientation#

BarCodeR existing orientation रखता है और taxa_are_rows() उपयोग करता है।

14.1. Taxa rows में#

taxa_are_rows(ps) == TRUE पर samples columns में होते हैं और column names साफ़ होते हैं।

14.2. Taxa columns में#

taxa_are_rows(ps) == FALSE पर samples rows में होते हैं और row names साफ़ होते हैं।

14.3. कोई transposition नहीं#

App ASV rows, samples columns या common orientation force नहीं करता। पुरानी orientation-selection documentation अब लागू नहीं है।

15. Sample-name standardization#

15.1. Transformations#

Accent transliteration की कोशिश, outer spaces trim, internal spaces/unsafe characters को _, repeated underscores collapse, edge underscores remove, empty names fill और duplicate suffixes add किए जाते हैं।

15.2. Examples#

Before Possible result
Station 01 Station_01
Station-01 Station_01
Échantillon A Echantillon_A
sample/1 sample_1
sample sample
empty sample_1
two sample sample, sample_1

15.3. Cleaning क्यों होती है#

Complex identifiers statistical formulas, joins, R packages, file names, plots, exports और Shiny selectors में समस्या कर सकते हैं।

15.4. Cleaning हमेशा लागू नहीं रहती#

OTU renaming तभी रखी जाती है जब metadata alignment सुरक्षित रहे।

Safe correspondence न बनने पर BarCodeR OTU renaming rollback कर सकता है, original names रखता है और report में warning देता है। Consistency cosmetic cleaning से अधिक महत्वपूर्ण है।

16. Metadata processing#

sample_data optional है। Metadata के बिना import संभव है, लेकिन sample variables वाले analyses unavailable रहेंगे।

16.1. Rownames alignment#

Original OTU names से match होने पर metadata और OTU पर वही transformations लगती हैं।

Direct match साबित न होने पर metadata अलग से clean होती है और केवल compatible रहने पर apply होती है। Uncertain match पर original names रखे जाते हैं और warning दी जाती है।

17. Blank metadata cells#

Empty strings या केवल spaces वाली strings वास्तविक NA से replace होती हैं।

Original Imported
"" NA
" " NA
"0" "0"
"NA" "NA"
real NA NA

Literal "NA" automatically missing value नहीं बनती।

17.1. Column types पर प्रभाव#

Current implementation blank replacement से पहले हर metadata column को character बनाती है। Numeric, integer, logical, factor और date columns character हो सकती हैं।

Import के बाद Description, Data Edition या R में types verify करें। यह वास्तविक data transformation है।

18. जो components modify नहीं होते#

Input data OTU abundances, orientation, ASV names, taxonomy values/ranks, reference sequences, tree, zeros, empty taxa/samples, negative/decimal values या OTU NA को सीधे modify नहीं करता।

यह पूर्ण scientific validation नहीं है।

19. Single dataset integrity check#

19.1. Phyloseq class#

Object वास्तविक phyloseq होना चाहिए।

19.2. OTU table required#

otu_table होना अनिवार्य है।

19.3. Sample identifiers#

sample_data मौजूद हो तो उसके rownames सभी sample names से set-wise match करने चाहिए। Partial metadata reject होती है।

19.4. Taxon identifiers#

tax_table मौजूद हो तो उसके rownames सभी OTU taxa names से match करने चाहिए।

19.5. Guard क्या नहीं जाँचता#

refseq/tree coverage, sequence validity, integer/non-negative counts, biological taxonomy coherence, duplicates और minimum depth सीधे नहीं जाँचे जाते।

20. Inconsistency पर import reject#

Identifiers mismatch, missing OTU table या non-phyloseq object पर dataset add नहीं होता और original file modify नहीं होती।

21. Dataset import report#

Success पर Dataset loaded and checked modal दिखता है।

इसमें final label, samples, taxa/ASV, actions count, source file/object, add/replace mode, total datasets, OTU/metadata before-after tables, blank replacements, warnings और notes होते हैं।

केवल पहले दस renames दिखते हैं, total count बना रहता है।

22. .rds project load करना#

BarCodeR project के phyloseq datasets extract करता है।

22.1. Empty session#

Project सीधे replace mode में load होता है और restoration report दिखती है।

22.2. Existing datasets#

Load a project modal current names, incoming names और add/replace choice दिखाता है।

23. Project datasets add करना#

Current datasets रखे जाते हैं, imported phyloseq add होते हैं, name collisions resolve होती हैं और active dataset update होता है।

23.1. Collision#

Existing COI के साथ incoming COI COI_2 बन सकता है।

23.2. Active dataset#

Valid active_ds होने पर corresponding imported dataset active होता है। Collision से name बदलने पर final name उपयोग होता है। अन्यथा पहला imported dataset active होता है।

24. Project से replace करना#

Current in-memory datasets हटते हैं, imported list load होती है और valid active_ds restore होता है; अन्यथा पहला dataset चुना जाता है।

Disk files delete नहीं होतीं, लेकिन unsaved session datasets खो सकते हैं।

25. Project dataset names#

Valid list names रखे जाते हैं। Missing, blank या partially missing names पर generic names बनते हैं:

dataset_1
dataset_2
dataset_3

Current behavior में एक missing name पूरी list के names regenerate करा सकता है।

26. Project में non-phyloseq content#

datasets या ps_registry structure में केवल वास्तविक phyloseq items अंततः रखे जाते हैं। अन्य items ignore होते हैं।

Pre-import list actual loaded count से बड़ी हो सकती है। Final report source of truth है।

Valid phyloseq के बिना structurally recognized project replace mode में registry empty कर सकता है।

27. Project datasets cleaning#

हर phyloseq पर वही sample-name, metadata-name और blank-cell cleaning होती है।

Report प्रति dataset sample count, taxon count, OTU renames, metadata renames और blank replacements summarize करता है।

28. Dataset और project validation में अंतर#

Single dataset insertion से पहले explicit bcr_guard_ps() से गुजरता है।

Project items clean होते हैं, लेकिन entire project insert से पहले प्रत्येक item पर guard explicitly नहीं चलता।

Active dataset change पर global check होता है। Project import के बाद हर महत्वपूर्ण dataset को Description में verify करें।

29. Session memory#

Datasets datasets() reactive registry में और active name active_ds() में रहता है।

Import के बाद registry बदलती है, downstream modules नया content देखते हैं और project modified/unsaved हो जाता है।

29.1. Import save नहीं है#

Close करने से पहले Datasets → Save project उपयोग करें।

30. Active dataset#

Single imported dataset active हो जाता है। Project saved active_ds restore करता है या पहला dataset चुनता है।

बाद में global control, Datasets या synchronized modules से बदला जा सकता है।

31. Scientific guarantees नहीं मिलतीं#

Successful import मुख्यतः object readability, phyloseq class, OTU table और selected ID consistency बताता है।

यह raw counts, no prior transformation, empty taxa/sample removal, valid taxonomy, rank order, sequence/tree coverage, experimental design, पर्याप्त replicates, preserved metadata types या सभी statistical analyses के लिए suitability guarantee नहीं करता।

32. Import के बाद recommended checks#

Description खोलकर samples, taxa, total reads, available components, identifiers, metadata types/missing values, OTU orientation/values, taxonomy ranks और tree/reference coverage जाँचें।

33. बाद की dataset management#

Datasets में active selection, rename, duplicate, delete, export, save, restore और project switching करें।

34. Troubleshooting#

34.1. File selector में file नहीं दिखती#

Extension और extra compression जाँचें।

34.2. File 500 MB से बड़ी है#

Object छोटा करें, unnecessary components हटाएँ, datasets split करें, एक-एक export करें या controlled deployment में limit बदलें।

34.3. छोटी file अधिक memory लेती है#

Serialized object memory में expand होता है। RAM खाली करें।

34.4. .rds read error#

obj <- readRDS("file.rds")
class(obj)

34.5. .RData में compatible object नहीं#

load("file.RData")
ls()
class(object_name)

34.6. कई objects दिखते हैं#

यह normal है; सही object चुनें।

34.7. गलत project detection#

Object में datasets या ps_registry हो सकता है। Target phyloseq सीधे save करें:

saveRDS(my_phyloseq, "dataset.rds")

34.8. OTU table missing#

phyloseq::otu_table(ps)

34.9. Sample IDs inconsistent#

setequal(
  phyloseq::sample_names(ps),
  rownames(as.data.frame(phyloseq::sample_data(ps)))
)

Expected result TRUE है।

34.10. Taxon IDs inconsistent#

setequal(
  phyloseq::taxa_names(ps),
  rownames(as(phyloseq::tax_table(ps), "matrix"))
)

34.11. Partial metadata reject होती है#

Missing samples पूरा करें, undocumented samples consistently हटाएँ या aligned object rebuild करें।

34.12. Sample names बदल गए#

Before/after report देखें।

34.13. Names clean नहीं हुए#

Metadata alignment बचाने के लिए OTU rename rollback हुआ हो सकता है।

34.14. Numeric column text बन गई#

str(as.data.frame(phyloseq::sample_data(ps)))
metadata$Depth <- as.numeric(metadata$Depth)

Conversion से पहले values जाँचें।

34.15. Literal "NA" missing नहीं#

metadata[metadata == "NA"] <- NA

Legitimate category होने पर सावधानी रखें।

34.16. अपेक्षा से कम datasets load हुए#

कुछ items phyloseq नहीं थे या ignore हुए। Final report देखें।

34.17. सभी names dataset_1 आदि बन गए#

names(project$datasets) <- c("COI", "16S", "ITS")

34.18. _2 suffix#

Add mode में existing label protect हुआ।

34.19. पुराने datasets गायब#

Replace mode confirm हुआ। Saved project या source files से restore करें।

34.20. Figures restore नहीं हुईं#

Input data .rds data-only project है। Complete .zip Datasets में import करें।

34.21. वही file दुबारा trigger नहीं करती#

Previous modal cross से बंद हुई हो सकती है। Temporary दूसरी file चुनें, field reset करें या tab reload करें।

34.22. Metadata absent#

Import संभव है, लेकिन sample-variable analyses unavailable रहेंगी।

34.23. Taxonomy absent#

tax_table dependent analyses unavailable रहेंगी।

कुछ UniFrac जैसी tree-dependent methods unavailable रहेंगी।

Sequence-dependent analyses unavailable रहेंगी।

35. Import से पहले checklist#

File#

  • .rds, .RData या .rda format।
  • 500 MB से छोटा।
  • पर्याप्त memory।
  • R में readable।

Phyloseq#

  • OTU table मौजूद।
  • Sample IDs unique।
  • Taxon IDs unique।
  • Metadata सभी samples cover करती है।
  • Taxonomy सभी taxa cover करती है।
  • Sequences/tree coherent हैं।

Metadata#

  • Missing values पहचाने गए।
  • Numeric columns ज्ञात हैं।
  • Ordered factors और dates documented हैं।
  • Sample names OTU table से aligned हैं।

Session#

  • Existing datasets saved हैं।
  • Add/replace समझा गया है।
  • Name collisions anticipated हैं।

36. Import के बाद checklist#

  • पूरा cleaning report पढ़ें।
  • Sample renaming जाँचें।
  • Samples/taxa counts जाँचें।
  • Metadata types जाँचें।
  • NA replacements जाँचें।
  • Description खोलें।
  • OTU table और taxonomy देखें।
  • Sequences और tree देखें।
  • Datasets में project save करें।

37. Current limitations#

  1. Exhaustive scientific validation नहीं।
  2. Metadata columns character बन सकती हैं।
  3. Auto-transposition नहीं।
  4. Taxonomy cleaning नहीं।
  5. Project validation single dataset से कम strict है।
  6. Project recognition structural है।
  7. Cross से closing pending state छोड़ सकती है।
  8. Maximum upload 500 MB है।

38. Recommended workflow#

  1. R में phyloseq बनाएँ और verify करें।
  2. saveRDS() से save करें।
  3. Input data खोलें।
  4. File चुनें।
  5. Add या replace चुनें।
  6. Label जाँचें।
  7. Confirm करें।
  8. Report पढ़ें।
  9. Description खोलें।
  10. Dimensions/components जाँचें।
  11. Metadata types जाँचें।
  12. Datasets में project save करें।

    rownames(as.data.frame(sample_data(ps)))
  ))

41. Traceability principles#

Original source file रखें, पुराने exports overwrite न करें, export date और object name दर्ज करें, cleaning report देखें, automatic renames document करें, metadata types verify करें, BarCodeR project save करें और source object को cleaned in-memory object से अलग मानें।

BarCodeR object sample-name cleaning, metadata synchronization, blank replacement और column conversion के कारण source file से अलग हो सकता है।

सत्यापित internal sources#

  1. modules/data/mod_data_loader_ui.R — current interface और accepted extensions।
  2. modules/data/mod_data_loader_server.R — pending state, detection, cleaning, modals, insertion और reports।
  3. modules/_shared/_dataset_naming.R — safe और unique dataset labels।
  4. modules/_shared/_ps_guard.R — phyloseq class, OTU table और identifier checks।
  5. modules/datasets/mod_datasets_server.R तथा mod_datasets_ui.R — data-only और complete project formats।
  6. app.R — 500 MB limit, datasets() registry, active dataset और unsaved state।
