डेटासेट — पद्धति संबंधी मार्गदर्शिकाएँ

1. सामान्य परिचय#

Datasets टैब BarCodeR में दो अलग स्तरों का प्रबंधन करता है:

  1. Memory में datasets: current session में उपलब्ध named phyloseq objects।
  2. Persistent projects: disk पर सुरक्षित workspaces, जिनमें datasets, active dataset, interface state, figure histories और module files हो सकते हैं।

Dataset actions से active object चुनना, rename करना, notes और tags जोड़ना, duplicate करना, order बदलना, export करना और memory से हटाना संभव है। Project actions से save, restore, create, open, rename, duplicate, export, import और delete किया जाता है।

2. आवश्यक परिभाषाएँ#

2.1. Dataset#

Dataset reactive named list की एक entry है:

datasets()

हर entry सामान्यतः एक phyloseq object होती है। उसका list name पूरी application में identifier के रूप में उपयोग होता है।

2.2. Active dataset#

Active dataset अलग से यहाँ रखा जाता है:

active_ds()

यह global default के रूप में चुने गए object का केवल नाम है; object की अतिरिक्त copy नहीं।

2.3. Dataset registry#

Registry current in-memory list है, जिसमें names, order, attributes और active name शामिल हैं। यह disk पर last saved version से automatically synchronized नहीं रहती।

2.4. Session#

Session browser में application की current state है। Registry changes पहले memory में लागू होते हैं। Application बंद करने या पुरानी save restore करने पर unsaved changes खो सकते हैं।

2.5. Project#

Project यहाँ store होता है:

save/projects/<internal-project-id>/

इसमें registry.rds, manifest.rds, ui_state.rds और barplot/, alpha_div/, Ordination/, DAA/, Analyse/, multiview/ जैसे module folders हो सकते हैं।

3. Dataset और project में अंतर#

गुण Dataset Project
phyloseq object रखता है हाँ एक या कई
Active हो सकता है हाँ हाँ, current project के रूप में
Figure histories रखता है नहीं हाँ
केवल memory से हटाया जा सकता है हाँ नहीं
Disk से physically delete हो सकता है Dataset delete action से नहीं हाँ

इसलिए dataset delete करना और project delete करना पूरी तरह अलग operations हैं।

4. टैब की संरचना#

टैब में तीन मुख्य क्षेत्र हैं:

  1. global active dataset;
  2. dataset registry;
  3. projects।

5. Global active dataset#

5.1. Selector की भूमिका#

चुना गया dataset Description, Data Edition, Filtration, Exploration और Analysis के लिए default working object बनता है।

5.2. Synchronization#

Selector active_ds() और अन्य global dataset selectors के साथ synchronized रहता है।

5.3. Modules में local selection#

कुछ modules अस्थायी रूप से कोई दूसरा dataset चुन सकते हैं। Operation चलाने से पहले global selector और module-specific selector दोनों जाँचें।

5.4. Active dataset बदलने का प्रभाव#

यह बदलाव data edit, filter, copy या delete नहीं करता। केवल global reference बदलता है, लेकिन project को unsaved mark करता है क्योंकि active name project में persist होता है।

6. Memory में कोई dataset नहीं#

Registry empty होने पर Input data से object load करें, OpenMetaBar से phyloseq import करें, saved project खोलें, project archive import करें या previous registry restore करें।

7. Dataset registry#

Table datasets() में current memory की हर entry के लिए एक row दिखाती है। यह disk files को सीधे scan नहीं करती।

8. Registry columns#

8.1. Active state#

Star active dataset दिखाता है; circle inactive dataset। यह icon quality, filtration या save status नहीं बताता।

8.2. Name#

Name selectors, reports, exports, histories, lineage attributes, legends और कुछ filenames में key के रूप में उपयोग होता है।

8.3. ASV#

दिखाया गया value यहाँ से आता है:

phyloseq::ntaxa()

यह taxa की संख्या है। Source workflow के अनुसार units ASV, OTU, ZOTU या कोई अन्य unit हो सकती हैं।

8.4. Samples#

दिखाया गया value यहाँ से आता है:

phyloseq::nsamples()

8.5. Provenance#

  • Loaded: recognized filtration या OpenMetaBar provenance attribute नहीं।
  • OpenMetaBar: object में openmetabar_run है।
  • Filtered: filtration_log में named parent है।

Filtered provenance की priority OpenMetaBar से अधिक है।

8.6. Parent#

Parent name यहाँ से आता है:

filtration_log$parent_dataset

यह stored string है, live object link नहीं। Parent rename या delete होने पर BarCodeR recognized descendants में इसे update करता है।

8.7. Note और tags#

ये attribute में store होते हैं:

list(note = "...", tags = c("tag1", "tag2"))

Individual exports, duplicates और project saves में ये साथ रहते हैं।

8.8. Modified#

Date पहले latest edit_log entry से, फिर filtration_log से ली जाती है। Rename, notes, tags, order और active selection इस date को जरूरी नहीं update करें।

8.9. Actions#

हर row को activate, edit, duplicate, export, ऊपर/नीचे move या memory से delete किया जा सकता है।

9. Registry refresh करना#

Refresh current reactive objects से visible table rebuild करता है। यह registry.rds नहीं पढ़ता, projects scan नहीं करता और data restore नहीं करता।

10. Dataset को active बनाना#

Row activate करने से active_ds() update होता है, global selectors synchronize होते हैं और project modified mark होता है। Restart के बाद selection रखने के लिए project save करें।

11. Dataset edit करना#

Edit dialog में dataset name, free-text note और comma-separated tags होते हैं।

12. Dataset rename करना#

12.1. Name cleaning#

bcr_clean_label() outer spaces हटाता है, unsafe characters को _ से बदलता है, edge underscores हटाता है और empty result पर dataset उपयोग करता है।

12.2. Non-ASCII characters#

Cleaning partly R locale पर निर्भर है। Maximum portability के लिए ASCII letters, digits, _ और - उपयोग करें।

12.3. Name collision#

Name पहले से होने पर _2, _3 जैसा suffix जुड़ता है। Existing object silently overwrite नहीं होता।

12.4. Active dataset update#

Renamed dataset active था तो active_ds() final name पर update होता है।

12.5. Filtered descendants#

Recognized descendants में parent_dataset नया parent name प्राप्त करता है।

12.6. क्या rename नहीं होता#

पहले exported files, source RDS, old figures, old reports, project name और project slug rename नहीं होते।

13. Note जोड़ना#

Note processing, limitations, database version, validation status या intended use document कर सकती है। यह phyloseq object के अंदर store होती है। Note बदलने से Modified date जरूरी नहीं बदले।

14. Tags जोड़ना#

Tags comma पर split और trim होते हैं। Empty tags हटते हैं, लेकिन duplicates और capitalization differences बने रहते हैं। Consistent convention उपयोग करें।

15. dataset_meta attribute#

Edit save करते समय dataset_meta केवल note और tags वाली list से replace होता है। उस attribute में पहले से मौजूद अन्य custom fields खो सकते हैं।

16. Dataset duplicate करना#

16.1. Proposed name#

Default name <name>_copy है, जरूरत पर numeric suffix जुड़ता है।

16.2. Copied content#

पूरा object copy होता है: abundance table, metadata, taxonomy, sequences, tree, logs, provenance, note, tags और अन्य attributes।

16.3. Active dataset#

नई copy active बनती है।

16.4. बाद की independence#

इसके बाद दोनों registry entries independently edit होती हैं।

16.5. Provenance#

Duplication “copy” provenance नहीं बनाती। Copy source के provenance attributes और parent रखती है।

17. Dataset order बदलना#

Up/down arrows list order बदलते हैं। इससे selectors, multi-dataset operations और fallback selection प्रभावित हो सकते हैं। Order project save होने पर ही persistent होता है।

18. Individual dataset export करना#

Row export current phyloseq object को इस तरह के file में लिखता है:

dataset_<name>_<timestamp>.rds

इसमें object components और attributes होते हैं, लेकिन other datasets, project figures, module histories, raw FASTQ, OpenMetaBar remote run folders या original taxonomy database नहीं। इसे Input data से reimport करें।

19. Session से dataset हटाना#

19.1. Immediate effects#

Object datasets() से हटता है, selectors से गायब होता है और current session में unavailable हो जाता है। Project unsaved mark होता है।

19.2. Active dataset हटाना#

पहला remaining dataset active बनता है; कोई dataset न बचे तो active_ds() empty होता है।

19.3. Filtered descendants#

Deleted dataset parent था तो descendants का parent_dataset clear होता है। Filtered badge non-empty parent पर निर्भर होने के कारण visible provenance बदल सकती है।

19.4. केवल memory#

Last saved registry तुरंत नहीं बदलता। Disk से restore करने पर dataset फिर आ सकता है।

19.5. Deletion persistent बनाना#

Row delete करें, registry जाँचें और Save project करें।

19.6. Last dataset delete करना#

Quick save empty registry को refuse करता है। इसलिए पुराना non-empty registry.rds disk पर रह सकता है। वास्तव में empty persistent workspace के लिए नया project बनाएँ।

20. Unsaved changes state#

datasets() या active_ds() बदलने पर project modified mark होता है। यह indicator मुख्यतः registry और active name track करता है; सभी module files का complete audit नहीं।

21. Projects section#

Project manager current persistent workspace, save, restore, creation, exports, imports और project list नियंत्रित करता है।

22. Current project#

Current slug यहाँ store होता है:

save/projects/.current

Startup पर BarCodeR इसे reopen करने की कोशिश करता है। उपलब्ध न होने पर sans-titre उपयोग करता है।

23. Display name और internal slug#

Project का display name, ASCII-safe internal slug और disk folder होता है। Rename केवल display name बदलता है; slug और paths स्थिर रहते हैं।

24. Project disk structure#

24.1. registry.rds#

Datasets, order, active dataset और format metadata store करता है।

24.2. manifest.rds#

Display name, creation/modification dates और saved dataset count रखता है।

24.3. ui_state.rds#

Main tab, sub-tabs और restorable interface parameters रख सकता है।

24.4. Module folders#

Modules अपने folders में figures, R objects, parameters और history metadata save कर सकते हैं।

25. Project में automatically क्या शामिल नहीं होता#

Project सभी scientific inputs की complete copy नहीं है। Raw FASTQ/BAM, reference FASTA, taxonomy databases, OpenMetaBar designs, remote results, external scripts और tool databases अलग archive करने चाहिए।

26. Project save करना#

26.1. Saved content#

Dataset list, order, complete objects/attributes, active dataset, manifest count और available UI state save होते हैं।

26.2. Figure histories#

Histories सामान्यतः modules सीधे लिखते हैं। Save action मुख्यतः dataset registry synchronize करता है।

26.3. Empty project#

कोई dataset न होने पर save refuse होता है।

26.4. Empty overwrite protection#

Non-empty saved registry को empty memory से overwrite होने से बचाया जाता है, जैसे failed load के बाद।

26.5. Success#

Successful save unsaved flag clear करता है और project metadata update करता है।

27. Available save status#

दिखाया गया timestamp registry.rds modification time है; जरूरी नहीं कि यह last figure, analysis या history file का समय हो।

28. Disk से reload करना#

Reload current memory के सभी datasets को registry.rds से replace करता है; merge नहीं करता। Unsaved imports, edits, deletions, filters, notes, tags, order और active selection खो सकते हैं।

29. Save नहीं मिला#

registry.rds न होने का अर्थ नया project, figures-only project, never-saved project, manually deleted file या partial import हो सकता है।

30. Unreadable save#

registry.rds न पढ़ने पर project empty memory और warning के साथ खुल सकता है। BarCodeR unreadable file को empty registry से silently overwrite होने से बचाता है। Recovery से पहले project folder copy करें।

31. केवल data .rds में export करना#

Export versioned list में datasets() और active_ds() देता है। Figures, histories, manifest, display name, UI state और external files शामिल नहीं होते। इसे Input data से reimport करें।

32. Complete project .zip export करना#

ZIP current project folder रखता है। BarCodeR पहले in-memory registry save करने की कोशिश करता है। Save fail होने पर archive में current memory के बजाय disk का last valid registry हो सकता है। Notifications पढ़ें।

33. Size warning#

200 MB से ऊपर warning आती है। Size सभी project files शामिल करता है और थोड़े समय के लिए cached हो सकता है। Upload limit 500 MB है; इससे बड़ा ZIP export हो सकता है लेकिन interface से reimport नहीं।

34. Project .zip import करना#

Archive हमेशा नए project के रूप में extract होता है और current project में merge नहीं होता। Import के बाद project list से खोलें। BarCodeR registry.rds, manifest.rds या known history folders पहचानता है; figures-only project zero datasets के साथ import हो सकता है।

35. नया project बनाना#

Folder और manifest बनते हैं, current project normal save/switch workflow में जाता है, नया project current बनता है और application reload होती है। Empty या duplicate names refuse होते हैं।

36. दूसरा project खोलना#

BarCodeR current project save करने की कोशिश करता है, नया slug .current में लिखता है, session reload करता है और modules को नए paths से initialize करता है। Save error हमेशा switch नहीं रोकता, इसलिए red notifications ignore न करें।

37. Multiple BarCodeR browser tabs#

Current project R process level पर shared है। Other tabs पुराने project paths रखकर files गलत जगह लिख सकते हैं। Project switch से पहले save करें और अन्य BarCodeR tabs बंद करें।

38. Current project rename करना#

केवल display name बदलता है। Slug, directory, histories, datasets और active dataset नहीं बदलते। पहले से उपयोग name refuse होता है।

39. Project list#

Projects manifest की latest modification date से sort होते हैं। Dataset count saved registry दिखाता है, जरूरी नहीं current unsaved memory।

40. Project duplicate करना#

पूरा project folder copy होता है: registry, manifest, UI state, datasets, figures और histories। Current project duplicate करने से पहले manual save करें क्योंकि internal pre-save result strictly blocking नहीं।

41. Project delete करना#

केवल closed project delete हो सकता है। पूरा save/projects/<slug>/ permanently हटता है; internal trash नहीं। पहले ZIP export करें।

42. तीन exports का अंतर#

Export Content Figures Reimport
Individual dataset .rds एक phyloseq नहीं Input data
Project data .rds Dataset list + active name नहीं Input data
Complete project .zip Project folder हाँ Datasets

43. Projects और OpenMetaBar data#

Phyloseq import remote OpenMetaBar run directory copy नहीं करता। Raw reads, Nextflow logs, work/, containers, reference databases और cluster outputs अलग archive करें।

44. Projects और figure histories#

केवल module history में वास्तव में stored figures project में guaranteed हैं। केवल screen पर displayed plot archive नहीं हो सकता।

45. Physical location#

Projects <BarCodeR-working-directory>/save/projects/ में हैं। Docker/server deployment में persistent storage जरूरी है। Shared installation में privacy permissions, authentication और deployment configuration पर निर्भर है।

46. Recommended daily workflow#

  1. सही project खोलें या बनाएँ।
  2. Data load करें।
  3. Registry और active dataset जाँचें।
  4. उपयोगी notes और tags जोड़ें।
  5. Major edits से पहले duplicate करें।
  6. नियमित save करें।
  7. Critical datasets export करें।
  8. Complete ZIP को समय-समय पर BarCodeR के बाहर store करें।

47. Risky operation से पहले#

Filtering, mass editing, deleting, restoring, project switching या application upgrade से पहले project save करें, success verify करें, महत्वपूर्ण dataset export करें, जरूरत पर full project export करें और downloaded files जाँचें।

48. समस्या निवारण#

48.1. Dataset registry में नहीं दिखता#

Import completion, current project, deletion और older registry restoration जाँचें।

48.2. Module गलत dataset उपयोग करता है#

Global और local selector दोनों जाँचें।

48.3. Active selection नहीं बचती#

बदलने के बाद project save करें।

48.4. Entered name बदल गया#

Unsafe characters normalize हुए।

48.5. _2 जुड़ा#

Same final name पहले से था।

48.6. Modified date नहीं बदली#

Notes, tags और rename उस date source से नहीं आते।

48.7. Copy original provenance रखती है#

Duplication attributes copy करती है।

48.8. Filtered dataset filtered नहीं दिखता#

Parent delete हुआ हो सकता है। attr(ps, "filtration_log") देखें।

48.9. Deleted dataset वापस आया#

Deletion save नहीं हुई और old registry restore हुई।

48.10. Empty project save नहीं होता#

Quick save को कम से कम एक dataset चाहिए। नया project बनाएँ।

48.11. Reload ने changes हटाए#

Reload memory को saved registry से replace करता है।

48.12. Save file नहीं है#

Project ने अभी registry.rds नहीं लिखा।

48.13. Project empty खुला और registry error है#

Overwrite न करें। Folder copy करें और external readRDS() test करें।

48.14. New project name refuse हुआ#

Name empty या already used है, case/outer spaces ignore करके।

48.15. Rename के बाद folder पुराना name रखता है#

Design के अनुसार केवल display name बदलता है।

48.16. Project open करने पर app reload होती है#

Module paths reinitialize करने के लिए जरूरी है।

48.17. दूसरा project खोलते समय save error#

Switch फिर भी जारी हो सकता है। Previous project दोबारा खोलकर verify करें।

48.18. Multiple-tab warning#

Project switch से पहले other tabs बंद करें।

48.19. Duplicate में latest changes नहीं#

Duplicate से पहले explicit save करें।

48.20. Current project delete नहीं होता#

पहले दूसरा project खोलें।

48.21. Project deletion fail#

Permissions, locks, disk errors और target directory जाँचें।

48.22. ZIP बहुत बड़ा है#

Unnecessary histories हटाएँ या data-only export करें।

48.23. ZIP 500 MB से बड़ा है#

shiny.maxRequestSize बढ़ाएँ, archive घटाएँ, project folder सीधे copy करें या external storage उपयोग करें।

48.24. Imported project open नहीं हुआ#

List में चुनकर Open करें।

48.25. Archive invalid है#

ZIP integrity और recognized project markers जाँचें।

48.26. Imported project में zero datasets हैं#

इसमें केवल histories हो सकती हैं या registry missing/unreadable है।

48.27. ZIP में latest data नहीं#

Pre-export save fail हुई हो सकती है; notifications देखें।

48.28. Project dataset count गलत लगता है#

Save और refresh करें; list persisted metadata दिखाती है।

48.29. Project size देर से update होती है#

Size calculation थोड़े समय के लिए cached है।

48.30. Redeployment के बाद projects गायब#

save/projects/ को persistent storage पर mount करें।

49. Save से पहले checklist#

  • सही project खुला है।
  • Expected datasets मौजूद हैं।
  • सही dataset active है।
  • Names, notes और tags सही हैं।
  • Deletions और duplicates intentional हैं।
  • कोई important operation pending नहीं।
  • कोई error notification नहीं।

50. Project switch से पहले checklist#

  • Current project save करें।
  • Success message verify करें।
  • Critical datasets export करें।
  • Modals बंद करें और calculations finish करें।
  • Other BarCodeR tabs बंद करें।
  • Target project name verify करें।

51. Dataset delete से पहले checklist#

  • Exact name और active status जाँचें।
  • Filtered descendants जाँचें।
  • जरूरत पर export करें।
  • Project archive करें।
  • Delete करके नया active dataset verify करें।
  • Project save करें।

52. Project delete से पहले checklist#

  • सुनिश्चित करें कि यह current project नहीं।
  • ZIP export और verify करें।
  • Critical datasets अलग export करें।
  • Raw data और OpenMetaBar outputs कहीं और archived हों।
  • इन checks के बाद ही delete करें।

53. Recommended backup strategy#

कम से कम तीन layers रखें:

  1. नियमित Save project;
  2. critical datasets के individual RDS exports;
  3. BarCodeR installation से बाहर stored periodic complete ZIP archives।

Internal storage अकेला disk loss, redeployment या server failure से सुरक्षा नहीं देता।

54. Traceability principles#

Explicit project/dataset names, consistent tags, meaningful notes, preserved provenance, major edits से पहले copies, frequent saves, reference exports, recorded BarCodeR versions और separate raw-data archives उपयोग करें।

55. Current limitations#

  • Dataset actions पहले memory में होती हैं और save के बाद persistent बनती हैं।
  • Empty project quick-save नहीं हो सकता।
  • Modified date incomplete है।
  • Filtered provenance named parent पर निर्भर है।
  • Duplication provenance attributes रखती है।
  • Dataset names ASCII guaranteed नहीं।
  • Project switching पूरी R instance पर global है।
  • Save errors हमेशा switch या duplication नहीं रोकते।
  • Save indicator मुख्यतः registry और active dataset track करता है।
  • ZIP external scientific files शामिल नहीं करता।
  • 500 MB से बड़े archives interface से import न हो पाएँ।
  • save/projects/ persistent storage पर होना चाहिए।
